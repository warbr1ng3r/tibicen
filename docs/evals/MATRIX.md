# Frozen acceptance matrix

Задачи 1.3–1.4 стенда: 67 отдельных случаев в [matrix.ts](../../scripts/evals/matrix.ts), с фиксацией полного digest входа, oracle, рубрики и контрольных примеров в [matrix-lock.json](../../scripts/evals/fixtures/matrix-lock.json). Это подготовленные входы и независимые ожидания; наличие строки в матрице не означает живую приёмку.

Для [общего native runner](NATIVE_RUNS.md) fixture содержит host-only `interaction`: approve/refuse/revise и наличие staged process task. Будущие ответы остаются скрыты от executor. Текущий lock также фиксирует отдельные PROC adopt/update tasks, допустимую metadata change и обязательную точную LICENSE в SKILL-01; исторические frozen серии сохраняют свои условия.

| Группа | Отдельные случаи |
|---|---|
| Основное видение А–Е | Новый проект, существующее приложение, конфликт, повтор без записи, отказ, ручной шаг, incomplete, утраченный baseline, пресет |
| PREF | 01–07, отдельный 06 без вопросов, отдельные 08A/B/C/D |
| Дополнение §1 | Нет блока, корректный, совпадающий, пустой, перемещённый, удаление, дубли, вложение, обратный порядок, незамкнутая пара, старый/неизвестный формат; CRLF и окружающие байты |
| Дополнение §2 / SKILL-04 | Локальная правка, исчезнувший полезный upstream-ресурс, чужой сосед, занятый путь, неподтверждённая лицензия, изменённые байты и недостающий ресурс |
| Дополнение §3 | 11 состояний после настоящего hard exit: add/modify/delete до и после замены, до/после записи паспорта, перед cleanup, неоднозначная чужая правка, неизвестный исход команды |
| Дополнение §7 | Одна согласованная редакция Codex/Claude и отдельная устаревшая копия |
| Стек и инструменты | ML без обещания запуска приложения; форматы Codex/Claude/Cursor с честными пробелами совместимости |
| SKILL-01–04 | Установка и отказ, достаточные правила, выбор по потребности, обновление и отрицательные источники |
| PROC-01–04 | Init и полный workflow, adopt/update с существующей работой, четыре дефекта процесса, сохранение достаточного командного/OpenSpec процесса |

Обычные случаи требуют controlled-изоляции. Подставной `unsafe-init.mjs`, реально содержащий попытки записи в HOME/package.json и Git commit, помечен hostile. Обычный process runner отказывает ему до preflight/запуска; тест не исполняет этот payload. Наличие временной папки не считается требуемой изоляцией.

`loadAcceptanceMatrix()` возвращает scenario, отдельный MechanicalOracle, QualityPlan и контрольные примеры достаточного/нарушающего поведения. Только `scenario.files` и проекция `executorScenario()` передаются исполнителю. Oracle, контрольные ответы и будущие реплики остаются у host. Материализация обоих вариантов проверяет одинаковые байты и независимость деревьев. Исходники/CI/источники защищены на setup; task имеет собственные пути, команды и согласие. PROC отдельно разделяет разрешение planning-файлов и ревью перед реализацией.

Смысловые ожидания не проверяются поиском «правильного» названия в ответе. Grounding/fit/sufficiency/consistency/application/loading/process требуют фактических наблюдений, независимой рубрики и установленной человеческой выборки. Контрольные описания не являются живыми оценками. Число компонентов не является критерием.

Сценарии без исполнения не требуют скрытую Node-команду при setup. Новый пустой React-проект допускает согласованный package.json каркаса и отдельную задачу с React-файлами; Node-ожидания double/triple к нему не применяются. Web-checker в текущем профиле отсутствует, поэтому проверка приложения остаётся unverified. Матрица после этих исправлений ревью закреплена заново до будущей серии; условия уже проведённых diagnostic-когорт сохранены.

## Historical state templates

[lifecycle.json](../../scripts/evals/fixtures/lifecycle.json) получен [явным authoring-скриптом](../../scripts/evals/freeze-lifecycle.ts) через аварийный выход настоящего ядра. Сохранены schema 3, оригиналы, write intent, журнал команды и исходный session id. Это синтетическая история фикстуры, не доказательство пользовательского согласия.

Root и отдельный HOME представлены `/fixture/project` и `/fixture/home`. Перед заморозкой эксперимента host вызывает `bindAcceptanceFixture(fixture, canonicalProjectRoot, canonicalHome)`, меняя только эти привязки и связанные digest двух исторических JSON. Для последовательной пары используется один канонический путь, заново созданный между вариантами: после привязки начальные байты пары должны совпадать. Привязка после старта агента запрещена. Копирование шаблона без неё правильно даёт `tamper-suspect`; перенос пользовательского state этим helper не разрешён.

Тесты действительно возобновляют состояния с новым точным согласием, сохраняют id, проверяют отсутствие повторной записи готового файла и отказ затирать чужую правку. Для неизвестного test-командного исхода повтор без отдельного обоснования не исполняется, журнал остаётся unknown и проверка unverified. Совпадение файлов не становится свидетельством исполнения.

- Историческая выбранная поставка для SKILL-04: [`fe963cae99d986dae3199fe56403f99e87db7c6c`](https://github.com/DietrichGebert/ponytail/tree/fe963cae99d986dae3199fe56403f99e87db7c6c). Полезный старый пример не выдаётся за ресурс нового SHA.
- PREF-08B использует реальные шаблоны и MIT [`github/spec-kit@27d14e20c187c1f2916540ea201ecbdc9f8ed588`](https://github.com/github/spec-kit/tree/27d14e20c187c1f2916540ea201ecbdc9f8ed588), плюс явно локальные правила и незавершённый keep-double. Это проверка сохранения принятого процесса; новый Spec Kit адаптер/CLI-интеграция не заявлены.
- [OpenSpec 1.14.3](https://github.com/Fission-AI/OpenSpec): [openspec.json](../../scripts/evals/fixtures/sources/openspec.json) фиксирует pnpm integrity, SHA256 файлов upstream-пакета (кроме генерируемых установщиком launchers в `node_modules/.bin` с локальными путями), нативные init/update и четыре файла ограниченного адаптера. [Явный probe](../../scripts/evals/openspec-source.ts) использует закреплённую devDependency с отдельными HOME/XDG, CI и отключённой телеметрией. Native init создаёт десять файлов; первый update также пишет `HOME/.config/openspec/config.json`, второй ничего не меняет. Это наблюдённый инвентарь доверенного CLI, не OS sandbox и не загрузка агентом. Ограниченный адаптер не запускает init/update и не меняет зависимости приложения.

Источники и точный CLI scope доступны обоим вариантам. Для будущей PROC-серии host обязан разрешить `openspec` именно в проверенный отдельный пакет с этим инвентарём, затем заморозить PATH/права и проверить фактические команды. Первый диагностический Codex-драйвер поддерживает только два diagnostic-сценария и не выдаёт себя за профиль SKILL/PROC.

## Verification and refreezing

```sh
node --test tests/evals/matrix.test.ts
node scripts/evals/openspec-source.ts
node scripts/evals/freeze-lifecycle.ts
```

Последние две команды — явная перезапись авторских материалов, не часть обычного test. После содержательных изменений отдельно пересматривается matrix-lock; нельзя автоматически обновлять его, чтобы скрыть отличие условий уже проведённой серии. Source/SHA, установка, загрузка и применение имеют отдельные основания. Все материалы стенда и внешние процессы исключены из дистрибутива Tibicen.
