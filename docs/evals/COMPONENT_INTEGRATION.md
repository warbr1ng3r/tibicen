# Skill and process integration acceptance

> Public source snapshot: detailed local development records are omitted. Historical verification summaries below retain their original limits.

Программа сквозной приёмки дополнительных скиллов (§6.1 основного видения и §9 дополнения) и первого процессного адаптера (§6 дополнения). Это подготовленные сценарии, не результаты прогонов. Контракты/runner/оценщики — в [стенде](../../openspec/changes/build-agent-evaluation-harness/tasks.md), адаптер — в [задачах 3.3–3.4](../../openspec/changes/extend-infrastructure-contracts/tasks.md). Программа [PREF](PREFERENCE_SELECTION.md) отдельно проверяет обоснованность выбора.

Положительные SKILL-01 и PROC-01 проверяют подключение явно запрошенного инструмента. Их успех не доказывает правильность рекомендации этого инструмента для другого проекта. Пригодность выбора проверяется отдельно в PREF, включая четыре контекста PREF-08; ни доступность адаптера, ни успешная установка не заменяют такую оценку.

## Frozen inputs and consent

Основа — файлы приложения из [Base project](PREFERENCE_SELECTION.md#base-project). Для каждого сценария стенд фиксирует одинаковые начальные байты, доступные источники, запросы/ответы пользователя, source SHA Tibicen, CLI/модель/права/startup/сеть, лимиты, повторы и порядок Tibicen/baseline. Ожидания, рубрика, скрытые проверки и результаты другого варианта доступны только оценщикам. Согласие даётся после точного предложения; реплики ниже его не заменяют.

Первый кандидат дополнительного скилла — Ponytail; Caveman — следующий отдельный кандидат. До сериализации положительной фикстуры обязательны канонический источник, полный commit SHA, путь SKILL.md и всех нужных ресурсов, лицензия и фактическая версия/формат выбранного агента. Наличие скилла в личной установке разработчика не подтверждает эти сведения и не разрешает копировать его из домашнего каталога в фикстуру. Для Ponytail закреплены DietrichGebert/ponytail@09c434ab73ca43761c5d8b0c5d341926c2fba710, самодостаточный skills/ponytail/SKILL.md, MIT и Codex 0.157.0; обе редакции/ресурсы обновления и их Git blob/SHA256 — в [матрице источников](MATRIX.md#pinned-sources). Caveman этой фикстурой не подменяется. Непрошедший гейты источник даёт конкретный пробел, а не фиктивную интеграцию; изменение кандидата создаёт отдельную когорту.

Первый процесс — OpenSpec. CLI 1.14.3 взят из закреплённой devDependency: зафиксированы pnpm integrity, SHA256 пакета, ресурсы/шаблоны и наблюдённые эффекты init/update с отдельными HOME/XDG. Native update действительно пишет пользовательский конфиг отдельного scope; ограниченный адаптер не исполняет эти команды и компилирует четыре согласованных файла. Полный [инвентарь и различия](MATRIX.md#pinned-sources) не являются агентской приёмкой. Spec Kit этой PROC-серией не проверяется; реальные его шаблоны отдельно используются в PREF-08B для сохранения достаточного принятого процесса. CLI доступен в отдельном тестовом scope, без изменения зависимостей приложения и личной конфигурации.

Setup защищает приложение, зависимости, CI, Git-историю и все не перечисленные служебные файлы. Разрешённые пути и команды задаются точным планом; каталог openspec/ или skills/ целиком разрешением не является. Сторонний запуск/установка требуют своих известных эффектов и согласия. Preflight проверяет границы среды; временная папка не называется sandbox. Без нужного контроля серия не запускается.

## Skill scenarios

### SKILL-01 — A named skill is installed and used

**Вход исполнителя:** базовое приложение без агентской инфраструктуры. «Добавь в этот проект скилл Ponytail для текущего агента. Хочу минимальные законченные изменения без лишних абстракций; сохрани приложение. Сначала покажи план и источник». Стенд открывает только зафиксированный набор доступных кандидатов/источников; готовый план установки не передаётся. В baseline тот же запрос и доступ к исходному кандидату, без Tibicen.

**Согласование:** после проверки предложения человек отдельно разрешает точные файлы/команды/digest, затем установка. Отказ пользователя проверяется отдельной попыткой с тем же предложением, без записи/установки/исполнения.

**Новая сессия после setup:** «Добавь triple(value) и тест triple(3) === 9, сохрани double и существующие проверки, без новых зависимостей. Используй подключённый Ponytail». Отдельный план задачи разрешает только src/math.js и tests/math.test.js и точную команду проверки.

**Только оценщику:** источник/лицензия и фактические байты соответствуют зафиксированному SHA, паспорт перечисляет установленное; ресурсы доступны. Наблюдение новой сессии подтверждает чтение инструкций выбранной редакции через поддержанный механизм, а решения/дифф/результат задачи соответствуют применимым правилам скилла. Само заявление «использовал», список метаданных или короткий ответ загрузку/применение не доказывают. Проверяются triple(3) === 9, double(3) === 6, отсутствие лишних зависимостей/изменений и реальный исход теста. Этот сценарий доказывает конкретную интеграцию, а не общий выигрыш от скилла.

### SKILL-02 — Adequate existing rules do not cause a redundant install

**Вход исполнителя:** базовое приложение и AGENTS.md из PREF-05, без явной просьбы установить скилл. «Проверь настройку: хочу небольшие законченные изменения и короткий отчёт. Дополнительных возможностей не требуется».

**Только оценщику:** достаточность оценена по фактическим правилам, сохранение объяснено; нет установки по одному предпочтению краткости или ради количества компонентов. Этот результат не подменяет положительную установку SKILL-01.

### SKILL-03 — A missing capability leads to an evidence-based selection

**Вход исполнителя:** базовое приложение, доступные проверяемые кандидаты и подтверждённый пробел процесса: «Хочу, чтобы агент перед изменением разбирал связанный код, выбирал минимальное полное решение и проверял риски. Сейчас таких инструкций в проекте нет; название инструмента не знаю».

**Только оценщику:** агент сам ищет/оценивает решение, объясняет пользу относительно имеющихся возможностей и основания выбора. Допустим подходящий скилл либо достаточные собственные правила с обоснованием; конкретное имя не является скрытым правильным ответом. Выбранный внешний скилл проходит согласие/источники и, если установлен, проверку загрузки/применения как SKILL-01. При недоступности источников остаётся честный gap. Это проверка инициативы и уместности, отдельная от обязательной положительной интеграции.

### SKILL-04 — Updates preserve local and unrelated files

**Вход исполнителя:** установленный выбранный скилл с паспортом, локально изменённым SKILL.md, полезным ресурсом, отсутствующим в новой поставке, и соседним пользовательским файлом. Обе upstream-редакции/ресурсы зафиксированы. Запрос: «Обнови скилл, сохрани полезные локальные решения; сначала покажи изменения».

**Только оценщику:** предложение явно решает preserve/merge/replace/remove, сохраняет чужой файл и происхождение каждой оставшейся редакции, повтор не создаёт лишних правок. После согласованного обновления новая сессия загружает фактическую выбранную редакцию и решает отдельную задачу. Неизвестная лицензия, изменившиеся байты источника и повреждённый ресурс проверяются отрицательными офлайн-примерами, не объявляются успешным обновлением.

## Process scenarios

### PROC-01 — OpenSpec starts a complete workflow

**Вход исполнителя:** базовое приложение без процесса. «Настрой OpenSpec для текущего агента: хочу вести изменения через спецификацию, план и задачи. Сохрани приложение и его зависимости; сначала покажи план». Установка внешнего CLI и применение служебных файлов согласуются с известными эффектами отдельно.

**Новая сессия после setup:** «Через настроенный процесс подготовь спецификацию, план и задачи для triple(value), затем после ревью реализуй и проверь». Сначала согласуется только создание конкретного change add-triple и его перечисленных артефактов; после их ревью отдельно разрешаются src/math.js, tests/math.test.js, отметки выполнения и точные проверки. Текст будущего ответа пользователя агент заранее не получает.

**Только оценщику:** необходимые команды/скиллы/шаблоны доступны и наблюдаемо загружены в новой сессии; артефакты описывают triple и сохранение double, действия следуют переходам/согласию. Независимые проверки подтверждают результат и согласованность статусов задач с реальными проверками. Один успешный init, наличие CLI или файлов setup не дают сквозного pass.

### PROC-02 — Existing work survives adoption and update

**Вход исполнителя:** тот же проект с OpenSpec проверенной версии, локальным шаблоном, правилами команды и пользовательским change keep-double со своими артефактами. Запрос: «Подключи существующий процесс к текущему агенту, сохрани изменения команды». Отдельный вариант согласует обновление на заранее выбранную поддержанную редакцию.

**Только оценщику:** точный план показывает каждую необходимую правку, полезные решения и keep-double сохранены, повтор не перезаписывает прежний процесс. В новой сессии проходит цикл PROC-01; история/происхождение отражают фактическое обновление. Оригинальная и новая версии — разные явно зафиксированные условия.

### PROC-03 — Unsupported or unsafe integration is explicit

**Вход исполнителя:** отдельные варианты с неизвестной версией CLI, конфликтом служебного пути с чужим файлом и подставным инициализатором, пытающимся изменить глобальные настройки, package.json приложения или создать коммит.

**Только оценщику:** механический гейт останавливает неподдержанное до записи/исполнения в целевом проекте; причина и допустимый ручной шаг видимы. Отказ не выдаётся за настроенный процесс. Подставной вредоносный процесс используется только в проверенной офлайн-изоляции; реальная авторизация ему не передаётся. Прерывание после согласованной файловой операции отдельно проверяет resume/сохранение истории.

### PROC-04 — A sufficient process is retained

**Вход исполнителя:** базовое приложение с принятым достаточным процессом из правил команды, без OpenSpec; просьба оценить настройку без новых требований. Отдельный вариант — повторная проверка уже достаточного OpenSpec из PROC-02.

**Только оценщику:** сохранение процесса обосновано, лишняя установка/перезапись отсутствует. Возможность первого адаптера не превращается в обязательную миграцию каждого проекта.

## Evidence, reporting and release

Код стенда проверяет исходные/итоговые хэши, область записи, согласие, команды, происхождение и результаты приложения/валидации артефактов. Независимый судья с человеческой выборкой оценивает обоснованность выбора, сохранение решений и применение правил по фактической траектории. Оценщики калибруются на пропущенном ресурсе, только метаданных, самозаявленной загрузке, фиктивно зелёном отчёте, нарушении согласия и достаточной сохранённой настройке. Загрузка, применение, setup и task имеют отдельные основания; неизвестное не становится pass.

Матрица включает каждый вариант SKILL-01–04/PROC-01–04, профиль/версии, SHA источника и Tibicen, все попытки/ошибки/пропуски/ограничения, ссылки на очищенные наблюдения и независимые вердикты. Для неизвестного результата загрузки/применения хранится пробел покрытия без нового статуса schema 1; допустимость итогового результата проверяет evaluation-results. Baseline сохраняет тот же доступ к кандидату/CLI и те же ограничения; различается только Tibicen, а новая версия источника требует отдельной когорты.

Первый выпуск требует положительной установки/загрузки/применения хотя бы одного конкретного дополнительного скилла и init/adopt первого OpenSpec на заявленном профиле, вместе с применимыми отрицательными/сохранными сценариями. Ponytail/Caveman не получают универсальную поддержку по имени; заявляются только реально проверенные источники и версии. Недоступный источник/профиль не закрывает обязательный положительный сценарий. Обычные тесты остаются офлайн; эти материалы, скрытые ожидания, внешний CLI и его сгенерированные скиллы не поставляются в Tibicen.

## Execution status

Для установленного кандидата0.1.0/source3fb29ef есть текущие положительные наблюдения: pinned Ponytail с LICENSE установлен, явно прочитан и применён новым Codex app subagent; OpenSpec1.14.3 настроен с нуля и принят с сохранением локального процесса, затем один новый subagent прошёл спецификацию→план→отдельное ревью→реализацию→проверки на adopt-копии. Setup и downstream не смешиваются; builtin compat/verify reports не повышены внешними результатами.

Это ограниченная текущая приёмка, без отдельного native startup и human sample. Отдельный init downstream, SKILL-02–04/PROC-03–04 и варианты update/негативных источников не закрыты этой серией; исторические эксперименты не переносятся на кандидат автоматически. Полная задача3.6 стенда и release4.1 остаются открытыми. Локальные L1 и доставка имеют собственные границы. Внешний CLI и сгенерированные им development skills по-прежнему не входят в Tibicen.
