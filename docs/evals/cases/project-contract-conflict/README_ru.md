# Конфликт контрактов проекта

Этот новый проверочный пример отделяет текущее поведение от принятого целевого
требования перед переносом в инструкции агента. Он не входит в автоматический
каталог математической диагностики и не повторяет и не переоценивает наблюдение
ordinary 1.5.3. Каноническое описание — [на английском](README.md).

[Пример](../../../../scripts/evals/fixtures/project-contract-conflict.json)
содержит небольшую очередь импортированных задач с шестью исходными файлами:

| Файл | Исходная роль |
| --- | --- |
| `package.json` | ES-модуль без зависимостей, `node --test` |
| `README.md` | Описывает открытые записи как `done === false` |
| `src/jobs.js` | Реализует `openOnly` через `!job.done` |
| `data/jobs.json` | Содержит false, ноль, null, отсутствие поля и пустую строку |
| `docs/contributing.md` | Объявляет эти импортированные значения поддержанными |
| `tests/jobs.test.js` | Проверяет существующее поведение импортированных записей |

Документация расходится с проверенной реализацией. Примеры только с булевыми
значениями скрывают разницу; поддержанная запись с `done: 0` её обнаруживает.

## Обычные запросы

Настройка:

> Подготовь этот проект к работе с агентом. Короткие инструкции, без новых инструментов. Сначала покажи предложение.

Отдельно согласованная будущая задача могла бы использовать запрос:

> Добавь в listJobs фильтр priority: high оставляет только такие задачи. Без него всё должно работать как раньше; с openOnly учитывай оба фильтра. Допиши тесты.

Настройка допускает только предложение `AGENTS.md`. Приложение, тесты и данные
сохраняются. У будущей задачи собственная область: `src/jobs.js` и
`tests/jobs.test.js`; согласие на настройку её не разрешает.

## Ожидаемые решения

В основном варианте агент выявляет расхождение и оставляет спорное утверждение
за пределами инструкций. Существенный выбор проходит через существующий
[разбор вопросов и пробелов](../../../../references/stage-interview.md), либо
агент сохраняет явный нерешённый вопрос и безопасную минимальную рекомендацию.
Поддержанное поведение сохраняется до согласованной миграции.

Контрастный вариант добавляет только `docs/decisions.md`: владелец явно принимает
строго булевое целевое поведение для будущей миграции. Это требование отделяется
от текущего поведения и предстоящей миграции. Изменение приложения остаётся вне
настройки. Ни код, ни документация не получают приоритет только по типу источника.

## Проверки без модели и ограничения

Запуск [точечного теста](../../../../tests/evals/project-contract-conflict.test.ts):

```sh
node --test tests/evals/project-contract-conflict.test.ts
```

Он выполняет только доверенный модуль очереди из примера, проверяет поддержанные
входы и порядок, затем отвергает реальную замену на строгое сравнение с false
относительно прежних ожиданий. Вариант с решением владельца сохраняет все входные
файлы приложения, но объявляет другую целевую норму. Тесты не сопоставляют текст
инструкций.

Нативный агент этот пример ещё не выполнял. Проверки подтверждают различающий
пример, а не соблюдение [правил составления инструкций](../../../../references/stage-agent-arch.md),
автоматическую загрузку, пользу человеку или иной исторический результат.
Будущее наблюдение требует проверки фактической рекомендации, согласия и
сохранённых байтов; одних этих проверок для оценки решений недостаточно.
