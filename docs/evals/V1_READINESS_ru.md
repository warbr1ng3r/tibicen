# Готовность полного MVP к версии 1.0

**Проверено: 2026-10-31. Решение: сохранить полный исходный MVP.** Владелец отклонил сокращённый scope стабильной версии. Этот реестр фиксирует недостающие свидетельства, а не отмену критериев, новые требования или разрешение на модельные прогоны и публикацию. Требования и подробные задачи остаются в связанных OpenSpec changes.

**Политика принята 03.11.2026:** полный функциональный/технический объём сохранён, техническая готовность определяется [инженерной оценкой](ENGINEERING_ACCEPTANCE.md) и независимым ревью по свидетельствам. Человеческие наблюдения пользы и калибровка рубрики — добровольное исследование после публикации; анкета владельца не запланирована. Их отсутствие явно указывается и не блокирует технический выпуск. Датированные записи ниже сохраняют прежние исходы экспериментов и ограничения на момент фиксации; старые человечески откалиброванные оценки не переписываются. Обязательные технические, эксплуатационные и относящиеся к точному кандидату пробелы остаются открытыми. Поля оценки и уровни свидетельств определены в [QUALITY_AND_REPORTS](QUALITY_AND_REPORTS.md#engineering-release-assessment).

**Инженерный аудит завершён 2026-11-03:** все 67 замороженных ID учтены в [оценке](ENGINEERING_ACCEPTANCE.md), проведено независимое интеграционное ревью. Оставшиеся работы разделяют недостающие решения/наблюдения, положительное применение компонентов на текущем профиле, привязку кандидата/охвата и публичную доставку/сопровождение. Подтверждённые механические подкритерии сохранены без объявления целых кейсов успешными. Этот аудит не устанавливает готовность 1.0.

Частная отправка GitHub включена, @warbr1ng3r подтверждён получателем security-сообщений; conduct-контакт и независимый advisory/checksum-канал остаются открытыми. Общая версия остаётся 0.1.0-alpha.1, нового executor или immutable публичной приёмки кандидата нет.

## Что действительно обещает полный scope

Продуктовые форматы — **Claude Code, Codex и Cursor**. Первая очередь внешних испытаний — **Codex, Claude Code и ZCode**; это разные оси. Наблюдения ZCode app не заменяют покрытие формата Cursor.

[Product Vision §10](../PRODUCT_VISION.md#10-engineering-layer) обещает автоматические headless полезные задачи и quiz только для Claude Code. Для остальных агентов допустим честный `unverified` с причиной. Поэтому ремонт экспериментального Codex native-runner не становится условием релиза автоматически. Положительные загрузка/применение компонентов и правдивые результаты по агентам остаются обязательными.

Собственные скрипты обещают Node ≥22.20 и кроссплатформенное поведение. Существующий отказ исполнения в Windows (`process-tree-unavailable`) предусмотрен контрактом; успешное исполнение команд Windows не является новой задачей MVP. macOS-наблюдения и Ubuntu CI не подтверждают полную Linux/Windows-приёмку продукта. До запуска нужно записать заявляемые сочетания и пробелы, а не подразумевать каждую комбинацию OS × Node × agent.

### Assertions доставки точного кандидата

Переиспользовать процедуру alpha с новыми immutable refs и отдельными тестовыми scopes. Проверить inventory/версии обоих установленных скиллов и standalone self-test; public alpha → candidate; backup локальных изменений установленной поставки **и восстановление этого backup**; сохранность preset, manifest/history и прерванной сессии; новое согласие на оставшуюся работу; отказ неизвестной схеме без записей; удаление с сохранением внешних файлов. Installer replacement может удалить локальные дополнения внутри установленного каталога, поэтому backup находится снаружи. Обновление инфраструктуры проекта и замену установленного Tibicen учитывать отдельно.

Проверять заявленные runtime/платформенные сочетания, включая нижнюю границу runtime и ожидаемый Windows refusal, где применимо. Локальный архив не заменяет публичную Git SHA/tag установку. Точные public refs замораживаются после подготовки проверяемой поставки; опубликованный alpha tag не перемещается.
