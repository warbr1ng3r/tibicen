## 1. Цели второго этапа

1. **Широта харнессов** (HOST-04/05/07 исходного плана): ещё один полный CLI-цикл на
   **Gemini CLI** (Gemini-формат — четвёртый протокольный путь), плюс **Qwen Code CLI**
   и/или **DeepSeek Harness** (chat-семейство, дешёвый контраст). Roo/Kilo — legacy/IDE
   заметки, если автоматизируемы headless; иначе честная запись «ручной лимит», без фальшивых
   результатов.
2. **Широта моделей** (MODEL-04) на проверенном харнессе: на OpenCode по одному циклу на
   2–3 модели Polza (например, `z-ai/glm-5.3` — следить за ценой вывода 166.9 ₽/М;
   `qwen/qwen3.8-flash`; повтор `minimax` с большим капом только если дёшево). Смена модели =
   одна строка конфига = новое наблюдение; кросс-выводов нет.
3. **Недостающий кусок плана: adopt** (ADOPT-01/02/03): на настроенном проекте OpenCode —
   исправление одной действительно устаревшей команды, побайтовое сохранение User-decision при
   удалении legacy-правила и no-op повтор без записей.
4. **Продуктивизация находок этапа 1** (Unreleased-файлы скиллов + репозиторий):
   а. указание «проектные секции — ВНЕ управляемого блока» + regression в evals;
   б. указание для Claude Code: файловая форма `--input PATH` вместо stdin-pipe;
   в. перенос фикса классификатора раннера (границы слов) из scratch в репозиторий.
5. **Инженерные долги аудитов этапа 1** (каждый — небольшая правка, офлайн, 0 ₽):
   ENV-04 транспорт-моки (DNS/TLS/ECONNREFUSED/hung-body), RUN-01 таймстемпы уровня
   supervisor, ORACLE-02 мутации округления/пустого входа, PRESET-05 кросс-проектный пресет,
   CHECK-02 тест запрета publish/deploy argv, MCP-01 вывод списка форматов из кода,
   SAFE-10 тест конкурентного apply, DIST-06 автотест восстановления из бэкапа.
