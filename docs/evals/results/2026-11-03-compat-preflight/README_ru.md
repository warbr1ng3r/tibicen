## Фактические результаты подготовки

Оба вызова ниже использовали наблюдённую версию, фактические путь/хеш закреплённого скилла и собственную копию. `startupControlled` намеренно оставлен **false**: first-party инспектор проверяет дерево скиллов проекта, а help и документация не подтверждают полный startup незапущенного native-процесса или отсутствие/эффект управляемой host-политики. Безопасное дерево проекта записано отдельно и не повышено до полного контроля startup.

| Функция кандидата | Наблюдённый результат |
| --- | --- |
| `prepareCompatCommand` для Claude | `status: unverified`, `reason: startup-uncontrolled`; команды нет |
| `prepareCompatProbe` для Claude | `kind: compat`, `status: unverified`, `loading: unverified`, `reason: startup-uncontrolled`; закреплённые identity/версия сохранены; команды нет |
| `prepareCompatCommand` для Codex | `status: unverified`, `reason: headless-method-unverified`; только политика кандидата, без проверки executable/версии Codex |
| `prepareCompatCommand` для Cursor | `status: unverified`, `reason: headless-method-unverified`; только политика кандидата, без проверки executable/версии Cursor |

Кандидат проверяет startup раньше auth. Поэтому этот проход **не** вернул `auth-unavailable`; отдельно наблюдённый отсутствующий/неразрешённый API-ключ остаётся самостоятельным условием. Положительный бюджет или auth-переменная для получения ready-команды не выдумывались. Runner не передавался и не вызывался.

Текущие официальные [документация headless](https://code.claude.com/docs/en/headless) и [CLI reference](https://code.claude.com/docs/en/cli-reference) прочитаны 03.11.2026. Они различают bare mode, явную загрузку скиллов из добавленной папки и auth/startup-флаги. Headless-страница также уточняет отдельное поведение bare до v2.1.286; актуальная документация не подставлялась вместо наблюдённого поведения локальной 2.1.283. Эти источники и имена флагов help — метаданные, а не живая startup-траектория.
