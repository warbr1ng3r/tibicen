# Criterion applicability review — 3 November 2026

The gap ledger overstates the two-tool requirement: **the authored cases do not require launching Codex and Claude or proving both tools' native use.** They require consistent, traceable shared revisions and handling an outdated copy. Loading and behavioral observations remain separate results governed by the applicable probe contract. This is a documentary correction, not acceptance of unobserved behavior or a reduction of the MVP.

This read-only review compared the [engineering assessment](../../ENGINEERING_ACCEPTANCE.md) with the original [product vision](../../../PRODUCT_VISION.md), its [addendum](../../../PRODUCT_VISION_ADDENDUM.md), main and active OpenSpec requirements, authored cases and agent/profile contracts. It assigns no new case grades. Root retains the shared ledger and will independently review any correction.

## Mandatory evidence remains mandatory

[Vision §10.11](../../../PRODUCT_VISION.md#10-engineering-layer) still requires actual controlled L1 setup/improvement runs, repeated use and the ML infrastructure fixture, strict invariants and independent functional-quality assessment. Agent judgment about sufficiency, conflicts, sources, refusal and safe continuation is not established merely by testing a supplied plan. The corrections above remove added observations, not the original decisions.

[Vision §13](../../../PRODUCT_VISION.md#13-target-product-first-release-and-implementation-order), [component release criteria](../../COMPONENT_INTEGRATION.md#evidence-reporting-and-release) and the active [optional complete workflow requirement](../../../../openspec/changes/extend-infrastructure-contracts/specs/process-configuration/spec.md#requirement-the-first-process-adapter-supports-an-optional-complete-workflow) require positive selected-version installation/loading/use of an additional skill and OpenSpec init/adopt/update with applicable fresh-session process work. Ordinary per-project compatibility can be `unverified` under [§6.4](../../../PRODUCT_VISION.md#64-internal-compatibility-probes); this cannot substitute for those mandatory positive release observations. The [technical acceptance requirement](../../../../openspec/specs/product-scope/spec.md#requirement-technical-release-acceptance-preserves-full-mvp-obligations) also retains exact-candidate delivery/update/recovery, declared support and maintenance.

The 67 prepared cases define coverage and expectations, not 67 live runs on every agent. The matrix authoring code also assigns separate following tasks; a narrow setup-content review does not prove those tasks ran. Reuse must be bound to the actual inputs, observed bytes/configuration and criterion. A full transcript is not a universal output-format gate, but missing observations needed for loading, application, consent or process cannot be supplied by prose review. Historical failures, attempt ceilings and assistance remain unchanged. This audit does not determine final readiness while evidence integration remains open.
