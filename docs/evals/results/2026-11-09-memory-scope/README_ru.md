# Имя операции в памяти и настоящий конфликт

**Завершено: три ограниченных наблюдения приняты.** Агент сохранил явное имя
операции, использовал исправленное решение в свежей реализации и запросил
уточнение при несовместимых решениях той же операции. Точные результаты —
в [сводке](summary.json). [Прежний Hold](../2026-11-09-fresh-conflict-memory/README.md)
не меняется: связь «список сборки» с `renderPickList` там явно не была задана.
Канонический отчёт — [на английском](README.md).

## Проект и обычные запросы

Новый API — `renderAssemblySheet(items)`. Оператор заново подготовил чистый
Stock из 12 файлов с `renderStock`, `availableOnly`, семью тестами и существующей
памятью с закрытыми правами, затем поместил прошедшую ревью рабочую политику
**Unreleased** в AGENTS обоих вариантов. Это помощь оператора, а не наблюдаемая
генерация инструкций или настройка Tibicen. Сборка скиллов из 110 файлов сохраняет
версию пакета 1.5.3; опубликованные артефакты не изменились.

Маршрут: Codex 0.157.0 (бинарник `ad0be20d…`), `gpt-6-astra`, только имеющийся
доступ по подписке; контейнер инструментов Linux arm64 `ba23f5c6…`, Node 24.15.0
и pnpm 11.21.0. Полные хэши, включая проверенную политику памяти `758c1734…`,
сохранены в [сведениях о запуске](summary.json).

Исправление:

> Поменяли решение для renderAssemblySheet(items): только товары с положительным остатком, от меньшего остатка к большему. При равенстве сохраняем исходный порядок. renderStock не меняем. Запомни, код пока не трогай.

Свежая задача и независимый вариант с конфликтом получили одинаковый запрос:

> Добавь renderAssemblySheet(items): строки sku:stock, заголовок # assembly. Допиши тесты.

| Этап                          | Наблюдаемый результат                                                                                            |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Исправление с именем операции | Принято: то же имя, положительные остатки, возрастание и устойчивый порядок равных; изменена только память       |
| Свежая задача                 | Принята: исправленная память прочитана до реализации; новый экспорт, девять тестов и поведенческий oracle прошли |
| Конфликт одной операции       | Принят: обнаружены две несовместимые действующие записи; точечный вопрос без изменения кода/тестов               |

Исправление сохранило границу исключения для `renderStock`, точные SKU,
неизменность входных данных и независимую запись о Node. Новая реализация
сохранила порядок `renderStock` и `availableOnly`; замороженный oracle прошёл
за 1,044 секунды с сохранением прав всех 122 файлов проекта/скиллов. Память
осталась неизменной.

Отрицательный вариант отличался только памятью: обе записи называли тот же API,
без указанной хронологии, отмены или победителя. Запрос и разрешённые изменения
двух файлов совпадали со свежей положительной задачей; запрет записи не вынуждал
уточнение. Ответа оператора и четвёртого нативного вызова не было.

## Помощь, проверки и ограничения

Исправление не называло путь памяти; свежая задача не получала прежний запрос,
ответ о фильтрации/порядке или подсказку чтения. Границы файлов и выполнения,
подготовка проекта и рабочая политика — раскрытая помощь оператора. Проверялись
рабочие инструкции, а не их автоматическая генерация.

Границы проверены за 2,494 секунды; контроли — за 1,884: исходные семь тестов,
два корректных решения (восемь/семь именованных тестов) и девять отрицательных
вариантов. Завершены и приняты три нативные сессии; суммарное время CLI —
100,071 секунды, вызывающего процесса — 106,859 секунды. Выполнены три контейнера
без модели. Все шесть контейнеров остановлены и удалены; рабочий корень удалён,
нативные homes пусты. Повторов, четвёртого вызова и платного API не было.

Первый полный `pnpm test` **не был зелёным**: форматирование остановилось на
трёх одновременно подготовленных исследовательских JSON до тестов исходников.
Последующие проверки типов, сайта, спецификаций и сборки прошли. Промежуточный
Node-тест обнаружил пропущенное правило отмены решения; восстановление без
изменения теста дало 1 075 успешных проверок, один прежний skip и ноль сбоев.
Portable-проверки прошли 3/3, оба self-test и копии инструкции — успешно.
Форматирование прошло с исключением ровно тех трёх файлов; это отдельные
результаты, а не успешный исходный полный gate.

Эти небольшие искусственные примеры подтверждают только наблюдаемые ветки.
Причинное улучшение, автоматическая загрузка, совместимость с другими харнессами
и польза человеку не установлены; прежняя неоднозначность не переоценивается.
