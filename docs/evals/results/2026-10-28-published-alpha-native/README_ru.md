# Опубликованная alpha: нативное обнаружение и приёмка компонентов

28 октября 2026 опубликованная alpha подтвердила неявную нативную загрузку
инструкций Tibicen и две полезные задачи с компонентами в отдельных новых app
контекстах. Нативная задача Ponytail загрузила скилл, но остановилась на ошибке
инструмента и не завершилась. Эти результаты учитываются отдельно.
Канонический текст: [English report](README.md).

Неизменяемая `v0.1.0-alpha.1`, distribution commit
`db03ebc988af1e38ea9f62c02027945ba40660fc`, установлена в одноразовые сгенерированные
проекты. Все 86 файлов совпали с закреплённой поставкой. Этот прогон не привёл
к исправлению продукта Tibicen, изменению поставляемых скиллов или release assets.

## Обнаружение, загрузка и остановившаяся нативная задача

Запрос R2 не называл Tibicen и не просил читать инструкции. Записанная команда
прочитала установленный tibicen-init с SHA256
`9d0c81dfb488f64e27f97250d15722f5588a730c915a8852041707b0c26e692a`.
Root подтвердил неизменность всех 91 host-файла, побайтное совпадение 91 собранного
файла контейнера и его остановку/удаление. В этом кейсе не было AGENTS.md;
инъекция AGENTS и загрузка тела adopt не проверялись. R1 остаётся ошибкой сбора
с неизвестным более ранним стартом модели. R2 — одна отдельно проверенная
повторная попытка после исправления протокола сбора; дальнейших повторов не было.

В отдельном нативном рендере проекта Ponytail без модели точные байты AGENTS.md
автоматически внедрены и совпали с setup SHA256
`a8ef92715b146df94821b37e1f3874668cb3df0552267e265e757a2695cbd833`.
Найдены точные metadata и aliased project path Ponytail. Оба renderer-наблюдения
использовали изолированные debug-конфигурации и сами по себе не доказывают
тождество live-конфигурации или загрузку полного тела скилла.

Настоящая нативная задача Ponytail неявно прочитала полный закреплённый SKILL.md,
SHA256 `9badd22a32e19cb884e46dfa8d3aae82bb81dfa5484105b8b4f0262df823a509`.
Модель стартовала, но не завершила работу. Конкретная причина tool-failure
недоступна в сохранённой траектории. Остановка/удаление контейнера подтверждены;
fail-closed сбор вернул ноль файлов, поэтому набор его записей не проверен.
Все 9 host-файлов и режимы были сохранены до отдельной app-задачи. Флаг
source-guard:false не доказывает изменение исходников: root отдельно сверил все
20 закреплённых хэшей после остановки. Native-повтора не было. Последующий
app-результат не повышает статус остановившейся native-задачи.

## Setup, согласования и полезные app-задачи

Ponytail — настоящий upstream
`DietrichGebert/ponytail@09c434ab73ca43761c5d8b0c5d341926c2fba710`, MIT, с точными
байтами SKILL.md и LICENSE. Синтетическим скиллом он не подменялся. OpenSpec
запрошен явно: это дополнительная интеграция процесса, а не условие обычного
прогона Tibicen. Изолированная копия 1.14.3 содержит 57 пакетов / 2093 файла,
совпадающих с закреплёнными зависимостями и прошлой принятой runtime-копией.
Все 431 ресурс OpenSpec совпадают с frozen inventory обычных файлов.
Самостоятельный version smoke вернул 1.14.3 без записей в свежем HOME/XDG.
Для setup не использовались native init/update или изменение зависимостей
приложения; внешний runtime не входит в дистрибутив Tibicen.

Root проверил оба точных setup-proposal и выдал отдельное **синтетическое
согласие оператора**, а не прямое человеческое одобрение digest. Реальные
apply → verify → status → report завершились complete: 3 новых файла
инфраструктуры для Ponytail, 5 для OpenSpec; байты и режимы всех 10 исходных
файлов приложения/package/README сохранены. Baseline на Node 24.15.0 дал
2/2 теста в каждом проекте.

Исходные встроенные отчёты оставлены без повышения статусов: infrastructure
passed structure-only (включая process/package-resource verification OpenSpec),
project verification `unverified/no-project-checks`, task/quiz
`unverified/not-requested`, compatibility loading Ponytail
`unverified/trust-required`, process loading/task/CLI execution OpenSpec
`unverified`. Внешние наблюдения не переписывают эти отчёты.

Отдельная новая app-задача реализовала clamp, сохранив double. App-контекст
OpenSpec явно прочитал установленный first-party адаптер и native schema/templates.
Root отдельно согласовал пять точных planning paths, принял strict-valid план
с сохранением всех 11 прежних файлов, затем согласовал два файла приложения
и отметки выполнения задач. Root подтвердил ровно эти три изменения,
13 защищённых файлов без изменений, наличие всех 16 ожидаемых файлов,
отсутствие лишних добавлений/удалений и сохранение всех 11 исходных режимов.
Проверки mean покрыли обычные, пустые, некорректные входы, неизменность входа,
численные случаи и прежнее поведение sum. CLI instructions apply показал
all_done, 4/4 задачи.

App subagent процесса сначала наблюдал Node 25.8.0; этот receipt сохранён
отдельно. Все записанные planning, implementation и root acceptance проверки
использовали явный Node 24.15.0. Итог app-наборов — **14/14**, без ошибок/skip,
плюс **две независимые скрытые проверки**. Это полезность в app-контексте,
а не полный native model workflow или измеренное преимущество над
ненастроенным проектом.

## Доказательства и оставшийся объём

[Машиночитаемые результаты](results.json) сохраняют отдельные профили и оси.
Точные планы/digests, синтетические согласования, траектории, хэши, неудачный
сбор, исправления подготовительных проверок и независимые root receipts
остаются локально у сопровождающего; персональные пути, авторизация и полные
траектории исключены. Независимое ponytail-review приняло ограниченные свидетельства и изменения приложений: Ship. Основной отчёт сохраняет проверенные границы и ограничения.

Подтверждённого дефекта продукта Tibicen не найдено; эти наблюдения сами по
себе не обосновывают новый релиз. Открыты завершение полезной native-задачи
после ошибки инструмента Ponytail, полный нативный OpenSpec workflow,
нативное обнаружение/новая полезная задача ZCode, полная матрица SKILL/PROC,
межплатформенная приёмка и пилот с людьми. Польза человеку, экономия
времени/стоимости и причинное преимущество не измерялись. Платный API-маршрут
не использовался. Приёмка полного MVP остаётся открытой.
