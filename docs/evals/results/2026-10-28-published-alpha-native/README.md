## Discovery, loading and the stopped native task

The R2 user prompt did not name Tibicen or ask for an instruction-file read. The
recorded command read installed tibicen-init with SHA256
`9d0c81dfb488f64e27f97250d15722f5588a730c915a8852041707b0c26e692a`.
Root verified all 91 host files unchanged, all 91 collected container files byte
matched, and container stop/removal. This probe had no AGENTS.md; it did not test
AGENTS injection or adopt body loading. R1 remains a collection failure with
unknown earlier startup. R2 was one separately reviewed amended attempt after a
collection-protocol correction; no further discovery repeat was performed.

injected the exact AGENTS.md bytes, matching setup SHA256
`a8ef92715b146df94821b37e1f3874668cb3df0552267e265e757a2695cbd833`.
Ponytail's exact metadata and aliased project path were discovered. Both renderer
observations used isolated debug configurations; they do not prove identical
live configuration or full skill loading by themselves.

The actual native Ponytail task implicitly read the complete pinned SKILL.md,
SHA256 `9badd22a32e19cb884e46dfa8d3aae82bb81dfa5484105b8b4f0262df823a509`.
The model started but did not complete. The specific tool-failure cause is
unavailable in the retained trajectory. Container stop/removal was confirmed;
fail-closed collection returned no files, so its write set is unverified. All 9
host files/modes were preserved before the separate app task. A false source-guard
postcheck does not establish source mutation: root independently matched all 20

result does not upgrade this stopped native task.
