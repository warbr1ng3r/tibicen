# Подготовка релиза Tibicen 1.4.0

**Неопубликованный черновик — 6 ноября 2026, Europe/Moscow.** Владелец разрешил
работу до коммита, push и публикации. До завершения публичных проверок кандидата
и сверки полученных файлов текущим релизом остаётся опубликованная 1.3.0.
Этот отчёт описывает подготовку и не подтверждает публикацию.

## Состав и совместимость

Планируемая версия — **1.4.0**, совместимый минорный релиз:

- Необязательные сведения о выбранном харнессе/версии, рабочем каталоге и пути
  задачи делают отчёт и передачу работы init/adopt конкретнее. Связи инструкций
  по расположению файлов отделены от наблюдаемого нативного чтения/использования.
- Команда только для чтения `mcp-diagnose` изучает один выбранный локальный сервер
  максимум в четырёх разрешённых файлах проекта ограниченного размера. Она
  объясняет выбор источника, отключение, условия запуска и точное поддерживаемое
  исправление либо следующий шаг в нативной среде.
- Любой корректный ID харнесса позволяет явно выбрать известный формат либо
  передать очищенные наблюдения stdio, связанные SHA-256 с изученным UTF-8
  текстом источника. Модель, провайдер и наличие в каталоге не ограничивают маршрут.
- Восемь контрактов форматов охватывают Claude Code, Cursor, Gemini CLI,
  OpenCode V2, нативный/общий JSON ZCode, текущий JSON Kimi Code и ограниченное
  подмножество TOML Mistral Vibe. Выбор формата не разрешает новые записи или запуск.

Прежние вызовы отчёта, сохраняемые схемы, пресеты, файлы памяти проекта и границы
одобрения остаются совместимыми. Контекст задачи и наблюдения MCP передаются
на время запроса; миграции сохраняемых форматов нет. Автоматическая запись MCP
по-прежнему доступна только прежним адаптерам Claude/Cursor; ручной помощник
Codex сохранён. Замена установленных скиллов не обновляет настройку проекта.
См. [форматы MCP](../../../MCP_FORMATS.md),
[диагностику задачи](../../../ADOPT_DIAGNOSIS.md) и
[процедуру релиза](../../../RELEASING.md).

## Проверки точного кандидата 1.4

Установка зависимостей и сборка зафиксированного кандидата прошли закреплёнными
инструментами. Свежий полный gate завершился кодом 0: 891 тест прошёл, ноль ошибок,
один ручной standalone пропущен (всего 892). Он включал lint, форматирование,
типы, сборку сайта, строгие спецификации и сборку дистрибутива. Отдельный запуск
точного standalone-кандидата на macOS arm64 / Node 24.15.0 прошёл обе самопроверки,
все 12 MCP CLI-фикстур, отчёты с контекстом задачи и прежним вводом, а также
пропущенный жизненный цикл (3/3, без пропусков). Файлы/режимы фикстур сохранены,
маркер запуска сервера не появился. Проверка жизненного цикла использует
синтетические изолированные home/PATH и точное одобрение оператора для своих
фикстур; это не запуск нативного приложения.

D01 проверил локальную универсальную замену 1.3→1.4, идентичный повтор, обе
самопроверки установленных скиллов, полное восстановление изменённых резервных
копий в фактические каталоги установленных скиллов и удаление. Все 100 файлов
поставки совпали. Синтетическое приложение из семи файлов, последующая запись
памяти владельца, соседние скиллы, внешние настройки и исходные входы сохранены.
Тесты приложения не запускались: это свидетельство жизненного цикла установки.
Доверенный установщик сохранял обычную возможность чтения среды; запись
ограничивалась своими путями. Изоляция ОС и системный firewall не заявляются.
Публичная доставка по SHA и `skills update` не наблюдались. Независимая приёмка
D01 не заменяет ожидающие кейсы инструкций.

Исходные свидетельства сохранены локально в `release-1.4-20261106`: candidate-01,
его standalone-запись и попытка доставки D01. Платные API и нативные приложения
не использовались. Публичная доставка, скачивание файлов и Pages — отдельные этапы.
Привязки SHA-256 свидетельств: кандидат
`2e17e92744432dde5f818ebe9411a4c4a7b884c151220b594febf001affb44b9`,
standalone `ba7be87da74ae10cd2a6b2ae1b7f4b9922756388661e8b1e2c1f4ef2f3f3d672`,
D01 `45bc1902e4c2b10b30e38fba55ad16a409323f129b4ffb83f6bda412dbf58f5e`.

## Свежие наблюдения инструкций

Два свежих внутренних агента явно прочитали зафиксированный скилл и нужные
ссылочные файлы, затем использовали только разрешённые фикстуры и CLI кандидата.
Гипотетический контекст харнесса/задачи был передан. Нативные приложения не
запускались; планы не применялись, файлы проекта/конфигурации не менялись.

| Кейс | Фактическое наблюдение и ревью |
| --- | --- |
| I1 / вход init, неизвестный private-team-agent | Четыре вызова CLI, без повторов. Переданы неизвестный харнесс/контекст задачи и наблюдения собственного YAML, привязанные к хэшу источника. Конфигурация сохранена, изменения не рекомендованы до нативных свидетельств; завершение manual-action-required. Независимый результат принят в рамках одних рекомендаций. Это не применённая первичная настройка. |
| A1 / вход adopt, выбран ZCode | Все шесть вызовов CLI завершились кодом ноль, без повторов. Предложена только замена отсутствующего `pnpm lint` на документированный `pnpm test` из корня с явным указанием, что lint не настроен. Правила целых центов, память, инструкции подкаталога и отключённый MCP сохранены. Независимое ревью: Ship для сформированного без записи и неприменённого плана; байты/режимы всех 50 файлов скилла и шести файлов фикстуры сохранены. |

В I1 встроенное сканирование не признало собственный `.team/mcp.yml`
инфраструктурой; переданный контракт харнесса позволил составить инвентарь вручную.
Эта помощь и неизвестный нативный рабочий каталог сохранены в отчёте, без заявлений
автоматической поддержки формата или доказанного дефекта отсутствующего скрипта.
A1 сообщил кандидатов инструкций по расположению, не обещая нативного слияния,
и раскрыл будущие служебные/usage-записи в плане; они не выполнялись. Все байты и
режимы фикстур/зафиксированного дистрибутива сохранены. Тесты приложения и полезная
задача не запускались.

Их дистрибутивы содержали байты разработки с метаданными версии 1.3.0;
они никогда не были опубликованным дистрибутивом 1.3.0.

| [Контекст задачи в init/adopt](../../../../openspec/changes/explain-task-aware-setup/verification.md) | 849 тестов полного gate прошли / один standalone пропущен; отдельный жизненный цикл точного дистрибутива 3/3. Четыре свежие сессии с переданными исходниками и фикстурами наблюдали чтение, использование и исправление инструкций/памяти. Идентичности харнессов были входными данными, а не запущенными приложениями. Применение через API использовало отдельные явно заданные домашние каталоги. |
| [Локальная диагностика MCP](../../../../openspec/changes/diagnose-local-mcp-context/verification.md) | Итоговый gate: 872 прошли / один standalone пропущен; отдельный жизненный цикл 3/3, обе самопроверки и 15 CLI-кейсов. Эти результаты подтверждают только заявленные автономные сценарии и сессии с
переданными исходниками. Изменение байтов поставки требует повторных затронутых
проверок. Прежние публичные релизы, неудачи, неисполненные кейсы и помощь сохраняют
исходную идентичность; см. [отчёт 1.3](../2026-11-05-release-1.3/README.md).

## Сохраняющиеся ограничения

В этих пакетах не наблюдались запуск нативного приложения, MCP-handshake,
обнаружение инструментов, работа живой модели/провайдера и полезность для людей.
Привязка хэшем подтверждает источник наблюдения, но не правильность, безопасность
или применение его интерпретации в нативном клиенте. Разобранная конфигурация и
переданные вызывающим наблюдения сохраняют разные результаты. Личные настройки,
учётные данные и платные API-вызовы не входят в эту работу. Публичная доставка и
Pages остаются отдельными проверками до записи фактических свидетельств.

[Черновик заметок релиза](release-notes.md) подготовлен для публикации только после
успешного завершения ожидающих проверок.
