were reconstructed at 23:23:47, after application. Actual CLI receipts consume the
matching envelope digests, which proves content binding. The original separate grant
messages and operations are not exported. U5 has an initial fixture grant, but no retained
separate resume grant. This is missing proof of the pre-write authority under test,
not evidence that self-approval occurred. CASES copies declared prompts from PROTOCOL;
it is not a host event export. FRICTION summarizes questions/answers rather than retaining
their literal original text. Counts and zero unnecessary waits remain reported synthetic
friction, not measured human effort.

**Freshness.** The stated Agent-tool reset mechanism has no retained host documentation,
launch-control event or complete initial-context receipt. Declared U4 ordinary prompts
contain no threshold answers; actual complete context remains unknown. A fresh worker ID
or an answer consistent with memory does not satisfy the revision-02 admission requirement.
Keep the freshness-dependent dimension `context-isolation-unverified`; native ZCode
loading and human usefulness remain unknown.

**Timing.** The frozen rule limits each executor phase to 360 seconds and stops dependent
calls after an overrun. The report later resets the count for consent continuations.
Reported setup segments sum to **388 seconds for U1, 430 for U2 and 367 for U4**, excluding
controller wait time, and later dependent work still ran. Preserve this protocol deviation.
The 17 reported invocations count continuations and are arithmetically consistent with the
32/16 ceilings; four-way concurrency, about 50 minutes and zero new paid API spend remain
reported within coarse host accounting. Subscription usage/cost is unknown.

**Memory history and recovery scope.** U4's after-work snapshot is timestamped after the
reported correction start, and early code/test/memory bytes were not retained. The claimed
digest-drift rejection is a later narrative without the original failing envelope or output.
For U5, the controller helper omitted the beforeApply runtime hook that ordinarily captures

preparation limit, not proof that every CLI crash there happens before baseline capture.

The returned execution review's SHIP is coordinator-reported; its reviewer transcript/verdict
is not retained. Earlier Codex preparation review files are a different scope. This assessment
keeps the positive functional results without importing the claim that all execution claims
