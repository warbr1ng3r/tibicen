# Наблюдения первой нативной сессии — 6 ноября 2026

**Пакет закрыт: Pages и локальные исправления проверены; нативные запуски остановлены после неудачной S1.**
Опубликованные скиллы остаются
[1.4.1](../2026-11-06-release-1.4.1/README.md).
Выполнением управляет [пакет работ](../../../../.scratch/native-first-use/map.md),
статусы — на [дашборде](../../../../.scratch/native-first-use/dashboard.md).
Это техническая проверка одного собственного синтетического Node-проекта,
а не человеческий пилот или проверка всех харнессов и моделей.

## Что просили и что произошло

Изначально в проекте были package metadata, README, одна функция `formatTicket`
и один встроенный Node-тест. Инструкций агента и памяти не было. Условный владелец
выбрал память проекта, лимит семь тикетов на экспорт и согласование зависимостей;
CSV оставался непринятой идеей.

| Шаг | Запрос или действие | Фактический результат |
| --- | --- | --- |
| Предложение настройки | Настроить агента, сохранить решения и сначала показать изменения. | Одна настоящая сессия Codex CLI завершилась. Она прочитала опубликованный скилл целиком и нужные ресурсы, затем настоящим CLI предложила `AGENTS.md` и `.agents/memory.md`. Без изменений приложения, лишних инструментов и apply. |
| Применение оператором | Независимо проверить и применить точный план в собственном контейнере. | Одобренные файлы применены один раз; verify прошёл проверку структуры, status/report сохранили обязательное последующее чтение. Одобрение оператора отделено от нативного автора предложения и не считается согласием конечного пользователя. |
| Новая рабочая задача — S1 | Добавить разбиение тикетов на партии согласно решениям проекта. | Неудача/incomplete через 20,856 секунды. Подтверждены чтение точного `AGENTS.md` и список файлов; чтение памяти, реализация и приёмка задачи не проверены. |
| Позднее исправление — S2 | Заменить решение о лимите и обновить реализацию. | Не запускалось: остановлено после неудачи S1. Есть только черновики caller/запроса, без freeze, одобрения и попытки. |
| Новое чтение памяти — S3 | Объяснить результат с учётом исправленного решения. | Не запускалось: остановлено после неудачи S1. Есть только черновики caller/запроса, без freeze, одобрения и попытки. |

Маршрут настроен на Codex CLI 0.157.0, `gpt-6-astra`, существующую подписку
и закреплённую контейнерную границу репозитория. S0 завершилась за 116 секунд
с подготовкой вызывающей стороны; 14 нативных команд завершились с кодом ноль.
Digest точного плана — `f8544e6a16bf080c183681ae878399127178aa9a6348aaea836f9d62a85b0300`.
Независимое ревью подтвердило полные чтения, настоящий вызов proposal,
сохранность 54 защищённых файлов и всех 55 исходных файлов на хосте. Контейнер
остановлен и удалён. В плане остаётся обязательное последующее чтение инструкций
и памяти; структурный успех не означает завершённую активацию.

До обращения к модели отдельный контейнер без модели передал и вернул все 55
входов, прошёл исходный тест приложения и отклонил ещё не реализованный экспорт
в независимой контрольной проверке. Это отдельные результаты подготовки.
Нативное выполнение ограничено четырьмя последовательными запусками, 570
секундами, без повторов и платного API, с остановкой при первой неудачной фазе.
**Фактически выполнены две нативные попытки: S0 и S1.** Единственное применение
оператором выполнялось без модели и не считается третьей нативной попыткой.
Неудача S1 остановила пакет: повторов, заменяющей задачи, другого нативного
маршрута или запусков S2/S3 не было.

Первая проверка оператора ошибочно требовала временный файл состояния после
финализации. Исходный неудачный результат сохранён. Чтение кода и независимое
ревью подтвердили: успешная финализация удаляет временное состояние, сохраняя
`manual-action-required` в manifest. Те же 63 файла прошли исправленную проверку
без нового выполнения; apply не повторялся. Все четыре настоящих CLI-вызова
завершились с кодом ноль, одобренные содержимое/режимы и защищённые файлы совпали,
идентификаторы сессии manifest/usage согласованы. Root отдельно подготовил для
новой задачи только семь полученных файлов проекта; runtime, прежний proposal
и артефакты оператора не входят в контекст модели.

## Неудача рабочей задачи и независимая диагностика

S1 использовала новую сессию только с семью фактическими файлами проекта.
Запрос явно предлагал прочитать `AGENTS.md` и добавить `chunkTickets(tickets)`;
лимит партии, путь памяти и её содержимое в запросе отсутствовали. В сохранённой
траектории есть две завершённые команды, обе с кодом ноль:

- `cat project/AGENTS.md`: полный вывод совпадает с одобренным содержимым.
- `pwd; rg --files project`: показаны рабочая папка и список файлов.

Явного чтения тела памяти, изменения приложения, запуска тестов или завершённого
хода не наблюдается. Ссылка на память в `AGENTS.md` не доказывает её чтение.
Весь caller работал 20 855,904292 мс; нативный CLI — 17 199,418666 мс.
Исходный результат остаётся `pass: false`, `timedOut: false`, код завершения
внешнего CLI — `null`, `sourceUnchanged: null`. Результат контейнера содержит
`tool-failure` с `toolFailure: {kind: process-exit, exitCode: 1}`; остановка
и удаление прошли. Числовой код процесса не является кодом внешнего CLI.

Статический разбор кода и независимое ревью подтвердили механизм остановки:
ненулевое уведомление `process/exited` вызывает остановку существующим observer
с пустым списком собираемых файлов. В сохранённом результате нет связи процесса,
запроса и команды, необходимой для определения неудачной операции. Нельзя
приписывать ошибку ни одной из двух успешных команд. Причина неизвестна;
дефект модели, авторизации, лимита запросов или Tibicen не установлен.

**Из контейнера не собрано ни одного файла.** Записи, защищённые байты и режимы
в контейнере остаются непроверенными. Пять меток `protectedChanges` и семь
`invalidModes` исходного caller возникают из-за отсутствующих файлов/режимов,
что независимо воспроизведено без нового нативного запуска: это не свидетельства изменений
или ошибок прав. Исходные проекции и неудачный результат сохранены. Отдельно
все семь входных файлов хоста сохранили байты/режимы без обратной записи,
а двадцать хэшей исходников runtime совпали с freeze при последующей проверке
без запуска. Это не заменяет исходную недоступную полную проверку профиля.

Приватные первичные записи: `s1-outcome.json`, `s1-events.jsonl`,
`s1-collection.json` и `s1-host-preservation.json`. Независимая оценка находится
в `s1-result-review.md`/`.json`, ограниченная диагностика сохранённых данных —
в `s1-failure-diagnosis.md`/`.json`. SHA256 исходного результата:
`71385b9ffd443d07205d7b21820c6e6056ba8afd2656200e364b34625eb04f2a`;
SHA256 событий: `7094f91cf64f57c9ab1fe930f374ef5e6ef9bd02aeff48a852e4054d32bd4bb2`.
Ревью приняло точный отчёт о неудаче, а не рабочую задачу. Ранее сохранённые
записи оператора (`operator-raw.json`, исходный `operator-outcome.json`, отдельные
`operator-independent-review.json`, `operator-corrected-review.json` и решение
root) сохраняют исходную ошибку checker и исправленную оценку того же результата.

Код рабочей задачи не оценивался. Контроли oracle без модели показывают только,
что отдельная проверка отклоняет исходный пример и принимает заведомо правильный
контроль; это не нативная приёмка. Черновики S2/S3 не выполнялись, без новых
контролей, замороженных входов и оценки. Диагностика не запускала новые native,
Docker, auth или model-вызовы. Новой нативной попытки после этого не было.

## Исправление диагностики без нового запуска

[Ограниченное изменение](../../../../openspec/changes/correlate-contained-tool-failures/tasks.md)
сопоставляет запрос, ответ запуска и завершение процесса в стенде разработки:
идентификаторы сохраняются в виде хэшей отдельной сессии, факты завершения
проверяются. Объём наблюдаемого ввода ограничен; команды, пути, окружение,
вывод и тексты ошибок в диагностическом контексте не сохраняются.
Остановка при первом сбое, пустой сбор файлов при ошибке и очистка сохранены.
Прямая сессия уже фиксирует исходники owner/session; рекурсивная заморозка пакета
настройки включает его собственную проекцию результата. Стандартный профиль теперь
сохраняет безопасный контекст в существующем артефакте collection до сообщения
о неудаче дочернего запуска; содержимое файлов там остаётся хэшами и режимами.

Контекст подтверждает внутреннюю связь принятого `process/start` и завершения,
но сам по себе не восстанавливает команду, не связывает строку команды CLI
и не объясняет причину ошибки. Исходная S1 остаётся неудачной, её команда
и несобранные файлы — неизвестными. Проверка использует только имитацию транспорта;
[запись проверок](../../../../openspec/changes/correlate-contained-tool-failures/verification.md)
содержит итоговую проверку репозитория: 954 пройденных теста, один пропущенный,
независимый Ponytail Ship, отдельное ревью документации и сверку всех 100
неизменённых файлов опубликованных скиллов. Все 74 исходные записи прогонов
сохранены. Эти локальные проверки не меняют неудачу рабочей задачи и не заменяют
невыполненные фазы памяти.

## Ограничения

Явный путь чтения скилла — помощь; автоматическое обнаружение не проверено.
Claude Code и встроенный ZCode найдены, но нативные сессии через них не запускались.
Подключение MCP, широкая совместимость и измеренная человеческая польза остаются
непроверенными. Новый выпуск скиллов, изменение авторизации и дополнительные
коммиты исходников не входят в пакет. Полные запросы, события и результаты
сохраняются приватно.
