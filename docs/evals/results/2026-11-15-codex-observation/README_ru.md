# Наблюдение Codex, 15 ноября 2026 года

Отдельно разрешённая перепроверка adopt проекта документации завершила все четыре
CLI-шага; подробности ниже в разделе повторной проверки. Исходный пакет сохранён.

Восемь нативных попыток Codex CLI охватили четыре семейства искусственных
сценариев. Семь ходов завершились, один завершился ошибкой. **Это не показатель
успешности продукта.** [Обезличенный индекс свидетельств](evidence.json)
сохраняет отдельные результаты, хэши, помощь оператора, пропуски вывода и очистку.

## Кандидат и маршрут

Проверялась база исходников `31f87d993e76bbf546643211980c628c365500f0`
с проверенными изменениями надёжности из **Unreleased**: 110 файлов поставки,
хэш состава `9acde8988b871893705ecb8d11a5ed176b30b0312a941456627d4d2abd13e9f7`.
Опубликованная **1.5.4 не изменялась**.

Codex CLI **0.157.0** с настроенной моделью **gpt-6-astra** работал через
существующую подписку ChatGPT в выделенных контейнерах Linux arm64. Каталоги
хоста не подключались, инструментам сеть была недоступна. Каждая фаза начиналась
в новом CLI-чате. Дата указана для Europe/Moscow, сохранённые временные метки — UTC.

## Ограничения и сохранённые ошибки

Загрузка скиллов включала явное чтение с помощью оператора. Условному применению
предшествовали ревью root и точное искусственное одобрение контроллера; это
не наблюдения человеческого одобрения. Файлы проектов на стадии предложения
сохранились без изменений; для планов init/adopt разрешались два JSON-файла
контроллера вне проекта. Это наблюдалось, но **механически внутри контейнера
не обеспечивалось**. Собирались
данные по явным путям, без исчерпывающего наблюдения неизвестных файлов и
временных записей.

В свидетельствах оставлены отсутствие Python/git, пустой вывод команд и неверный
флаг `--approved` в инструкции root: исполнитель исправил его на документированный
`--approve` в той же нативной сессии. Эти случаи не скрыты и не объявлены
подтверждёнными дефектами продукта. Независимое ревью приняло наблюдения с
указанными ограничениями.

Выделенные контейнеры всех восьми уникальных CLI-чатов остановлены и удалены.
Суммарное время вызовов — **466 секунд** (около 7м46с), а не длительность всего
исследования. **Повторных запусков со стороны вызывающего кода — ноль**, новых
платных API-вызовов — тоже ноль. Это не число HTTP-запросов. Денежная стоимость и
токены неудавшегося хода неизвестны.

## Отдельная повторная проверка adopt

Владелец явно попросил перепроверить сбой в проекте документации. Одна
дополнительная свежая сессия через подписку использовала **те же 63 входных файла,
запрос, поставку и одобренный digest**. У неё отдельный предварительный протокол,
лимит 120 секунд и никаких автоматических повторов. Исходный пакет из восьми
попыток и его [свидетельства](evidence.json) не переписаны.
[Свидетельства повторной проверки](recheck-evidence.json) содержат идентификаторы
и хэши записей.

**Apply → verify → status → report вернули код 0, JSON каждого шага сохранён.**
Apply, status и report — `complete`; verify — `passed`, **только по структуре**.
Байты и права согласованного `AGENTS.md` совпали; остальные **62 входных файла**
и их права сохранились. Решения владельца остались вне заменяемого блока,
существующая память не изменилась. Добавлены только ожидаемые manifest и запись
usage. Контейнер удалён, временные домашние каталоги пусты. Независимое ревью
подтвердило эти выводы.

Время вызова — около **73 секунд**; новых платных API-вызовов и автоматических
повторов нет. Отсутствующая утилита `shasum` вернула 127; последующие проверки
байтов и прав через Node и независимая сверка состава прошли. Ошибка утилиты
сохранена в истории. Исходный сбой **не повторился; его причина остаётся
неизвестной**. Текст прежней ошибки был заменён хэшем до сохранения, а временный
домашний каталог CLI удалён. Для этой проверки в частную копию контроллера
добавлено ограниченное сохранение ошибок с удалением секретов; поставка продукта
не менялась. Самопроверка записи прошла; успешная сессия не дала терминальной
ошибки для сохранения. Это не доказательство исправления дефекта продукта или
провайдера.

## Сопоставление харнессов

[Оценка внешнего ZCode](../2026-11-15-zcode-observation/README.md) независимо
подтверждает итоговые файлы и идентичность планов, сохраняя ограничения сообщений
исполнителей о нативных действиях и чтении памяти в новых сессиях. В созданной
init-инструкции есть ошибочное ограничение обновления только через init. Это
замечание к качеству рекомендации, а не наблюдавшийся сбой безопасности CLI.

сгенерированной политики. Автозагрузка, восстановление прерывания и человеческая
полезность здесь не подтверждены. Эти наблюдения не меняют исходники или релиз и
не доказывают широкий охват хостов. Рядом остаются
[предыдущая оценка](../2026-11-10-reliability-runs/ASSESSMENT.md) и
