# Наблюдения ZCode после релиза: независимая оценка

Возвращённый пакет проверяет **опубликованную 1.5.5**, source `b3b981fb4fcce05a6348f9826c249df61c95a2a3`, distribution `6d4baea666fc2885c04ba0fa0fc60dbb8b4e6a74`. Он содержит полезные механические результаты и **провал обычной задачи с памятью**. «Подтверждённого дефекта runtime нет» не означает «всё поведение продукта прошло». [Проверенные идентичности и индекс свидетельств](receipt.json).

## Что проверено независимо

Совпали все **1 511 замороженных входных файлов/прав**. Байты всех **1 399 файлов рабочей копии исходников** равны замороженным; рабочая копия намеренно доступна для записи, а входы — только для чтения. Воспроизводятся оба digest: исходный `8744c238a0cc17acbec9c5b86f80e26e02a2b91641417a98cf106aafa79a6f56`, затем связанный с disposable HOME `175024ba0344ce51a5d52ffb7b83e41156328d3636fcb9b7fa839af3adcd0c81`. Изменения файлов одинаковы; поменялась связь usageFile/окружения, потребовав нового синтетического согласия контроллера. Тело и права обоих применённых файлов совпадают с планом. Четыре возвращённых JSON CLI имеют exit zero и согласованное состояние сессии.

Механические квитанции описывают настоящий exit/SIGKILL, сохранение исходного baseline, отсутствие дублирования проверки, отказ при чужом изменении и repair с новым согласием. Сохранённые prefix/suffix владельца, память, приложение и права adopt независимо совпадают с замороженными байтами. beforeHash вложенного правила подтверждает чтение CLI, а не понимание агентом. Исполнитель сообщил **44/44** и **88/88** базовых регрессий; это не модельные сессии.

Две оговорки к исходному отчёту:

- Механические drivers запускают **CLI из экспортированных исходников**, а не отдельную установленную поставку. Все поставляемые runtime-скрипты совпадают с этим исходником, но результат относится к механике привязанных исходников.
- Driver достаточной настройки **создал и применил пустой план**, обновив `.tibicen/manifest.yml`. Файлы проекта сохранены; выбор нативным агентом обходиться без proposal/сессии не наблюдался.

## Провал задачи и допуск протокола

Сгенерированный `AGENTS.md` повторяет отличительное решение. Контракт пользовательских разделов продукта это допускает, но прежняя проекция memory-only правильно отклоняет такой вход: `generated-memory-answer-leak`. Root воспроизвёл отказ. Исполнитель всё же запустил обычную задачу с объявленной адаптацией смешанного использования. Отдельный будущий протокол до запуска не был зафиксирован; считать это успешным допуском memory-only нельзя.

Root воспроизвёл результаты неизменённым scorer:

| Проверка | Фактический результат | Оценка |
| --- | --- | --- |
| общий `formatPrice(0)` | `0.00 EUR` | failed |
| обычная сумма | `12.50 EUR` | passed |
| возврат | `-2.50 EUR` | passed |
| строка чека | `Notebook: On the house` | passed |

Затем агент дописал в память `Boundary: the exception applies to receipt lines only` без исправления от пользователя. Исходная фраза владельца и посторонние правила приватности/зависимостей сохранились, но это не делает новое исключение согласованным. Видимые тесты проекта прошли 4/4, независимый scorer — только 3/4. Исправление и повторное использование исправленной памяти не запускались и остаются непроверенными. Дублирование ответа не позволяет доказать причинное использование памяти.

## Решения по результатам

1. **Уточнить сохраняемую политику:** принятые владельцем смысл и область сохраняются; противоречащая реализация записывается отдельно. [Изменение](../../../../openspec/changes/clarify-memory-decision-authority/proposal.md) обновляет все копируемые политики и [руководство](../../../PROJECT_MEMORY.md). Это улучшение инструкции, а не воспроизведённое исправление runtime или новый поведенческий успех.
2. **Сохранить строгую проверку:** проектор и scorer неизменны. Смешанному использованию нужен заранее зафиксированный собственный протокол; адаптация не меняет старую неудачную оценку.
3. **Явно учитывать предел retry проверки:** обычный CLI resume сохраняет исходную идентичность baseline и сообщает `baseline-unavailable`; возвращённый retry-план прерванную проверку не перезапустил. Это ограничение маршрута, которое нужно учитывать до использования, а не свидетельство сетевой ошибки или отказа прав. Новая возможность runtime здесь не добавляется.

## Границы и расходы

Исполнитель сообщил три свежих контекста/четыре рабочих хода, **456,8 секунды вызывающей стороны**, **894 822 `subagent_tokens`** и ноль платных API-вызовов через подписку. Модель контроллера указана как GLM-5.3; маршрутизация отдельных workers, разделение входных/выходных токенов и денежная стоимость неизвестны. Принудительного нативного timeout, экспорта tool-событий и OS sandbox нет. Свежесть и чтение остаются сообщениями исполнителя; файлы/JSON не доказывают полную последовательность нативных инструментов или человеческое согласие.

Root не запускал новых поведенческих модельных сессий или платных API-вызовов для этой оценки. Выпуск 1.5.5 неизменён. Автозагрузка, успех исправления/повторного использования, человеческая польза, показатели надёжности и поддержка всех харнессов не заявлены. Прежний неудачный пакет остаётся остановленным; следующему наблюдению нужны новые объявленные границы и идентичность кандидата.

Локальные проверки Unreleased записаны в [verification](../../../../openspec/changes/clarify-memory-decision-authority/verification.md); оценку возвращённой задачи они не меняют.
