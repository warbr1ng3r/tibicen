# Свежая проверка конфликтов и исправленной памяти

**Закрыто с пробелом в реализации.** Два предложения по конфликтам и исправление
памяти приняты. Свежий агент прочитал исправленное решение, но вместо реализации
задал уточняющий вопрос. Точные результаты — в [сводке](summary.json);
[предыдущее наблюдение](../2026-11-09-ordinary-1.5.3/README.md) сохраняет исходные
сбои и пробелы. Канонический отчёт — [на английском](README.md).

Проверялась локальная сборка **Unreleased**, прошедшая ревью: 110 файлов скиллов
с версией пакета 1.5.3. Опубликованные артефакты 1.5.3 не изменились.

## Исходные проекты и запросы

[Новый пример конфликта](../../cases/project-contract-conflict/README.md) —
очередь из шести файлов: README задаёт `done === false`, а реализация и тесты
поддерживают ноль, null, отсутствие поля и пустые значения. Независимый вариант
из семи файлов добавляет принятое строго булевое требование для будущей миграции.
Оба получили запрос:

> Подготовь этот проект к работе с агентом. Короткие инструкции, без новых инструментов. Сначала покажи предложение.

Stock содержит пакеты каталога и отчётов, корневые и вложенные инструкции,
существующую память. Оператор заново подготовил ровно 12 файлов из принятого
состояния stock-task **до** прежнего остановленного исправления, сохранив
`availableOnly` и семь тестов. Старые скиллы, state, manifest, стенограммы и
частичное исправление исключены. Это не подтверждает новую настройку Tibicen
или прохождение согласования.

Исправление:

> Поменяли решение для списка сборки: туда идут только товары с положительным остатком, от меньшего остатка к большему. При равенстве сохраняем исходный порядок. Обычный renderStock по-прежнему сохраняет порядок входных данных. Запомни это, код пока не трогай.

Использование в свежей сессии:

> Добавь renderPickList(items): формат как у обычного отчёта, но заголовок # pick. Допиши тесты.

## Действия и результаты

| Этап | Результат |
| --- | --- |
| Нерешённое расхождение | Принят: показаны различие на нулевом значении и нерешённая цель |
| Явное решение владельца | Принят: разделены строгая цель, текущее поведение и миграция |
| Исправление памяти | Принято: положительные остатки, возрастание и устойчивый порядок равных |
| Свежая задача | Частично/Hold: память прочитана, задан вопрос об области решения, код/тесты не изменены |

Оба предложения получены фактическим CLI; приложение сохранено, применение и
его тесты не запускались. Чтение скилла и этапов наблюдалось. Обычные сбои команд
обработаны внутри тех же вызовов, без повторного запуска. Вариант с решением
владельца раскрыл будущие несогласованные служебные записи и счётчик использования.

Исправлён только существующий файл памяти; закрытые права, порядок `renderStock`,
точные SKU и независимая запись о Node сохранены. В свежей сессии агент прочитал
память и успешно запустил семь исходных тестов, но уточнил связь исключения для
сборки с «форматом как у обычного отчёта» и общей документацией. Замороженная
проверка отклонила отсутствие экспорта (`REUSE:pick-export`, exit 1, 880,23 мс).
Безопасный вопрос не выполнил задачу реализации. Ответа оператора и пятого вызова
не было; возможная неоднозначность не доказывает дефект продукта или модели.

## Помощь, проверки и ограничения

Проверяющий добавил `$tibicen-init` и отдельные границы передачи, файлов и
выполнения. Исправление не называло путь памяти; свежая задача не получала
прежний запрос, ответ о сортировке или подсказку чтения. Подготовка файлов и
эти границы — помощь оператора.

Четыре контроля конфликта, исходные семь тестов, два корректных решения и восемь
отрицательных вариантов дали ожидаемые результаты. Завершены четыре нативные
сессии: три принятых наблюдения и один функциональный Hold; суммарное время CLI
294,547 с, вызывающего процесса 303,707 с. Из трёх контейнеров без модели два прошли
предварительные проверки; задача отклонена из-за отсутствующей функции при
сохранении 125 файлов и прав. Все семь контейнеров остановлены и удалены без сбоя
инструмента; рабочий корень удалён, homes пусты. Повторов и платного API не было.

Остаётся вопрос, когда сохранённое исключение для конкретной задачи нужно
применять сразу, а когда — уточнять относительно общей документации. Причинное
улучшение, автоматическая загрузка, совместимость с другими харнессами и польза
человеку этим наблюдением не установлены.
