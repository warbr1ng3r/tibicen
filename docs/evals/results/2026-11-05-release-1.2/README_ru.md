# Статус кандидата 1.2.0 — 5 ноября 2026 года

**Tibicen 1.2.0 — кандидат, а не опубликованный релиз. Текущей опубликованной
версией остаётся [1.1.0](https://github.com/warbr1ng3r/tibicen/releases/tag/v1.1.0).**
Офлайн-проверки и обычный CI прошли, но обязательное новое наблюдение изменённого
поведения объяснений не завершилось. Публикация остаётся заблокированной.

Кандидат добавляет в `practices` необязательный проверяемый ввод версий агентов
и уточняет, как init/adopt объясняют свидетельства, применимость и минимальное
полезное изменение либо сохранение настройки. Переданные версии остаются
контекстом вызывающего, а не доказательством установленной версии или
совместимости. Получение источника, датированное содержимое и смысловая
применимость остаются разными фактами.

После I01 область новых наблюдений остановлена. Повторной попытки, резервного

восстановления учётных данных не было. A01 остаётся неизрасходованным.
Новые наблюдения объяснений и цикл применения конкретного согласованного
предложения остаются незакрытыми техническими требованиями; успешные другие
проверки их не заменяют. Пройденные проверки публичной поставки не заменяют эти наблюдения.

## Сохранённая история исправлений

Первая попытка проверки поставки остановилась после обновления Codex: проверка
требовала побайтного равенства служебных данных lock-файла установщика.
Закреплённый ref и все 92 файла сохранились. Анализ закреплённого установщика
показал несовпадение форматов кэша: Git-tree-хэш из API и локальный SHA-256.
Это может вызвать повторную установку того же ref и изменение времени записи.
Объект до обновления был зафиксирован в предыдущей записи; исходные сырые байты
lock-файла до обновления отдельно не сохранялись. Фактический файл после
обновления и неудачная попытка сохранены.

Исправленная проверка допускает только подтверждённые изменения служебного
хэша/времени; точный ref, байты/права файлов и все остальные поля должны совпадать.
Она прошла независимое ревью и отрицательные офлайн-проверки отклонений.
Один новый механический прогон прошёл для трёх целей за 33,127 секунды; в нём все
три сырых lock-файла фактически сохранились побайтно. Для этого результата не
менялись файлы продукта или закреплённый установщик.

Отдельное исправление вспомогательного кода разработки передаёт первое событие
ошибки в существующий callback после остановки, с той же защитой `type`/`detailHash`,
что и парсер результата. Независимое ревью отклонило первоначальную передачу
сырого события до любого живого использования. Исправленный пример проверяет
отсутствие частного текста и в журнале callback, и в сохранённых результатах.
Это исправляет доставку события, а не причину I01; утраченную ошибку оно не
восстанавливает. После этого полный офлайн-прогон прошёл 804/804 без пропусков; каждый заново
собранный файл и манифест сохранили байты/права исходного кандидата.
Для следующих наблюдений нужны отдельный ограниченный протокол, новые привязки
исходников/наблюдателя, ревью и root GO. Готовится Desktop-пара с явно переданным
контекстом только для изменённых общих правил рассуждения; она не подтверждает
загрузку установленного компонента, личность CLI или изоляцию ОС.
