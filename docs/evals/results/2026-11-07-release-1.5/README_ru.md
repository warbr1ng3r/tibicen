# Отчёт о выпуске Tibicen 1.5.0

**Опубликован в `2026-11-06T22:43:22Z` (7 ноября 2026, Москва).**
[Релиз 1.5.0](https://github.com/warbr1ng3r/tibicen/releases/tag/v1.5.0), ID
`437135839`, прошёл CI исходников, все шесть платформенных ячеек, точную публичную
доставку по полному SHA и сверку полученных файлов. Кандидат-02 и три ограниченных
свежих наблюдения приняты. Отдельная выкладка метаданных Pages и сверка полученных
тел **ожидаются**.

## Охват и разрешение

1.5.0 — совместимый minor: необязательные явно выбранные источники инструкций,
сравнение источников запомненных фактов и переданные оценки влияния версий в
существующем отчёте без записи, а также уточнение подписей EN/RU-иллюстрации.
См. [руководство](../../../PROJECT_CONTEXT_REVIEW.md) и
[реализованное изменение](../../../../openspec/changes/explain-project-context-changes/tasks.md).
Схемы сохраняемых данных, точное согласование плана, границы записи и единственное
выбранное хранилище памяти прежние. Без новых необязательных входов отчёт сохраняет
прежнюю структуру. Миграции проекта и автоматического обновления нет.

7 ноября владелец ответил «Поехали» на конкретный план: подготовить 1.5.0,
проверить новые инструкции в свежих сессиях, проверить установку/обновление/
восстановление/удаление, затем сделать коммит, push, пройти публичный CI,
опубликовать релиз и обновить Pages. Разрешение действует в этом охвате при
успешных проверках; обычные шаги не требуют повторного согласования. Оно не
разрешает платные API-запросы, изменение авторизации или посторонних проектов.
Конечную работу ведёт пакет выпуска (`../../../../.scratch/release-1.5/map.md`; приватная запись разработки; не входит в публичную копию исходников),
фактический статус — дашборд (`../../../../.scratch/release-1.5/dashboard.md`; приватная запись разработки; не входит в публичную копию исходников).

## Свежие наблюдения инструкций

Заранее замороженный протокол допускает три последовательные свежие сессии,
не более 150 секунд каждая/450 секунд суммарно, без автоматических повторов или
замены модели. Запрошенный маршрут — Codex CLI 0.157.0 / `gpt-6-astra` через
имеющуюся подписку ChatGPT и собственный container/code-mode bridge. Бюджет
платного API — ноль. Сборка модели backend, число HTTP-запросов и восстановлений
авторизации не подтверждены; настройки повторов request/stream равны нулю.

| Кейс | Фактический результат |
| --- | --- |
| B1 — явно выбранные инструкции | Принят. Полный скилл/инструкция прочитаны; настоящий scan и отчёт с хэшем `RULES.md`; неизвестный `team-agent` и непроверенная нативная загрузка/использование сохранены. 58,394 секунды native / 62,191 всего. |
| B2 — источник запомненного факта | Принят. Основание взято из настоящего прежнего scan; изменение версии пакета даёт changed/review, но неизменное требование Node остаётся верным. Для отдельного правила о токенах история не выдумана. 65,547 секунды native / 67,761 всего. |
| B3 — объяснение влияния версий | Принят. Прочитал замороженные официальные ограничения type stripping Node 22.18.0 и локальное решение; сохранил прямой запуск Node ≥22.20 с erasable-аннотациями без нового runner/обновления. Переданный источник/смысловая оценка отделены от сравнения локальных байтов. 79,383 секунды native / 81,552 всего. |

Все три разрешённых host-слота использованы, дополнительной сессии или повтора
модели нет. B1/B2 сохранили по 59 файлов, B3 — 60. Права и все проверки
cleanup/source/config/code-mode сохранены. У B3 12 из 13 обычных команд завершились
с exit 0: отсутствующий `shasum` вернул 127, затем `sha256sum` прошёл в той же
сессии до настоящего отчёта. Это не безошибочный прогон всех команд.
Промпт явно требовал чтение полного скилла и ограничивал формы вызова настоящего
CLI. Проекты синтетические, история B2 намеренно сохранена при подготовке, B3
получает замороженный официальный источник вместо браузинга. Это наблюдения с
помощью в одном запрошенном маршруте, не обычная установка, неявная загрузка,
охват всех харнессов, показатель надёжности или исследование пользы человеку.

## Доставка, сохранённые ошибки и свидетельства

Локальная D01 заменила замороженную опубликованную 1.4.1 кандидатом-02 через
закреплённый universal-установщик, повторила установку, полностью восстановила
изменённые backup в настоящие пути установки и удалила восстановленные скиллы.
Оба установленных self-test 1.5.0 прошли. Сохранены точные payload-файлы,
приложение/поздняя память владельца, соседние скиллы, внешние настройки и исходные
входы. Доверенный установщик имел обычные права чтения; запись ограничена своим
каталогом. Сетевой hook не был OS firewall. D01 не повторяла lifecycle/тесты
приложения; локальная установка не подтверждает публичную по полному SHA.

- Gate кандидата-01 сохраняется: 1034 прошли, одна ошибка, один прежний пропуск.
  Удалена устаревшая проверка href footer maintenance, точная проверка байтов
  maintenance сохранена. Кандидат-02 прошёл; байты, права и хэш архива поставки
  совпали между кандидатами.
- До заморозки/запуска native ревью обнаружило, что grader принимал поддельный JSON
  с похожими на CLI комментариями. Ограничение прямых команд/входов и привязка
  настоящего основания B2 исправили это. Независимые контроли прошли шесть
  положительных и 24 отрицательных случаев; исходные замечания сохранены.
- Подготовка P01 без модели упала из-за отсутствующего импорта `readdir` до
  заморозки протокола; исправление сохранило частичный runtime/прежний scan.
  Нативный слот не потрачен.
- В B3 событие 20 сохраняет отсутствующий `shasum`/exit 127; событие 27 успешно
  пересчитало хэш переданного источника через `sha256sum` до отчёта в событии 29.
  Замороженный runner отличает допустимый ненулевой результат обычной команды от
  ошибок транспорта native/tool/RPC. Общее слово «tool failure» в плане можно
  прочитать шире; неоднозначность раскрыта, а не молча исправлена. Неизменный
  grader, независимое ревью и root приняли этот конкретный ограниченный результат.
  Дополнительной попытки модели или смены правил оценки не было.
