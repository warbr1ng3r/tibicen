# Полезные задачи в свежих контекстах Codex

28 октября 2026 года два новых субагента Codex с `fork_turns=none` выполнили задачи на отдельных копиях проектов, настроенных при [приёмке приложения ZCode](../2026-10-27-zcode-app/README.md). Они не получили прежний диалог или вставленный текст AGENTS.md. Каждому предложено найти локальные инструкции; до правок он сообщил файл/хэш, затем реализовал задачу.

| Копия проекта | Задача | Хэш инструкции | Наблюдаемые проверки |
|---|---|---|---|
| CLI задач | Добавить `list --open`, сохранив обычные list/add/done и просмотр без записи | `5eba86c6…` | Baseline агента 6/6; итог 9/9; независимая приёмка и suite root на Node 24 — 9/9 |
| API заметок | Добавить поиск без учёта регистра `GET /notes?q=term`, сохранив маршруты и строгую проверку query | `4f8d4868…` | Baseline агента 6/6; итог 9/9; независимая приёмка и suite root на Node 24 — 9/9 |

Оба хэша совпадают с точными AGENTS.md, установленными прежним прогоном ZCode. Каждый агент изменил только один исходный файл и один файл целевых тестов. AGENTS.md, паспорта, package-файлы и README сохранены. Все 15 файлов исходных завершённых проектов сохраняют байты и права; прежний apply и история не повторялись и не сбрасывались.

## Независимая приёмка

До передачи агентам проверки хоста завершились ожидаемыми ошибками отсутствующих возможностей: неподдержанный `--open` и HTTP 400 при поиске заметок. После реализации независимые проверки настоящих CLI/HTTP прошли:

- CLI: оба порядка флагов, только незавершённые задачи, прежние list/add/done, отказ дублирующим/неизвестным флагам и флагу вне list, отсутствие записи/замены при просмотре, пустые и отсутствующие данные.
- API: поиск подстроки без учёта регистра и закодированные строки, порядок создания, отсутствующий/пустой/не найденный запрос, HTTP 200 успешных чтений, отказ неизвестным/дублирующим query и query в записи без изменения состояния, прежние create/list/delete.

Read-only review дизайна нашло отсутствие проверки HTTP-статуса в нескольких успешных ветках host-проверки API. Проверки усилены до первого успешного прогона; исходные скрипт/freeze/красные логи и явная поправка сохранены. Первоначальный контракт задачи не менялся; агенты не читали host-проверки.

Root выполнил оба suite проектов и обе независимые проверки с Node **24.15.0**: **18/18 тестов проектов**, обе приёмочные программы прошли. Собственные тесты CLI-агента выполнялись на Node **25.8.0**, что он указал как ограничение; они отделены от результатов root на Node 24. API-агент не записал свою версию Node; она остаётся неизвестной. Root не исправлял реализацию. Независимое review реализации: **Ship**, замечаний, требующих исправления, нет.

## Свидетельства и ограничения

[Машиночитаемый результат](results.json) содержит полные хэши инструкций, изменённые пути, различия runtime и результаты проверок. Исходные свидетельства чтения инструкций, frozen checks, поправки, красные/зелёные логи, patch и итоговые снимки хранятся у сопровождающего в локальном архиве свидетельств.

Подтверждены явное чтение проектных инструкций и выполненные полезные задачи в двух свежих контекстах Codex с инструкциями из настройки ZCode. Это не подтверждает автоматическое нативное обнаружение, новую задачу в самом ZCode, причинную пользу относительно ненастроенного проекта, измеренную экономию времени/денег или человеческий пилот. Найти инструкции просили явно; отдельного измерения автоматической загрузки не было.

Упражнения выполнены на сгенерированных проектах в отдельной видимой папке. Исходные README намеренно сохранены как baseline. Продуктовые исходники Tibicen, поставляемые скиллы, прежние паспорта/checks и релизные файлы не менялись. Само упражнение не запускало полный suite продукта из 668 случаев и не создавало коммитов/публикаций. Последующие review репозитория, проверки и коммиты документации учитываются отдельно.
