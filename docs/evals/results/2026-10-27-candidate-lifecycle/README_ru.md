Для noop использован прямо описанный в `stage-proposal.md` read-only путь: при отсутствии изменений и новых запусков `apply` не вызывался. Сохранение нового свидетельства в паспорт не подменялось отсутствием записи. В ручном MCP случае сохранённый report остаётся `manual-action-required`: структурная проверка временного config отдельно не объявлена завершённой сессией или MCP health-check.

В init точная команда проверки — абсолютный Node + `--test app.test.js`, только собственный tiny fixture с одним тестом. CLI сохранил две завершённые command attempts для baseline/final; дополнительно этот же owned тест исполнен host до/после. Произвольные команды существующего внешнего проекта не запускались.

Всего сохранено **50 квитанций: 48 вызовов CLI кандидата и 2 прямых owned Node test**. Каждый вызов содержит argv, cwd, безопасный явный env, stdin JSON, stdout/stderr и exit code. Точный план передавался через stdin, approval соответствовал полученному digest. Это полномочие детерминированного тестового host над своими fixtures; оно не выдаётся за согласие владельца внешнего проекта.

Машиночитаемая сводка: result.json (локальная запись сопровождающего; не входит в публичный снимок). Полные локальные evidence: private result (maintainer-local), индекс команд (maintainer-local), контекст (maintainer-local). В этой private области также находятся receipts, исходные/итоговые hash/mode/mtime snapshots, финальные fixtures и копия owned HOME. Временная установленная копия сохранена; её путь указан в context.json.

Ограничения: init проверен на свежем существующем Node-проекте без инфраструктуры, не на пустой папке. Incomplete создан известным дефектом missing-file; внезапный kill, неоднозначный результат команды и его повтор здесь не проверялись. Manual шаг в сохранённом report остаётся pending. Источники и актуальные практики по сети, Git-доставка/update/remove, миграция поддержанной схемы, OpenSpec/другие компоненты, загрузка инструкций, task/quiz/compat в новой агентской сессии и человеческая оценка — вне этого L1 наблюдения. Sources и compat pairs пусты; поведенческий pass не заявляется.

У host были две неверные исходные проверки exit code: `incomplete` apply и status ожидались с 0, CLI корректно вернул structured `incomplete` с 1. Первичные outputs сохранены; commands не повторялись, продолжение использовало сохранённый результат. Top-level `report.reason: null` при этом сопровождается конкретным `checks.infrastructure.issues: missing-file`; отдельным дефектом это не объявлено.
