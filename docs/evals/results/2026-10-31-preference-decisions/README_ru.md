# Выбор настройки на приватном preview — 31 октября 2026 года

Шесть свежих контекстов Codex app оценили три read-only пары обычного Codex/Tibicen. Оба метода сохранили достаточные инструкции и не добавляли лишние компоненты. Случай конфликта ревью выявил пропущенное уточнение: ни один метод не задал обязательный вопрос, а Tibicen предложил совместить отдельное ревью владельца с согласием на план. Позднее исправление инструкции привело к вопросу в одном свежем контексте; наблюдение записано ниже. Полная PREF-06/человечески откалиброванная приёмка и результаты пилота открыты. [Канонический отчёт](README.md).

## Условия

Полный inventory67fixtures совпал с lock до проекции канонических PREF-04/05/06. Ожидаемые ответы, результаты другого метода и подготовленное уточнение были скрыты. Внутри пары методы последовательно получали тот же неизменённый проект/запрос; разные пары выполнялись параллельно. Обычный Codex был первым в PREF-04/06; Tibicen — в PREF-05.

Tibicen использовал точный86-файловый приватный preview1.0.0-rc.1 из [релизного отчёта](../2026-10-31-private-rc-preview/README.md), SHA256 инвентаря: 1a4739fa032146b2bf7f8369a1e95fed726dc7b9430cc42ce7fc8e37aaa4390f. Только этот метод получил установленный скилл, references и разрешение на один read-only scan. Это явный вызов в приложении с неизвестными actual model/build, а не сертификация native CLI или автоматического обнаружения.

Запись в проект, применение/установки, проектные команды, сеть, личные config/auth и Git-операции не входили в scope. Единственная разрешённая запись — файл ответа вне проекта. Ограничения процедурные, не изоляция ОС. Лимиты — шесть контекстов/восемь ходов,180секунд на ход/восемь минут на случай, без повторов. Использованы только шесть начальных ходов. После этого исходного пакета автономный расход исполнителей составлял23/24; позднейшее исправление ниже доводит его до24/24. Нового judge-контекста не было.

Подготовленный ответ «сохраняем отдельное ревью; после него выполняй согласованный план самостоятельно» не отправлялся ни одному методу: ни один не запросил нужное уточнение. Отсутствующая стадия коррекции не является успешным наблюдением разрешения конфликта. По [действующим критериям PREF-06](../../PREFERENCE_SELECTION.md#pref-06--a-material-workflow-conflict-needs-clarification) неопределённость обязательного этапа ревью нужно уточнить до изменения процедуры. Root выявил пробел по сохранённым ответам; это его наблюдения, не слепые независимые quality-оценки.

Все шесть точных файлов ответов исполнителей скопированы с exclusive-create до следующего dispatch. Проверки до/после сохранили17уникальных файлов проектов, их права/состав и все87файлов поставки вместе с inventory. Исполнители сообщили только о чтении и трёх разрешённых scan Tibicen. Полная трасса инструментов/активности не собиралась; эти сообщения не подтверждают независимо загрузку или исполнение команд. Проектные проверки и apply не разрешались.

Время файлов ответов укладывается в лимиты ходов; более поздний интервал захвата root включает оркестрацию и не равен времени агента. Параллельные случаи, неизвестные model/build и отсутствие независимых timing/usage не позволяют сравнивать скорость, стоимость или пользу.

## Исправленное уточнение обязательного этапа

Общая инструкция интервью теперь явно считает сомнение в обязательном этапе проекта существенным уточнением, если вопросы разрешены. До ответа действует прежний этап; изменение, отмена или совмещение ожидают решения. Лимиты интервью и отдельная ветка безопасного gap при запрете вопросов сохранены. Это реализация существующей спецификации, не новый критерий выпуска.

От прежнего рабочего payload отличаются только две поставляемые копии stage-interview.md. Новый SHA256 инвентаря: 79002226def0ff0b1695cfc8fa854003c03ba7a655c2e29cfdae5c4f507cbd40.
