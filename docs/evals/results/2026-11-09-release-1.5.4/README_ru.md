## От созданной политики к рабочей задаче

Искусственный складской проект из двенадцати файлов использует работающее приложение с семью тестами, восстановленные прежние инструкции и сохранённые решения. Одна специально устаревшая строка README обещает сортировку по SKU; код, тесты и принятое решение сохраняют входной порядок. Именованное исключение в памяти задаёт для нового `renderAssemblySheet(items)` положительные остатки, возрастание остатка и стабильный порядок при равенстве. Такая подготовка раскрыта; оператор не подставлял новую управляемую политику памяти.

Обычные запросы: «Приведи инструкции для агентов в этом проекте в порядок. Сохрани код, тесты и принятые решения. Покажи изменения до применения» и в свежей сессии: «Добавь renderAssemblySheet(items): строки sku:stock, заголовок # assembly. Допиши тесты».

Агент написал политику и сформировал план настоящим CLI Tibicen, отделил устаревший README от принятых требований и сохранил этот пробел в документации. Оператор проверил точный digest и применил неизменённый план в изоляции, включая создаваемые служебные записи. Свежий агент получил фактические файлы и права без первой переписки, ответа о сортировке и подсказки читать память. Он реализовал именованное исключение, сохранив прежнее поведение `renderStock`, точные SKU и входные данные. Две обычные ошибки команд при предложении исправлены внутри того же вызова; внешнего повторного запуска не было.

До нативной работы прошли проверки границ и функциональные контроли: семь исходных тестов, два корректных варианта и девять отрицательных случаев. Точное применение заняло 2,03 секунды, проверка свежей задачи — 1,07 секунды. Все шесть контейнеров остановлены и удалены.

Это одна созданная кандидатом политика и полезная задача с явным вызовом скилла, ограничениями записи и согласованием/применением оператором. Она не доказывает нативное применение агентом, автоматическую загрузку, исправление памяти, причинное улучшение, поддержку других харнессов или пользу человеку. Прежние [наблюдения с подготовленной оператором политикой](../2026-11-09-memory-scope/README.md) и неудачи не меняются. [Примечания к выпуску](release-notes.md) сохраняют границы версии.
