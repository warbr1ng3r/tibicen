# Форматы MCP и свидетельства

Любой допустимый ID среды может использовать `mcp-diagnose`, явно выбрав известный
формат или общий маршрут наблюдений. Каталог, модели и провайдеры не ограничивают
этот выбор. Это поведение входит в опубликованную 1.4.0.
В [сценарии](ADOPT_DIAGNOSIS.md#local-mcp-diagnosis-for-init-and-adopt--unreleased)
описаны ввод команды, пределы исследования и следующий шаг.

## Общий маршрут

Для неподдержанного языка, собственного экспорта или неизвестного диалекта
выберите `format: "stdio-observation"`. Каждый источник передаёт
`observation: {sourceHash, state, envNames}`: SHA-256 исследованного текста в UTF-8 строчными hex-символами,
`state` со значением `stdio`, `disabled` или `unknown` и имена необходимых переменных
окружения. Все три поля обязательны; для состояния, отличного от stdio,
`envNames` пуст. Команды, аргументы, значения и содержимое настроек не передаются.
Источники по-прежнему ограничены разрешёнными файлами проекта; маршрут не читает
личные настройки и не интерпретирует Python, теги YAML или фрагменты оболочки.

Совпавший хэш связывает переданные сведения с этим текстом. Источник сообщает
`reported-stdio`; его явный выбор как `effectiveSource` даёт
`configuration.basis: "caller-observation"`. Изменившийся или недоступный источник
оставляет наблюдение непроверенным. Это не проверка
корректности парсером и не доказательство безопасности, нативной загрузки,
соединения или использования. Явные факты о целевом запуске могут выявить
недостающие предпосылки; исправление остаётся ручным/нативным. Без более конкретной
проблемы целевого запуска причина — `observed-configuration-not-parsed`.
Механизм записи не добавляется.

## Необязательное чтение нативных форматов

Явный формат работает с любым допустимым ID в `agent`, не переименовывая его.
Прежние запросы без `format` сохраняют значения по умолчанию только для
Claude Code, Cursor и Gemini CLI. Для остальных readers нужен явный выбор.
Один запрос использует один формат; порядок источников не задаёт приоритет,
записи не объединяются.

| Формат | Ограниченный ввод и существенный предел |
| --- | --- |
| `claude-code-json` | JSON `mcpServers`; контракт строковой команды и ссылок env Claude |
| `cursor-json` | JSON `mcpServers`; ссылки `${env:NAME}` Cursor отличаются от `${NAME}` Claude |
| `gemini-cli-json` | JSON `mcpServers`; URL-транспорт имеет приоритет, внешнее включение неизвестно |
| `opencode-v2` | JSON `mcp.servers`, массив команды, `environment`, `{env:NAME}`, `disabled`; явный V2, без JSONC/файловой подстановки |
| `zcode-native-json` | JSON `mcp.servers`; command, args, env, `enable: false` |
| `zcode-shared-json` | JSON `mcpServers`; та же ограниченная запись ZCode без заимствования подстановок других сред |
| `kimi-code-json` | Текущий JSON `mcpServers`; локальный stdio, cwd, `enabled: false`; нелокальный `environment_id` остаётся ручным шагом |
| `mistral-vibe-toml` | TOML `[[mcp_servers]]`; именованная запись stdio, command, args, env, cwd, `disabled: true` |

Новые readers ZCode/Kimi/Vibe оставляют непустые буквальные env-поля ручным
ограничением, не обрабатывая значения и не заимствуя подстановку другой среды.
Неподдержанные поля и неоднозначные структуры сохраняют ограничения.
Самодостаточное подмножество TOML для Vibe принимает однострочные basic/literal
strings, булевы значения, ограниченные числа, массивы, inline tables и bare dotted
headers/array tables. Повторы определений, quoted headers, dotted assignments,
многострочные строки, даты и неподдержанный синтаксис оставляют источник ручным
шагом; неверные посторонние области не пропускаются, команды оболочки не разбираются.

`formatEvidence` равен `caller-supplied`, `harness-default` или `unverified`.
Результат парсера использует `configuration.basis: "parsed-format"`; нативная
активация, соединение и использование остаются непроверенными. Для поддержанного
исправления по-прежнему нужны прежние совпавшие хост Claude Code/Cursor, формат
и явно выбранный точный проектный путь записи. Другая среда, выбравшая их формат,
не получает автоматический механизм записи.

## Источники проверены 6 ноября 2026 года

Эти изменяемые документы не устанавливают минимальную выпущенную версию или живую
нативную совместимость. Локальные файлы не доказывают действующие нативные слои
или целевой контекст.

- **ZCode:** проектные `.zcode/config.json` и `.agents/mcp.json`; личный нативный
  конфиг — `~/.zcode/cli/config.json`. Наличие нативных серверов подавляет весь
  общий fallback той же области; личные одноимённые настройки приоритетнее
  проектных. Отключение использует `enable: false`. Подстановка env здесь
  не документирована. [Контракт MCP](https://zcode.z.ai/en/docs/mcp-services).
- **Kimi Code:** текущая `.kimi-code/mcp.json`, отличная от прежней `.kimi`;
  одноимённые проектные записи заменяют личные. Нужно доверие проекту;
  `environment_id` по умолчанию локальный независимо от цели сессии.
  [Контракт MCP](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/mcp).
  [Закреплённый исходник stdio](https://github.com/MoonshotAI/kimi-code/blob/df90d90ec0714db23dcc830acd2db6232f5c7426/packages/agent-core-v2/src/mcpCore/client-stdio.ts)
  использует env как буквальное наложение.
- **Mistral Vibe:** проектная `.vibe/config.toml` требует доверия папке;
  слои агента, сессии и администратора могут заменить локальные настройки.
  [Конфигурация](https://docs.mistral.ai/vibe/code/cli/configuration),
  [поля MCP](https://docs.mistral.ai/vibe/code/cli/configuration-reference),
  [административные настройки](https://docs.mistral.ai/vibe/code/cli/admin-config).
  [Закреплённый исходник](https://github.com/mistralai/mistral-vibe/blob/c96a6dbb34d34f8a868b3f67b279ecabbf1aa616/vibe/core/config/models.py)
  включает cwd/массивы команды; `disabled` скрывает инструменты, но обнаружение
  может продолжаться.

Прежние readers сохраняют [датированные контракты](ADOPT_DIAGNOSIS.md#host-contracts-checked-on-6-november-2026).

## Модели и отдельные приложения

Одна смена модели/провайдера в том же приложении не требует нового адаптера формата
и не доказывает поведение модели. Некоторые поставщики также выпускают harness:

- **DeepSeek Harness** использует Cordis YAML overlays для MCP, включая
  исполняемые выражения `!!js`. Этот нативный синтаксис вне парсеров. Разрешённое
  исследование источника может дать безопасные наблюдения; Tibicen никогда
  не исполняет YAML. [Официальный пример](https://deepseek-harness.github.io/deepseek-harness/en/guide/mcp-memory).
- **GigaChat:** пример Сбера настраивает MCP в Python с LangGraph и MCP SDK;
  он не устанавливает универсальный формат файла настроек GigaChat. Используйте
  поддержанный контракт фактического приложения или связанные с источником
  наблюдения, не запуская Python при исследовании.
  [Пример Сбера](https://developers.sber.ru/docs/ru/gigachain/tutorials/agent-gigachat-mcp).

Неизвестный синтаксис оставляет конкретный пробел свидетельств; он не требует
замены harness, модели, провайдера или рабочей конфигурации пользователя.
