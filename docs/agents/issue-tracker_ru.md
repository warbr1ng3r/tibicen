## Wayfinding operations

- Карта усилия: `.scratch/<effort>/map.md`; метка `wayfinder:map`.
- Дочерний тикет: `.scratch/<effort>/issues/NN-<slug>.md`. Его путь — идентификатор. В тексте ссылки называются заголовком тикета.
- Поля: `Type: grilling|prototype|research|task`, `Labels: wayfinder:<type>`, `Status: open|claimed|resolved`, `Assignee: none|<session>`, `Blocked by: none|NN, NN`. Для карты допустима только метка `wayfinder:map`, для тикетов — только `wayfinder:<type>`.
- Перед работой установить `Status: claimed` и `Assignee`. Разрешённые пути и проверки берутся из контракта тикета и связанных OpenSpec-задач.
- Зависимость выполнена только если соответствующий тикет имеет `Status: resolved`. Frontier — открытые, не назначенные, не заблокированные тикеты; порядок по номеру. Разные пакеты запускаются последовательно, внутри пакета — только задачи с готовыми входами и непересекающимися разрешёнными путями.
- При завершении добавить результат и свидетельства в `## Answer`, установить `Status: resolved`, снять назначение и добавить одну ссылку с кратким итогом в `Decisions so far` карты. Человеческое решение требует ответа владельца.
- Детали существенного изменения и чекбоксы реализации живут в OpenSpec. Тикет хранит вопрос/результат, границы ответственности и ссылку на точную группу задач. Roadmap хранит порядок этапов.
- Дашборд `dashboard.md` — представление тикетов, обновляется после изменения статуса/зависимостей. Визуальное представление в чате — снимок, не второй трекер.

Для технической работы до релиза читайте [инженерную оценку](../evals/ENGINEERING_ACCEPTANCE.md) о недостающих наблюдениях и привязках к исходникам/версиям/кандидату, а также [реестр готовности](../evals/V1_READINESS.md) об оставшихся технических критериях и сопровождении. Карта (`../../.scratch/codex-zcode-acceptance/map.md`; приватная запись разработки; не входит в публичную копию исходников) хранит решения, дашборд (`../../.scratch/codex-zcode-acceptance/dashboard.md`; приватная запись разработки; не входит в публичную копию исходников) — актуальные работы. Подробные задачи поведения остаются в OpenSpec; порядок этапов — в [roadmap](../DEVELOPMENT_PLAN.md).

По политике от 03.11.2026 техническая приёмка требует независимого инженерного ревью и положительных наблюдений загрузки/использования SKILL/PROC для применимых версий и кандидата. Человеческие наблюдения полезности и калибровка рубрики — добровольная работа после публикации; измеренная польза остаётся неизвестной. Продолжайте сбор недостающих технических свидетельств и работу по сопровождению без назначения опроса владельца.

Владелец поручил автономную работу без пауз на обычные одобрения. Продолжайте готовые задачи в отдельных собственных scope, интегрируйте результаты и проводите независимое ревью. Root может одобрять конкретные предложения для синтетических тестовых проектов; человеческая оценка или результат пилота из такого одобрения не выводятся. Детали исполнения и конечные лимиты задаёт назначенный тикет. Платный API, изменение личной авторизации, коммиты и публикация требуют отдельного явного разрешения; старые разрешения конкретных этапов не дают его сейчас.

Его именованные конечные области управляют новыми техническими наблюдениями; текущие результаты, неудачи и учёт попыток — в дашборде. Исторический лимит24/24закрыт.
