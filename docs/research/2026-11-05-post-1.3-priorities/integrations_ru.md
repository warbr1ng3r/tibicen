# Локальные интеграции после Tibicen 1.3

Новое исследование публичных первоисточников, **5 ноября 2026 года**. Этот раздел
посвящён запуску локальных MCP, областям конфигурации и загрузке скиллов. Текущие
материалы сопоставлены с выпущенными [каталогом агентов](../../HARNESS_CAPABILITIES.md),
[переносимым процессом](../../HARNESS_PORTABILITY.md) и
[реализацией MCP](../../../scripts/mcp/index.ts). Старый план не используется как
доказательство спроса.

## Решение

Наиболее обоснованный ограниченный фронт интеграций — **находить действующую
локальную конфигурацию MCP и исправлять установленное несоответствие**. Начать
стоит с привязанной к версиям поддержки Gemini CLI и OpenCode, выбранных по
свидетельствам ниже; для остальных агентов сохраняется универсальное явное
чтение файлов. Полезный результат называет действующий источник, объясняет сбой
и предлагает одно проверяемое изменение. Это продуктовый вывод из исправлений
конфигурации, сообщений о контексте запуска и штатных решений, а не измеренный
рейтинг рыночного спроса. [I1](https://github.com/anomalyco/opencode/issues/36434),
[I2](https://github.com/mcp-router/mcp-router/issues/189),
[D1](https://dev.opencode.ai/v2/docs/mcp-servers/),
[D2](https://geminicli.com/docs/tools/mcp-server/)

Универсальный doctor, ещё один список агентов и автоматическое копирование во
все клиенты отличались бы слабее. У Cline уже есть управление MCP, у Amp —
просмотр и перезагрузка скиллов, у ZCode — скиллы настройки и диагностики.
[D3](https://github.com/cline/cline/blob/main/docs/mcp/mcp-overview.mdx),
[D4](https://ampcode.com/docs/customize/skills),
[B5](https://zcode.z.ai/en/docs/skill)

## Штатные решения и широкий обзор

| Агент | Текущее свидетельство первоисточника | Следствие для следующей функции |
| --- | --- | --- |
| OpenCode V2 | Для локального stdio используются `mcp.servers`, `environment`, `{env:NAME}` и `disabled`. Проектное переопределение целиком заменяет одноимённый объект. `opencode mcp list` проверяет соединения. [D1](https://dev.opencode.ai/v2/docs/mcp-servers/) | Привязать преобразование к V2; избегать неполных переопределений и копирования полей V1. |
| Gemini CLI | Неопределённая переменная превращается в пустую строку; описана фильтрация унаследованной среды. `gemini mcp list` и `/mcp list` показывают состояние и ошибки; проверка stdio зависит от доверия к папке. [D2](https://geminicli.com/docs/tools/mcp-server/) | Использовать штатные сведения о соединении; отдельно учитывать доверие и среду запуска. |
| Cline | У CLI свой путь MCP и переменная его переопределения; IDE открывает действующий файл через интерфейс. Штатные средства уже показывают, правят и перезапускают серверы. [D3](https://github.com/cline/cline/blob/main/docs/mcp/mcp-overview.mdx) | Не приравнивать состояние расширения, Desktop и CLI. Новый мастер даёт мало. |
| Исправление Cline CLI | Changelog 3.0.69 сообщает, что Windows-серверы `npx`/`uvx` незаметно выпадали из-за трёхсекундного запуска; лимит увеличили до десяти секунд. [F1](https://github.com/cline/cline/blob/main/apps/cli/CHANGELOG.md) | До изменения корректной конфигурации учитывать дефект версии клиента. |
| Amp | `amp skills list --json` показывает скиллы; текущей сессии нужна собственная перезагрузка. Глобальный одноимённый скилл имеет приоритет над проектным. | Copilot CLI | Источники MCP сессии, плагинов, проекта и пользователя имеют разные приоритеты; проект требует доверия. `copilot mcp list/get` показывает источники, перенос из VS Code меняет корневой ключ. [B1](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference) | До миграции определить конкретную поверхность Copilot и источник записи. |
| Goose | Официальные исходники документации различают среду оболочки и launcher и описывают обёртки runner, способные скачивать среду исполнения. [B2](https://github.com/aaif-goose/goose/blob/main/documentation/docs/mcp/developer-mcp.md), [B3](https://github.com/aaif-goose/goose/blob/main/documentation/docs/troubleshooting/known-issues.md) | Наличия команды в оболочке недостаточно; сохранять корпоративные/offline-ограничения и использовать штатные инструкции. |
| Continue IDE | Документация размещает проектные MCP в `.continue/mcpServers` и допускает их использование только в Agent mode. [B4](https://docs.continue.dev/customize/deep-dives/mcp) | Корректная запись в другом режиме — несоответствие области, а не обязательно дефект сервера. |
| ZCode | Настройки показывают источник, включение, обновление и ошибки формата; встроенные скиллы разбирают настройку и сбои соединений. [B5](https://zcode.z.ai/en/docs/skill) | Сначала использовать эти средства. Точный путь проектных скиллов эта страница не устанавливает. |

## Разрыв относительно выпущенной 1.3

[Каталог](../../HARNESS_CAPABILITIES.md) уже содержит 13 профилей и отделяет
описание от разрешённых записей, адаптеров и наблюдавшейся загрузки. Неизвестный
агент может явно прочитать полные скиллы. Добавление Amp или Goose в каталог
поможет навигации, но само не подключит сервер и не докажет загрузку скилла.

Текущий [модуль MCP](../../../scripts/mcp/index.ts) изменяет локальные JSON-записи
Claude Code и Cursor и готовит ручной TOML-фрагмент Codex. Он проверяет ссылки,
получая от вызывающей стороны доступные **имена** переменных и
`targetContextKnown`. Структурный успех остаётся `configured-unverified`; модуль
не ищет исполняемые файлы, не разбирает области других агентов и не наблюдает
MCP-handshake. При секретах в файле и неоднозначном формате требуется ручное
действие. Новая функция должна добавить проверку действующей области и целевой
среды, а не переименовать существующие проверки в подтверждённую работу.

## Предлагаемый ограниченный пакет

Это рекомендация для будущего изменения OpenSpec, а не уже утверждённый или
выполненный план реализации.

1. Для выбранных агента, версии и сервера объяснять действующий локальный
   источник, совпадение имён, переопределение/отключение, cwd и синтаксис ссылок
   на переменные. Неизвестные версии и форматы оставлять пробелами. Читать
   чувствительную конфигурацию с фильтрацией секретов; сообщать
   только имена и наличие переменных.
2. Разделять корректность файла, доступность команды/cwd в известной целевой
   среде, штатное соединение/обнаружение инструментов и реальное применение.
   Проверка оболочки не подтверждает GUI. Штатная команда, запускающая серверы,
   сохраняет существующую границу разрешения исполнения и доверия.
3. Предлагать минимальную правку разрешённой записи, сохраняя остальные поля и
   решения владельца. Неизвестная среда запуска требует точного оставшегося
   штатного шага, а не угаданного абсолютного пути или экспорта секрета.
4. Начинать со штатной диагностики и повторять ту же проверку после одобренного
   исправления. Отдельно хранить обнаружение скилла, выбранный источник/содержимое
   и явную активацию. Список скиллов не доказывает соблюдение инструкций моделью.

Начать с фикстур Gemini CLI и OpenCode V2: неверный синтаксис переменных,
отсутствующие имена, переопределённые/отключённые записи, различия cwd/путей и
корректная конфигурация без изменений. Будущее разрешённое нативное наблюдение
должно показать переход от сбоя к соединению без посторонних правок; одни
offline-фикстуры этого не доказывают. Расширять поддержку стоит по реальным
пользовательским случаям и актуальным контрактам первоисточников.

Tibicen может исправлять одобренные несоответствия локальной конфигурации. Он
может распознавать и направлять дальше дефекты клиентов, корпоративные политики
и неизвестную среду GUI. Развёртывание hosted MCP, удалённый OAuth, сбои
поставщиков и плохой выбор инструментов моделью не становятся задачами ремонта
локального stdio. [D1](https://dev.opencode.ai/v2/docs/mcp-servers/),
[D2](https://geminicli.com/docs/tools/mcp-server/),
[B1](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference)
