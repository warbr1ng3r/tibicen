synthetic project copies for competent direct Codex and Codex explicitly using
Tibicen. Initial setup and improvement were to be observed separately. Each arm
could have a proposal, an approved native application continuation and a fresh
useful task, followed by repeats of both adopt arms. The ceiling was **14
sequential host sessions / 1,500 seconds of native deadlines**, with no retries
or fallback; a justified no-change result would omit its unnecessary application
slot. The fixed order was init
direct, init Tibicen, adopt Tibicen, adopt direct, then direct adopt repeat and
Tibicen adopt repeat. This order is not a randomized performance estimate.

## Conditions recorded before execution

These were the selected protocol rules. They are retained as a historical record,
not instructions to resume either closed packet.

1. Freeze fixtures, simple user requests, task oracles, order, source/runtime
   hashes, phase rules and deadlines before any new session. Keep reference
   answers and grading schemas out of model inputs. Existing applicable project
   instructions receive the same explicit reading rule in both approaches.
2. Root reviews the actual proposal and visible explanation without improving
   their content. Direct approval binds exact proposed bytes/diff; Tibicen
   approval binds its unchanged actual proposal and digest. Record any extraction
   into an artifact as operator assistance. An essential unanswered question or
   an ambiguous plan is an incomplete observation, not permission to invent
   preferences, repair the proposal or add a launch.
3. For each approved continuation, freeze the exact accepted inputs and allowed
   new/removed paths before its one-use GO. Require protected existing bytes and
   modes, actual approved changes, finalized transient state where applicable,
   and container removal. A no-change result needs no gratuitous manifest or
   application. The fresh task receives accepted project bytes only, not the
   earlier transcript, treatment runtime, reference implementation or oracle.
4. Validate task/preservation checks with positive and meaningful negative
   controls before observation. Preserve raw outcomes and events before grading.
   Review actual native/tool evidence independently of the model's success claim.
   Do not change criteria after seeing an outcome to manufacture a pass.
5. A launch, transport, containment, collection, preservation or acceptance
   failure stops remaining phases. Keep a well-formed ordinary nonzero shell
   result and any same-session recovery distinct from an RPC, denied-sandbox,
   malformed-event or session failure. No caller rerun is permitted.

These conditions implement the repository's [engineering/research separation](../../PILOT.md):
there are no recruited participants or measured human benefits. An exact fixture
approval by root is an operator action, not a participant preference or a human
usefulness assessment.

## Collection boundary checked in source

The maintained [contained runner](../../../scripts/evals/contained-codex.ts)
requires a matching prospective freeze for subscription execution, one host
session and explicit result paths. Its [container session](../../../scripts/evals/container/session.ts)
copies the whole stopped workspace archive; the [archive decoder](../../../scripts/evals/container/archive.ts)
rejects unexpected files/directories rather than silently hiding them. Deriving
the next phase's exact allowlist from an approved proposal is therefore valid.
The decoder permits an allowed file to be absent: the packet must separately
check required files and distinguish intentional removal, optional state and
missing applied output. Required byte/mode preservation cannot be inferred from
the allowlist alone.

The same archive encoder stages input regular files with mode `0644`. A later
phase therefore normalizes a prior returned `0600` instruction or manifest to
`0644`. Check modes against each phase's actual staged baseline, record original
apply modes and this normalization, and do not claim mode preservation across
phase boundaries. Files outside the collected workspace, such as a per-user
usage counter inside the disposable container, are not observed project output.

The runner separately accepts well-formed command completion records, including
nonzero exits. The session bridge's ordinary-process classification excludes
sandbox denial and malformed process records. This supports the prospective
failure distinction above; it does not prove that all nonzero commands are
harmless or that a completed session satisfies product acceptance.
