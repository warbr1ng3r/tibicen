# Первый запуск: независимое ревью методики

Это прежний разбор исходников/подготовки. Отдельно запрошенное новое наблюдение описано в [текущем отчёте](README.md).

**7 ноября 2026 года, Europe/Moscow. Закрыто до первого наблюдения модели.**
Новый обоснованный вопрос: сможет ли агент провести своё настоящее предложение
через точное одобрение, применение, проверку и понятный итоговый ответ. Повтор
сравнения, в котором изменения применял оператор без модели, этого не выяснит.
Это ограниченная техническая проверка, а не человеческий пилот и не общий замер
скорости.
Новое сравнение на этот вопрос не ответило: две ошибки подготовки остановили
собственный исследовательский маршрут до сессии модели. Это проблемы обвязки
исследования, а не успех или сбой Tibicen. Прежние опубликованные свидетельства
работы продукта не меняются.

## Выбранный протокол — исторический, закрыт

План сравнения предусматривал опубликованную версию 1.5.0 и одинаковые копии
синтетических проектов для обычного компетентного Codex и Codex с явно указанным
Tibicen. Первичную настройку и улучшение существующей предполагалось наблюдать
отдельно. Для каждого варианта были предусмотрены предложение, новый запуск
агента с одобрением точных изменений и полезная задача в свежей сессии, затем
повторная проверка обоих вариантов adopt. Предел составлял **14 последовательных
сессий / 1500 секунд суммарных лимитов модели**, без повторных попыток и запасного
маршрута. После обоснованного «ничего менять не нужно» лишний запуск применения
следовало пропустить. Порядок был фиксирован: init обычным
Codex, init с Tibicen, adopt с Tibicen, adopt обычным Codex, затем повтор adopt
обычным Codex и с Tibicen. Это не рандомизированная оценка скорости.
Объём записан в карте работ (`../../../.scratch/first-run-value-20261107/map.md`; приватная запись разработки; не входит в публичную копию исходников);
конкретный пакет и каждое продолжение требовали предварительного ревью. Оба пакета
теперь закрыты; неиспользованные лимиты не разрешают дальнейшие запуски. Таблица
ниже сохраняет запланированные границы выводов, а не настоящие результаты.

| Наблюдение | Допустимый вывод | Ограничение |
| --- | --- | --- |
| Настоящее предложение, одобрение и применение/проверка/отчёт самим агентом | Наблюдаемый агент провёл именно эти изменения через проверяемый процесс с помощью оператора | Свежая сессия с подготовленными входными данными не доказывает сохранение контекста в обычном непрерывном чате |
| Независимая проверка принятых файлов проекта и полезной задачи | Настройка сохранила указанное содержимое, следующая задача выполнена | Успешная задача сама по себе не доказывает, что результат обеспечили инструкции |
| Повтор без изменений в обоих вариантах adopt | Оба способа сохранили либо не сохранили эти достаточные настройки | Повтор init, длительное использование и другие среды не наблюдались |
| Тексты вопросов, одобрения, ручное извлечение данных, работа с метаданными, команды и длительность этапов | Видны конкретные действия и затруднения в этих запусках | Число действий не равно активным минутам человека, удовлетворённости или экономии труда |

Явное чтение полного скилла из подготовленной папки — допустимая помощь выбранного
маршрута. Оно и прежние проверки доставки не доказывают автоматическое обнаружение
скилла в этом исследовании. Установка не входит в новые интервалы времени, если
её действительно не наблюдали и не записали отдельно.
[Предыдущее сравнение](../../evals/results/2026-11-06-repair-comparison/README.md)
уже дало одинаковый результат исправления и полезной задачи на одном примере с
помощью оператора. Это свидетельство следует сохранить, а не заменять количество
внутренних тестов утверждением о пользе.

## Условия, записанные до запуска

Ниже сохранены исторические правила выбранного протокола. Они не предписывают
возобновлять какой-либо из закрытых пакетов.

1. Зафиксировать проекты, простые запросы, независимые критерии задач, порядок,
   хэши исходников и поставки, правила этапов и лимиты до первой новой сессии.
   Эталонные ответы и схемы проверки не передаются модели. Для обоих способов
   действует одинаковое явное требование прочитать применимые инструкции проекта.
2. Root проверяет настоящее предложение и объяснение, не улучшая их содержание.
   Для обычного Codex одобрение связано с точными предлагаемыми байтами/диффом;
   для Tibicen — с неизменённым настоящим proposal и его digest. Любое извлечение
   данных в отдельный файл учитывается как помощь оператора. Существенный вопрос
   без ответа или неоднозначный план — незавершённое наблюдение, а не разрешение
   придумать предпочтения, исправить предложение или добавить запуск.
3. Перед одноразовым разрешением продолжения зафиксировать точные входные файлы
   и разрешённые добавления/удаления из одобренного плана. Проверить защищённые
   байты и права существующих файлов, применение точных изменений, завершение
   временного состояния при необходимости и удаление контейнера. При достаточной
   настройке не нужны новый manifest и лишнее применение. Свежая полезная задача
   получает только принятые файлы проекта, без прошлого диалога, скилла Tibicen,
   эталонной реализации и независимых критериев проверки.
4. До наблюдения проверить оценщик задач и сохранности положительными и
   содержательными отрицательными примерами. Сохранить исходные результаты и
   события до оценки. Независимо проверить настоящие действия агента, а не его
   заявление об успехе. Не менять критерии после результата ради успешной оценки.
5. Ошибка запуска, транспорта, изоляции, сбора результатов, сохранности или
   приёмки останавливает оставшиеся этапы. Корректно оформленный ненулевой код
   команды и исправление в той же сессии учитываются отдельно от RPC-ошибки,
   запрета песочницы, некорректного события или сбоя сессии. Повторять запуск нельзя.

Эти условия следуют [разделению технических и человеческих исследований](../../PILOT.md):
участники не набраны, польза для человека не измерена. Одобрение точного изменения
root — действие оператора, а не предпочтение участника или человеческая оценка
полезности.

## Граница сбора результатов проверена по коду

Существующий [изолированный исполнитель](../../../scripts/evals/contained-codex.ts)
требует совпадения заранее зафиксированных условий для запуска по подписке,
ограничивается одной сессией и явным списком возвращаемых файлов.
[Контейнерная сессия](../../../scripts/evals/container/session.ts) копирует архив
всей остановленной рабочей папки, а [декодер](../../../scripts/evals/container/archive.ts)
отклоняет неожиданные файлы и папки, а не скрывает их. Поэтому точный разрешённый
список следующего этапа можно получить из одобренного предложения. Декодер
допускает отсутствие файла из списка: пакет должен отдельно проверять обязательные
файлы и различать запланированное удаление, необязательное временное состояние и
отсутствующий результат применения. Список сам по себе не доказывает сохранность
байтов и прав.

Этот же код подготовки архива задаёт входным обычным файлам права `0644`.
Следующий этап поэтому меняет прежние возвращённые `0600` у инструкций или
manifest на `0644`. Права проверяются относительно настоящего входного состояния
каждого этапа; исходные права после применения и такое преобразование фиксируются
отдельно. Сохранность прав между этапами заявлять нельзя. Файлы вне собираемой
рабочей папки, например пользовательский счётчик внутри одноразового контейнера,
не наблюдаются как результаты проекта.

Исполнитель отдельно принимает корректные результаты команд, включая ненулевой
код завершения. Проверка обычного завершения процесса в контейнерном мосте не
включает запрет песочницы и некорректные сообщения процесса. Это позволяет заранее
разделить виды ошибок; отсюда не следует, что любой ненулевой результат безвреден
или что завершённая сессия автоматически прошла приёмку продукта.

## Настоящий результат и закрытие

Выбранный объём соразмерен пробелу в проверке применения и итогового ответа.
Подготовленный пакет прошёл независимое ревью исходников: совпали **20 хэшей кода
исполнителя, 132 материала и 110 файлов поставки**. Первичные проверки сохранности
без контейнера дали два положительных и десять отрицательных примеров. До фиксации
пакета исправлены ошибка копирования отрицательных примеров и пробел в записи STOP
при нарушении предварительных условий. SHA256 пакета:
`5dc30e4807dcbeb3de76e81a02ddc31e991535ec2fb3201f7a78cb6383523066`.
Отдельный одноразовый исполнитель изолированной оценки задач также прошёл ревью
исходников. Пути квитанций ниже относятся к закрытым локальным записям, которые
не публикуются. Проверка до запуска:
`.evals-private/first-run-value-20261107/reviews/method-prelaunch-v2.json`;
проверка помощника оценки:
`.evals-private/first-run-value-20261107/reviews/method-isolated-helper-v1.json`.

Затем root запустил один изолированный контейнер с контрольными задачами.
Независимая проверка приняла обе эталонные реализации и все шесть отрицательных
примеров. Восстановлены все 13 файлов и их входные права; остановка и удаление
подтверждены, ошибок инструментов нет. Длительность — 3006,38 мс, без модели и
авторизации. Закрытая проверка контролей и первого протокола
(`.evals-private/first-run-value-20261107/reviews/method-controls-and-first-protocol.json`)
связывает эти настоящие результаты с первым подготовленным этапом модели.

Затем первый вызов завершился ошибкой: подготовка не создала родительскую папку
для одноразового окружения. Исходные STOP, отметка запуска, GO и пустой файл
событий сохранены; пакет закрыт. Порядок действий в зафиксированном коде подтверждает:
ошибка произошла до создания контейнера сессии модели, чтения авторизации и запуска
модели. Служебные проверки метаданных уже выполнялись. Это один неудачный вызов до
модели, а не результат работы продукта и не отсутствие любого исполнения.
Происхождение ошибки и сохранность исходников зафиксированы в
аудите сбоя
(`.evals-private/first-run-value-20261107/reviews/method-pre-model-failure-and-correction.json`).

В пределах делегированной владельцем работы root заранее разрешил отдельный
исправленный пакет: создать только недостающую собственную родительскую папку,
сохранить проекты и критерии, прежний сбой и проверить новые хэши/GO. Полный парный
план допускал 14 новых сессий модели / 1500 секунд. Общие исторические пределы —
15 попыток вызова и 1650 секунд выделенных лимитов вызовов с учётом неудачной попытки до
модели, а также шесть контейнеров без модели с учётом прежней проверки. После
нового сбоя третий исправленный пакет не предусматривался. Проверка только файловой
системы подтверждает ошибку без родителя, закрытую пустую папку, создание свежего
окружения и отказ при заранее созданном окружении сессии. Это явное изменение
протокола, а не сохранение прежнего общего утверждения «без повторных попыток».

Затем новая контрольная попытка исправленного пакета завершилась ошибкой при
проверке входных данных без запуска контейнера. Из-за более длинного префикса
рабочей папки для
`adopt/project/.agents/skills/project-workflow/SKILL.md` понадобился **159-байтный
родительский путь в архиве**, а существующий ограниченный кодировщик ustar
допускает **155 байт**. В исходной записи нет исполнения, результата контейнера
и событий готовности. По исходникам проверка предшествует созданию Docker.
Вызов того же чистого валидатора без контейнера воспроизвёл отказ; тот же пример
проходит проверку с гипотетическим коротким собственным путём в `/tmp`. Эта
попытка не создала контейнер, не читала авторизацию и не запускала модель.

| Итоговый наблюдаемый счётчик | Количество |
| --- | --- |
| Попытки вызова модели | 1, ошибка до запуска модели |
| Вызовы модели в исправленном пакете | 0 |
| Сессии модели / чтения авторизации подписки / контейнеры сессии модели | 0 / 0 / 0 |
| Контрольные попытки без модели / действительно созданные контейнеры | 2 / 1 |

Оба пакета закрыты с сохранёнными STOP; третий исправленный пакет и новые живые
попытки не разрешены. Итоговая независимая проверка
(`.evals-private/first-run-value-20261107/reviews/method-final-closure.json`)
связывает счётчики и неизменённые свидетельства. Их принятие не означает приёмку
init, adopt, применения, полезной задачи или повторной настройки: они не
наблюдались. Предварительные ревью пропустили подготовку родительской папки и
ограничение составного пути архива. Проверка без контейнера выявила ошибку
подготовки и не меняет оценку сохранённых неудачных попыток.

Следующий ограниченный шаг — до будущей фиксации проверить все входные файлы
контролей, поставки и проектов существующим чистым валидатором и подтвердить
пустую закрытую родительскую папку, выбрав короткий собственный рабочий путь.
Эти сбои не обосновывают расширение формата архива, изменения продукта или новый
лимит живых запусков. Этот рецензент выполнял только проверки исходников/байтов
и чистый валидатор входных данных: без модели, авторизации, контейнера и кода
приложения из примера. Код продукта, результаты прежних закрытых исследований
и история Git не менялись.
