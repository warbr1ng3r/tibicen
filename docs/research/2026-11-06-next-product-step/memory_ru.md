# Память и контекст: сначала сделать понятным текущий источник

Проверено **6 ноября 2026, Europe/Moscow**. Только исследование для принятия решения. Канонический текст — memory.md; этот файл является переводом. Десять первичных источников ниже включают жалобы и достаточные встроенные альтернативы. Они не устанавливают распространённость проблемы или пользу Tibicen.

## Решение

**Сохранить существующую модель одного файла памяти. Эта ветка не обосновывает подключение backend или немедленную правку кода.** Наиболее убедительный небольшой кандидат — краткая связь инструкций и памяти для конкретной задачи в существующем отчёте/handoff. Менее приоритетный кандидат — видимость изменений источника явно связанных фактов проекта. Оба сначала можно отклонить ограниченной кабинетной проверкой без набора участников и запусков моделей.

Нужно различать: сохранено, применимо здесь, прочитано этой сессией, ещё верно и действительно соблюдено. Дополнительное хранилище не делает эти состояния равнозначными.

## Что уже покрывает 1.4.1

[Текущий обзор](../../CURRENT_CAPABILITIES.md), [контракт памяти](../../PROJECT_MEMORY.md) и [диагностика контекста задачи](../../ADOPT_DIAGNOSIS.md#task-context-for-init-and-adopt) уже предусматривают один необязательный файл проекта, правила принятых решений/исправлений, сохранность других заметок, структурные ссылки инструкций, контекст хоста/CWD/целевого пути и явное чтение при передаче работы. Дальше заметки ведут рабочие агенты; фонового процесса Tibicen нет. Поддержаны четыре точных расположения памяти; другие пути сохраняют ограничение/ручную связь.

Нельзя предлагать это как отсутствующие функции. [Нативные наблюдения](../../evals/results/2026-11-06-native-memory-recovery/README.md) показывают чтение, использование и исправление с помощью агента на одном примере, сохраняя первоначальный отказ оценки и отдельную оценку после наблюдения. Они не выделяют причинное влияние памяти и не подтверждают поведение всех хостов. [Сравнение исправления](../../evals/results/2026-11-06-repair-comparison/README.md) показало одинаковый итог задач, а не экономию усилий человека.

## Что действительно добавляют жалобы

Два сообщения о worktree выражают разные цели. Один автор предпочитает общие знания репозитория, другой — изоляцию по ветке. Оба сообщения закрыты по разным основаниям. Ни одно не разрешает выбрать общий режим памяти для всех. ([M1](https://github.com/anthropics/claude-code/issues/34975), [M2](https://github.com/anthropics/claude-code/issues/39920))

Автор сообщения об устаревании нашёл старое описание репозитория, но прямо указал, что автоматическая память была отключена и риск не реализовался. Это не наблюдаемая частота последующих ошибок. Один возраст файла не опровергает давнее решение владельца; это наш вывод, а не измеренный результат. ([M3](https://github.com/anthropics/claude-code/issues/85075))

Пользователь Codex сообщает о потере рабочих ограничений в длинных сессиях, хотя правила сохранены в репозитории. Это основание разделять хранение и использование, а не утверждать, что ещё один файл или сервер памяти исправит harness. Инцидент не воспроизводился. ([M4](https://github.com/openai/codex/issues/51672))

Обсуждение монорепозитория с Visual Studio/VS Code/OpenCode спрашивает, какой файл главный и где применяются вложенные инструкции. Ответы противоречат друг другу; это полезная постановка проблемы, а не надёжная матрица совместимости. Источник общий с веткой первого использования, а не отдельное независимое подтверждение. ([M5](https://www.reddit.com/r/GithubCopilot/comments/1wre0j7/agentsmd_vs_githubcopilotinstructionsmd_when/))

## Достаточные встроенные способы и обычные файлы

Claude сейчас документирует общую автоматическую память репозитория, просмотр через `/memory` и контекст вместо принудительного исполнения. Файла проекта и встроенных средств может быть достаточно. Git поддерживает отдельные рабочие деревья веток: версионируемые заметки могут сохранять намеренные различия без сервиса синхронизации. Ни один факт не доказывает фактическое использование инструкций. ([M6](https://code.claude.com/docs/en/memory), [M10](https://git-scm.com/docs/git-worktree))

Текущая матрица GitHub различает Visual Studio Chat, VS Code и CLI. Документация OpenCode V2 описывает поиск только AGENTS, в отличие от прежнего предположения о fallback. Gemini показывает загруженный контекст через `/memory show`. Проверять нужно выбранную среду/версию, а не обобщать название агента. Это заявленные контракты, а не локально проверенные установки. ([M7](https://docs.github.com/en/copilot/reference/custom-instructions-support), [M8](https://dev.opencode.ai/v2/docs/instructions/), [M9](https://geminicli.com/docs/cli/gemini-md/))

Текстовая просьба прочитать файл не везде является импортом. Tibicen уже допускает явное чтение; не нужно добавлять нативные копии или переписывать личную память ради одинакового вида всех хостов.

## Кандидат 1: небольшая карта контекста в существующем ответе

**Обычный запрос:** «Перенёс задачу в другой агент/worktree. Какие решения ему читать?»

**Видимый итог:** одна короткая цепочка для задачи, например `инструкции проекта → подходящие локальные правила → docs/decisions.md`, с переданными рабочим/целевым путями, условием чтения и неизвестной нативной областью. При необходимости: «файлы связаны; чтение сессией не подтверждено». Недостающая или неоднозначная связь показывается на своём месте. Новый файл отчёта — только по запросу.

**Оставшийся пробел:** нынешний отчёт перечисляет кандидатов и отношения путей; пользователь ещё сам связывает их с выбранной памятью и первым шагом чтения. Это уже описанное [расширение карты контекста](../../PRODUCT_VISION_ADDENDUM.md#5-connected-context-map), а не новый движок контекста. Карта полезна, только если меняет конкретное следующее действие.

**Минимальный объём / сопровождение:** небольшой или средний: представление уже собранных фактов в ответе/отчёте с сохранением неизвестного о неподдержанном хосте и загрузке. Без нового скана, чтения глобальной памяти, backend, наблюдателя и обязательного вопроса. Утверждения о конкретном хосте всё равно требуют сопровождения источников/версий. Основные риски — придуманный приоритет, раскрытие запрещённого содержимого и шум в достаточном handoff.

**Альтернатива без изменений:** нынешний отчёт контекста задачи, один явный запрос чтения либо встроенный просмотр контекста.

**Ограниченное опровержение:** один раз изучить шесть собственных сохранённых конфигураций: достаточный общий файл, отсутствующая ссылка, законное вложенное исключение, неизвестный хост, два неоднозначных хранилища и заметки конкретной ветки. Сравнить текущий вывод с краткой картой, написанной вручную. Отказаться от реализации, если нужное действие уже понятно или карте приходится угадывать активные инструкции. Это детерминированная проверка охвата/представления, а не доказательство экономии времени. Новая модель не нужна.

## Кандидат 2: показывать изменения источника, а не автоматически удалять старую память

**Обычный запрос:** «Настройка изменилась. Какие сохранённые факты проекта перепроверить?»

**Видимый итог:** только при явно известной связи заметки с источником показать «исходный источник изменился; перепроверьте факт», путь источника и ограниченное основание. Принятое правило согласования зависимостей остаётся принятым до замены. Не объявлять память неверной по старой дате и не перезаписывать заметки молча.

**Оставшийся пробел:** существующие правила уже требуют сохранять причины/источники и исправлять опровергнутые факты; общей механической проверки соответствия факта его источнику нет. Это не повторное предложение «добавить provenance». Смысл свободного текста оценивает агент.

**Минимальный объём / сопровождение:** средний, обоснован слабее первого кандидата. Использовать намеренно переданную локальную связь с источником; не извлекать привязки из произвольного текста, не вводить обязательную схему записей и второе хранилище. Переезды путей, несвязанные правки источника и необязательные метаданные создают стоимость сопровождения и ложные тревоги. Сохранить владение памятью и границы согласия.

**Альтернатива без изменений:** при обычном adopt прочитать актуальные файлы, существующую ссылку заметки и Git diff; неизвестные связи оставить неизвестными.

**Ограниченное опровержение:** вручную проверить шесть доверенных заметок по сохранённым снимкам источников: изменённый существенный факт, несвязанная правка, переименование, отсутствие источника, старое действующее правило и неподдержанный/закрытый источник. Отказаться от функции, если нынешняя проверка даёт то же действие, безвредная правка объявляется недействующим решением либо сопровождение привязок стоит дороже проверки заметки. Для первого отсева не нужны программный прототип и живой агент.

## Исключения и вывод

Ни один изученный случай не устанавливает необходимость в векторном поиске, импорте переписок, синхронизации проектов или постоянном сервисе. Поэтому интеграции mem0/Letta не выбраны; их SDK здесь не оценивались. SDD или каталог контекста не становятся решением лишь потому, что сохраняют больше артефактов. Дефекты сжатия/исполнения остаются задачей upstream; Tibicen не гарантирует соблюдение правил после настройки.

Существующая полезная память остаётся доступной. Необязательная карта контекста — первый кандидат, видимость изменений источника — второй, а отсутствие правок предпочтительнее обоих при достаточном текущем/встроенном объяснении. Это варианты решения, а не очередь реализации или исследований. [Прежняя стратегия](../2026-11-06-product-strategy/README.md) и [исследование контекста](../2026-11-05-post-1.3-priorities/context-and-memory.md) остаются датированным контекстом; новых требований к релизу нет.
