# Landing review: make the result understandable

**Observed:** 2026-11-04. **Status:** recommendations only; no landing implementation, release or version changes. Canonical report: this file; an adjacent Russian translation is maintained.

**Recommendation:** keep the existing visual direction and concentrate on explanation. The largest gap is that a visitor sees files and setup terminology before seeing a believable user request, the agent's response and the resulting project. A complete visual rebuild is unnecessary.

## What was checked

- The published [English landing](https://warbr1ng3r.github.io/tibicen/) and [Russian landing](https://warbr1ng3r.github.io/tibicen/ru/) in a browser, including the installation anchor, language routes, agent selector and optional preset disclosure.
- Desktop at 1280 × 720; English and Russian mobile views at 390 × 844; a narrow Russian layout observation at 320 × 800. These are browser viewports, not physical-device testing.
- The local [landing component](../../../landing/src/components/Landing.astro), [installation component](../../../landing/src/components/Installation.astro), [installation command generator](../../../landing/src/scripts/install.ts), [preset form](../../../landing/src/components/PresetForm.astro), [styles](../../../landing/src/styles/global.css) and [client handlers](../../../landing/src/scripts/app.ts), alongside [product scope](../../PRODUCT_VISION.md) and the [published release](https://github.com/warbr1ng3r/tibicen/releases/tag/v1.0.0).
- Six current official product sites below. Text was inspected for all six; OpenCode, OpenSpec and Tessl were also viewed in a rendered desktop browser. This is a purposive comparison of presentation patterns, not an exhaustive competitor or conversion study.

No installation commands were executed, presets submitted, project evaluations started, or product files modified. The temporary browser tab was closed and the viewport override reset. The web text extractor could not retrieve Tibicen; the browser displayed both published language routes successfully. That extractor failure is not a site failure.

## Main findings

1. **The design is already coherent.** The dark palette, green accent, clear headline, restrained navigation and visible primary button work together. There is no reason to replace Astro or introduce a design framework for this work.
2. **The product category is unclear too long.** The hero describes project setup but does not immediately explain that Tibicen is two skills used inside an existing agent, or make improving an existing setup as visible as initial setup. Those facts appear later.
3. **The example is too abstract.** A tree containing `AGENTS.md`, skills and MCP explains possible ingredients. The separate before/after example removes an unnamed obsolete instruction. Neither shows the actual conversation or enough starting project context for a newcomer to judge the result.
4. **The installation area mixes two audiences.** The exact command is useful. Around it are release-engineering terms, repeated prerequisites and four supporting links; the FAQ repeats much of the same compatibility explanation. Accuracy should remain, but the main path needs simpler language.
5. **The page is not broadly full of useless sections.** The problem is information allocation: prominent abstract material and repeated technical explanation, while a concrete demonstration and a clear first-session recovery instruction are missing. Expected comprehension improvements are hypotheses; no conversion or human-benefit measurements were made.

### A proposed simpler page order

1. Clear promise: prepare or repair the project for the existing coding agent; primary install action and secondary example action.
2. A concrete demonstration with a visible starting state and result.
3. Installation and the first prompt, with a short compatibility warning and recovery link.
4. A compact explanation of approval, preservation and verification; merge overlapping workflow/example prose where possible.
5. Practical FAQ: supported installation targets and limits, costs/account, data, updates/removal.
6. Optional preference builder and essential documentation/release/security links.

This is a proposed information hierarchy, not a request for an additional marketing page, account funnel or new product workflow.

## Example content brief

The demonstration should show the starting project first: for example, a small Node application with `src/`, tests and an existing `AGENTS.md` containing a stale test command plus a useful decision to avoid new dependencies. Then use a simple request such as **“The agent keeps using the wrong test command. Sort out the project instructions.”**

The following frames should show what the agent read, whether it needed a question, the small proposed correction and what remains unchanged. Only after visible approval should the sequence show an applied result and the actual checks. If there is no question, say the project already supplied the necessary information; do not invent a questionnaire. Show a separate first-setup example for a project without agent instructions.

A reconstruction must be labeled **illustrative**. A recorded run must name its version, environment, assisted/manual steps and unavailable checks; link to a scrubbed public artifact. Do not invent a success transcript, a universal “works in the next session” result, time savings or customer endorsement. Memory policy must not be advertised as an existing 1.0 feature while it is only proposed for a later release.

## Agent names, limits and privacy

**Keep agent names where they help installation.** The current selector has Codex, Claude Code and Cursor, matching the published mechanical-installation scope. A logo wall or a headline enumerating agents is unnecessary. Do not add ZCode, Gemini or other targets simply because another product lists them. Explain that additional environments are not yet established by these checks. The detailed history of bounded Codex and copied-skill ZCode exercises belongs in evidence, rather than first-use marketing copy. [Current release scope](https://github.com/warbr1ng3r/tibicen/releases/tag/v1.0.0).

**Keep boundaries close to the decision they affect.** Experimental native loading and unavailable Windows command execution matter before use. Project application checks use the current supported profile; installation success does not establish execution support. The static preset generator handles answers locally in the inspected code, while work inside the coding agent remains subject to that provider's data handling and external component research. Avoid a blanket “everything stays on your machine” or “free AI” promise. [Current FAQ source](../../../landing/src/components/Landing.astro), [preset handler](../../../landing/src/scripts/app.ts).

## Mobile and accessibility observations

At 390 px, the English document was approximately 6037 px tall and did not overflow horizontally; the Russian 320 px observation also had `scrollWidth = innerWidth = 320`. Language links were visible, and selecting Claude Code produced `--agent claude-code`. The preset disclosure opened. These observations confirm those interactions only; clipboard permission, downloaded preset contents, every manager/target combination and physical assistive technology were not exhaustively retested here.

The inspected markup includes a skip link, localized `lang`, hierarchical headings, form labels, status announcements and a reduced-motion branch. Language targets measured about 34 × 44 px at desktop size. Small text is a readability concern, not by itself a WCAG failure. A subsequent change should verify [200% text resizing](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html), [320 CSS-pixel reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) and [target size/spacing](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), with real keyboard and screen-reader checks where available. No contrast, performance or WCAG conformance score was measured in this review.

## Keep, and avoid adding

Keep English as the default with the adjacent Russian route, one main action, exact release pinning, explicit approval, preservation of application/user decisions, optional presets, honest unverified outcomes, update/removal guidance and existing license acknowledgements.

Do not add invented testimonials, adoption counters, productivity percentages, a supported-agent logo wall, enterprise pricing, login, a backend, analytics, a large animation library or a new frontend framework for this recommendation. No experiment here establishes that those additions would help. A human/user study can later evaluate comprehension or usefulness; this research does not substitute for measured benefit.

**Suggested first batch:** L1–L6 together, reviewed in EN/RU and on mobile. L7–L10 can follow if approved. The landing has not been changed by this review.
