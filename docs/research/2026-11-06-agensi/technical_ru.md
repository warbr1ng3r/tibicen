# Agensi: доставка и упаковка Tibicen

Дата: 6 ноября 2026 года. [Канонический английский отчёт](technical.md). Область исследования: публичная документация и чтение опубликованного дистрибутива 1.4.1. Подключение аккаунта, загрузка на площадку, установка, запуск модели и проверка работы через маркетплейс не выполнялись.

## Вывод

ZIP с неизменённым Tibicen может подходить по формату загрузки и одновременно не соответствовать способу исполнения. Tibicen — локальный инструмент Node из нескольких файлов, которым управляют поэтапные инструкции скилла. Agensi передаёт текст через MCP и предписывает временно запускать отдельные скрипты. Простая смена формата архива эту разницу не устраняет.

Обещать полноценную работу Tibicen до разрешения этого противоречия нельзя. Сначала следует запросить классификацию существующего продукта или исключение для бесплатного open-source-размещения/карточки со ссылкой. Автономный диагностический навык технически подходит, но это другой, более узкий продукт; создавать его стоит ради самостоятельной пользы. Бесплатный помощник, загружающий независимый GitHub-релиз, может сохранить полноценный продукт с меньшим дублированием, если площадка явно допускает такой вариант и установка отдельно согласуется пользователем. Здесь ни один вариант не реализован и не принят площадкой.

В каждом скилле четыре скрипта больше 20 000 байт: `core/apply.ts` — 31 564; `discovery/index.ts` — 20 090; `mcp/diagnosis.ts` — 26 417; `verify/index.ts` — 31 971. Это касается рекомендации Agensi для проверки, а не доказанного отказа модерации.

Сборка намеренно копирует полный runtime и справочники в каждый скилл, исключая сборщик и систему оценивания; отдельно создаёт минимальный пакет и контрольные суммы ([сборка](../../../scripts/build.ts) (строка 51)). Загружать только исходные `skills/tibicen-init/` или `skills/tibicen-adopt/` нельзя: там входные инструкции, а не полный дистрибутив. Также не следует загружать весь репозиторий разработки, зависимости, тестовые данные оценивания и инструменты OpenSpec для разработки.

## Локальный контракт выполнения

Ссылки ниже относятся к совпадающим локальным исходникам; соответствующие файлы сверены с архивом.

- Оба входа определяют `SKILL_DIR` как каталог установленного `SKILL.md`; пути к скриптам и справочникам считаются от него ([init](../../../skills/tibicen-init/SKILL.md) (строка 10), [adopt](../../../skills/tibicen-adopt/SKILL.md) (строка 10)). Внутри обоих есть оба маршрута, поэтому при смене маршрута другой вход устанавливать не нужно.
- `scripts/tibicen.ts` сразу импортирует соседние модули ([CLI](../../../scripts/tibicen.ts) (строка 5)); другие команды динамически импортируют дополнительные. Если сохранить только этот файл в произвольный временный каталог, зависимости не найдутся.
- Runtime читает версию из `../../package.json` относительно `contracts.ts` ([контракт](../../../scripts/core/contracts.ts) (строка 9)). Самопроверка читает настоящее дерево `references/stage-*.md` ([self-test](../../../scripts/tibicen.ts) (строка 414)). Текст в контексте модели не заменяет файлы в файловой системе.
- Установленному 1.4.1 нужен Node ≥22.20; текущая среда разработки требует более высокую версию. Архивный маршрут не требует Git, менеджера пакетов, checkout и зависимостей разработки. Хост должен читать проект и запускать Node, либо оператор должен возвращать реальные результаты ([требования](https://github.com/warbr1ng3r/tibicen/blob/319845f1f1597817807c81579b42250a1f189e7d/docs/INSTALLATION.md) (строка 15)).
- Применение — не только инструкции агенту: точные данные предложения, digest, сохранность файлов, восстановление и проверки обеспечивает CLI. Самодельная запись агентом после отказа apply меняет контракт продукта ([этап build](../../../references/stage-build.md) (строка 5)).
- Права `0644` не мешают `node scripts/tibicen.ts`; исполняемые бинарники не нужны. Расширение временного файла и способ вызова Node со стороны Agensi всё равно требуют проверки. Отдельного дерева `assets/` нет; справочники и метаданные пакета необходимы.

[Спецификация Agent Skills](https://agentskills.io/specification) описывает каталог и относительные ссылки. Она не гарантирует, что MCP-маркетплейс сохраняет локальный каталог и разрешает импорты Node.

## Что написано у площадки

Это заявления Agensi в документации на дату исследования, а не наблюдения за работой сервиса.

| Интерфейс | Задокументированное ограничение |
| --- | --- |
| ZIP через сайт | 50 МБ, 1000 файлов, до 50 скиллов |
| Загрузка агентом автора | 100 текстовых файлов, 5 МБ |
| Текст для покупателя | Все `SKILL.md`, до 200 других текстовых файлов, 6 млн символов |
| Скрипты | Отдельный временный запуск без доступа к другим файлам пакета |
| Рекомендация проверки | Логика скрипта до 20 КБ, встроенные данные не считаются |

[Правила упаковки](https://www.agensi.io/docs/packaging).

`get_skill` отдаёт инструкции/индекс, `file` получает отдельный файл, `path` выбирает скилл внутри pack. Агенту запрещают сохранять скилл в проект/каталоги скиллов; скрипты запускаются временно без изменения байтов. Бинарники не передаются. [Доставка](https://www.agensi.io/docs/how-agents-load-skills).

Skill pack — одна карточка с несколькими скиллами. Коммерческий bundle объединяет существующие платные карточки и не создаёт общий runtime. [Форматы продуктов](https://www.agensi.io/docs/what-you-can-sell), [правила bundle](https://www.agensi.io/docs/bundles).

Для инструментов удалённого сервера требуется OAuth; на аккаунт допускается один подключённый агент. Сам MCP не даёт доступа к проекту или локального shell — это обеспечивает хост. Если чат получил только справочники, он может советовать, но не выполнить локальные scan/apply. [MCP](https://www.agensi.io/docs/mcp-server), [требования Tibicen к хосту](https://github.com/warbr1ng3r/tibicen/blob/319845f1f1597817807c81579b42250a1f189e7d/docs/INSTALLATION.md) (строка 20).

Созданные конфиги/отчёты разрешены как результат; хранение самого скилла, его скриптов и шаблонов — отдельный случай. Open-source-размещение допускается при соблюдении лицензии. FAQ также говорит, что загрузить скилл через площадку можно только после публикации; загрузки автором собственной live-карточки бесплатны и не считаются использованием. [FAQ автора](https://www.agensi.io/docs/creator-faq).

### Граница bootstrap: независимый дистрибутив и экспорт скилла

Нужно различать три случая:

1. Воссоздание полученного через marketplace дерева модулей Tibicen в проекте или установленном скилле противоречит запрету сохранения. Платная обёртка не может молча назвать свой исходный код результатом работы.
2. Небольшое руководство может ссылаться на независимую официальную документацию; формат предусматривает `docs_url`. Ссылка сама по себе не доказывает допуск автоматической установки.
3. Launcher мог бы скачать независимый MIT-релиз с GitHub, не копируя ответы площадки. Это технически другой источник и отдельно полученная лицензия. Однако Agensi исключает продукты, требующие установки; публичные документы не классифицируют такой launcher однозначно. Разрешение open-source-карточек не устраняет эту неопределённость. [Упаковка](https://www.agensi.io/docs/packaging), [поддержанные продукты](https://www.agensi.io/docs/what-you-can-sell), [Terms §5.2](https://www.agensi.io/terms).

Публичные карточки показывают необходимость уточнения: [start mcp gateway](https://www.agensi.io/skills/start-mcp-gateway) обещает клонировать публичный репозиторий и запускать Docker; [Project Setup](https://www.agensi.io/skills/project-setup-app-idea-to-prd-mvp-backlog-build-plan) описывает сохраняемый локальный каталог скилла и альтернативную установку ZIP. Это заявления продавцов в live-карточках, а не проверенные payload и доказательство допуска Tibicen. Второй пример прямо расходится с общим запретом сохранения.

До реализации запросить классификацию точного сценария: **бесплатный оригинальный помощник проверки готовности/запуска**, самостоятельная польза, без экспорта собственного marketplace-контента, явное согласие человека, прямое скачивание отдельно MIT-лицензированного релиза автора, контрольные суммы, локальное исполнение, GitHub остаётся главным источником. Отдельно спросить, можно ли сохранить установленный Tibicen для дальнейшего прямого использования. Это уточнение политики, а не просьба ослабить проверку безопасности.

Если сценарий допускается, отдельно закрепить версии launcher и runtime Tibicen. Предпочесть имеющийся архивный маршрут без Git и менеджера пакетов. Использовать новый пустой каталог; проверить доверенный digest манифеста, две записи assets, извлечённый манифест и каждый файл. До согласия показать источники, пути, скачивание/исполнение и сохраняемые файлы. Не применять `curl | sh`. Сохранить лицензию и хэши релиза. Альтернатива — документированный установщик по полному SHA с закреплённой версией установщика и его заменой/резервными копиями ([установка](https://github.com/warbr1ng3r/tibicen/blob/319845f1f1597817807c81579b42250a1f189e7d/docs/INSTALLATION.md) (строка 29), [проверка архива](https://github.com/warbr1ng3r/tibicen/blob/319845f1f1597817807c81579b42250a1f189e7d/docs/INSTALLATION.md) (строка 85)).

Автоматическое обновление Agensi меняло бы обёртку, а локальный Tibicen не имеет фонового updater ([обновление Tibicen](https://github.com/warbr1ng3r/tibicen/blob/319845f1f1597817807c81579b42250a1f189e7d/docs/INSTALLATION.md) (строка 170)). Нельзя автоматически заменять runtime посреди согласованной сессии или молча менять pin на latest. Записывать реально запущенные источник и версию.

## Манифест будущего кандидата

Это предлагаемый перечень, а не созданный архив для публикации.

Для сравнения с неизменённым содержимым использовать только такие составы:

```text
ZIP отдельной карточки              ZIP pack
SKILL.md                            README.md (новое описание pack)
package.json                        tibicen-init/ (все 50 файлов релиза)
LICENSE                             tibicen-adopt/ (все 50 файлов релиза)
scripts/ (31 файл)                  release-provenance.json (новый, необязательный)
references/ (16 файлов)
```

В манифесте зафиксировать релиз `1.4.1`, исходники `319845f1f1597817807c81579b42250a1f189e7d`, дистрибутив `52c0769574e90d7d1a0438996df9da40621b0107`, хэш архива выше, digests/права каждого файла, версию адаптера и каждый изменённый путь. Новый ZIP имеет другой digest; использовать хэш tarball для него нельзя. При смене путей сохранить upstream-манифест как provenance и отдельно создать корректный манифест пакета. Проверить доставку каждого ресурса; не удалять модули ради лимита файлов.

Для bootstrap разумен небольшой состав: `SKILL.md`, `references/requirements.md`, `references/release-1.4.1.md`, `references/verification-and-recovery.md`, `LICENSE` и, только при необходимости и допуске, один автономный проверенный скрипт. Полный runtime в такую обёртку не включать. Честно заявить чтение/запись файлов, terminal, Node, точные сетевые источники и выбранные человеком каталоги. Git/менеджер пакетов указывать только для соответствующего маршрута.

Проверка безопасности может отметить сочетание сети и локального чтения, исполнение команд и запись. Эти возможности важны для полного процесса; их надо объяснить, а не скрывать. Agensi описывает warnings, ложные срабатывания и окончательное решение человека; scan не доказывает безопасность или совместимость. [Проверка модерацией](https://www.agensi.io/docs/review-and-approval), [ограничения безопасности](https://www.agensi.io/docs/security).

## Предлагаемые приёмочные проверки

Ни одна из проверок через Agensi здесь не выполнялась. Будущий отдельно разрешённый пакет должен разделять этапы:

1. **Офлайн-пакет:** точный allowlist, UTF-8, число/размер файлов, лицензия, отсутствие секретов/зависимостей, все ресурсы, пути входов, импорты, манифест и права; обзор чувствительных к scan возможностей. Валидный ZIP не доказывает доставку.
2. **Локальная эмуляция доставки:** читать обёртку и ресурсы без предположения о локальном каталоге скилла; запускать каждый скрипт без изменения байтов отдельно из временных файлов. Проверить отсутствие Node/terminal/доступа к проекту, пути с пробелами, посторонний CWD, запрет сети. Эмуляция не заменяет marketplace.
3. **Рассмотрение площадкой:** согласовать тип продукта и раскрыть возможности; отправлять только при разрешении публикации. Preview через creator tool подтверждает метаданные, а не даёт исполняемую площадочную приёмку. [Подача агентом](https://www.agensi.io/docs/submit-from-your-agent).
