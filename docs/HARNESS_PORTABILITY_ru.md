# Tibicen с разными хостами и моделями

Tibicen работает внутри вашего привычного агента. **Хост** (или harness) читает
файлы и вызывает инструменты; **модель и провайдера** вы выбираете в этом хосте.
Tibicen не подключается к API моделей, не выбирает модель из списка разрешённых
и не просит создавать учётные данные провайдера для обычной настройки.

[Руководство установки](INSTALLATION.md) закрепляет опубликованную **1.5.2**.
Её [отчёт выпуска](evals/results/2026-11-08-release-1.5.2/README.md) сохраняет
проверки доставки и их ограничения; прежние наблюдения рабочих сессий остаются
привязаны к исходным версиям. Общий `AGENTS.md` доступен с 1.2; в 1.3 появились
расширенные инструкции этапов, подсказки пресетов вне каталога и явный общий
маршрут установки. Это не доказывает нативную загрузку или совместимость моделей
во всех хостах.

## Начать в своём проекте

Установите оба полных скилла явным маршрутом `--agent universal`
из [руководства установки](INSTALLATION.md). Он выбирает `~/.agents/skills/`,
а не нативное обнаружение в каждом хосте. Сохраняйте явный флаг: без `--agent`
установщик может выбрать другие цели. В руководстве есть и полный вариант
через архив/ручное размещение в выбранной папке.

В сессии проекта попросите:

> Прочитай `~/.agents/skills/tibicen-init/SKILL.md` и следуй его инструкциям. Настрой агентскую инфраструктуру этого проекта. Сохрани приложение и до применения покажи точный план.

Для существующей инфраструктуры замените путь
на `~/.agents/skills/tibicen-adopt/SKILL.md` и попросите проверить и улучшить её.
При необходимости замените `~` фактическим домашним путём. При ручном размещении
используйте точный путь `SKILL.md` в выбранной полной папке скилла. Скрипты
и справочники должны оставаться вместе; одного `SKILL.md` недостаточно.

Агент изучает проект, рекомендует достаточную настройку и показывает точные
изменения и запуски для согласия. Хост вне каталога может использовать общий файл,
не выдавая себя за Codex, Claude Code или Cursor. Необязательные подсказки пресета
описывают предпочтения; они не дают прав установки, нативной конфигурации
или исполнения. Старые валидаторы отвергают новые неизвестные ID; при откате
удалите только эти необязательные подсказки.

## Что нужно хосту

| Операция | Если доступна | Если недоступна |
| --- | --- | --- |
| Читать разрешённые файлы проекта и скилла | Изучить фактическую настройку и необходимые ресурсы | Обсуждать только переданные материалы; не заявлять скан проекта |
| Запускать Node ≥22.20 | Выполнять локальные скрипты Tibicen | Использовать локальную сессию с файлами/Node или выполнить названный ручной шаг; не заявлять результаты скрипта |
| Писать в пределах согласованного плана | Применять поддержанные изменения инфраструктуры, сохраняя файлы приложения и полезные решения | Оставить точные предложенные изменения неприменёнными и назвать внешнее действие |
| Явно читать согласованные инструкции проекта | Активировать маршрут общего файла в текущей сессии | Оставить обязательную активацию как `manual-action-required` до наблюдения |

Исполнение Node не разрешает произвольный запуск проектного кода. Проверки проекта
по-прежнему требуют показанных команд, доверия и согласия. На Windows исполнение
команд пока останавливается с `process-tree-unavailable`; операции чтения доступны.
Временная копия сама по себе не изолирует права команды в ОС.

Установленным скиллам нужен Node ≥22.20. Для разработки всего репозитория
и лендинга действуют более высокое требование инструментов из
[package.json](../package.json) и закреплённая среда из [CONTRIBUTING](../CONTRIBUTING.md).

## Одного общего файла инструкций может быть достаточно

Несколько хостов могут явно читать один согласованный `AGENTS.md` и, если выбрана,
одну [память проекта](PROJECT_MEMORY.md). Сохраняйте полезные существующие правила
и заметки. Попросите каждый хост, указав фактический абсолютный путь проекта:

> Прочитай `/actual/project/AGENTS.md` и следуй относящимся к этой задаче инструкциям. Затем [ваша первая полезная задача].

Этому маршруту не нужны проверка нативной версии или адаптер копий `sharedRules`.
Дополнительные нативные копии, конфигурация MCP и процессные интеграции требуют
своих поддержанных контрактов и согласия. Существующие зарегистрированные связи
копий сохраняются; выбор общего маршрута не удаляет их молча. Явное чтение — шаг
активации, а не свидетельство автообнаружения или поведения в следующей задаче.

## Проверить MCP без смены среды

Сценарий MCP в 1.4.0 принимает любой допустимый ID среды: выберите
явный поддержанный формат или передайте безопасные сведения `stdio-observation`,
связанные хэшем с источником другого языка или приложения. Например, исследующий
YAML DeepSeek Harness или Python приложения на GigaChat агент может сообщить
наблюдаемое состояние сервера и имена необходимых env без исполнения этого кода.
Хэш определяет исследованный текст, но не доказывает правильность переданных
сведений. Переданные наблюдения, проверенная парсером конфигурация, факты целевого
запуска и нативное соединение/использование остаются отдельными результатами.
Поэтому отсутствие нативного парсера не требует смены модели/провайдера, нового
файла настроек или копирования чужой конфигурации. См. [форматы и свидетельства](MCP_FORMATS.md)
и [сценарий init/adopt](ADOPT_DIAGNOSIS.md#local-mcp-diagnosis-for-init-and-adopt--unreleased).

## Сохранить контекст в первой задаче

Сценарий 1.4.0 добавляет необязательный
[контекст задачи в отчёте](ADOPT_DIAGNOSIS.md#task-context-for-init-and-adopt--unreleased).
Он фиксирует выбранный хост, рабочую папку и целевой путь задачи без обязательного
профиля в каталоге или нативного адаптера. Контекст задачи входит в опубликованную 1.4.0.

- **Init:** «Настрой агентов для проекта». Для Node-приложения без зависимостей
  и инструкций агент получает команду из `package.json`, предлагает достаточные
  инструкции и необязательную память, затем даёт первый явный шаг чтения.
  Файлы приложения при настройке сохраняются.
- **Adopt:** «Проверь наши правила перед обновлением русской инструкции
  установки». Агент сохраняет корень проекта, рабочую папку и целевой путь
  `docs/ru/install.md`, объясняет корневые инструкции и инструкции перевода,
  сохраняет намеренные различия. Настоящий дефект получает точное предложенное
  исправление; само наличие нескольких файлов не требует изменений.

Для `team-agent` вне каталога первая задача может звучать так: «Из
`/actual/project` прочитай `/actual/project/AGENTS.md` и сохранённый
`/actual/project/docs/ru/AGENTS.md`; затем обнови `docs/ru/install.md` по
английской инструкции». Это явное указание чтения для этой задачи; обычное
согласование записей сохраняется. Оно не обещает автообнаружение или нативный
приоритет. Если в следующей сессии изменились хост, рабочая папка или целевой
путь, сообщите об этом и заново оцените область действия. Фактическое чтение,
поведение в задаче и недоступные проверки фиксируйте отдельно, включая помощь
с указанием файлов. [Руководство памяти](PROJECT_MEMORY.md#check-the-first-task-and-later-memory-use--unreleased)
объясняет проверку последующих решений без другого хранилища.

## Три обычных случая

| Ваша ситуация | Что можно продолжить | Что сохранить при передаче |
| --- | --- | --- |
| Командный хост вне каталога использует локальную Qwen, а не модель OpenAI или Anthropic | При доступных файлах/Node и согласии изучить и предложить/применить общий `AGENTS.md`; сохранить выбранные модель/провайдера | Только фактические операции и явное чтение; нативное обнаружение, ненаблюдаемые идентичность/версия модели и дальнейшее поведение остаются непроверенными |
| Чат-хост только для чтения не может запускать Node или читать локальные файлы | Рассмотреть переданные материалы и объяснить недостающую локальную операцию и следующий шаг | Не заявлять скан, применение или успешную проверку; обязательные внешние применение/активация остаются ручными |
| У известного хоста нет поддержанной автоматической пробы загрузки, задачи или квиза | Продолжить доступную согласованную настройку и структурные проверки | Недоступная проба остаётся `unverified` с причиной; без принудительной смены модели или нового ключа |

У встроенных автоматических проб задач/квизов/загрузки есть условный метод
для проверенной версии Claude Code с отдельными ограничениями согласия, startup,
доверия, учётных данных и бюджета. Отсутствие метода не означает полный отказ
в настройке. [Матрица адаптеров](../references/agent-matrix.md) и профили стенда
разработки не ограничивают выбор модели. Структурный успех, явное чтение
и наблюдаемое использование в свежей задаче — разные результаты. Ожидающая
обязательная активация остаётся `manual-action-required`; неисправленный
обязательный дефект подключения — `incomplete`, а не завершённая настройка
с пробелом необязательной пробы.
