# Память проекта

**Статус:** доступно в опубликованной [1.1.0](https://github.com/warbr1ng3r/tibicen/releases/tag/v1.1.0).
Прежняя поставка 1.0.0 не содержит этого сценария. Две контролируемые свежие
сессии Codex прочитали, использовали и обновили настроенную память; помощь при
настройке и ограничения описаны в [проверках кандидата и сведениях о выпуске](evals/results/2026-11-04-project-memory/README.md).
Примеры ниже иллюстративные и не являются стенограммами этих прогонов.

Память проекта помогает следующим агентам находить важные для вас решения.
Tibicen настраивает один файл проекта и короткие правила его чтения и обновления.
Затем заметки поддерживают рабочие агенты; запущенного сервиса Tibicen не остаётся.

## Начните с обычного запроса

### Проект без памяти

У вас небольшое приложение без инструкций для агентов и файла памяти. Попросите:

> Используй tibicen-init. Настрой проект для агентов. Запоминай, почему мы принимаем
> решения, и спрашивай перед добавлением зависимостей.

Агент изучает проект и запрос. Он предлагает `.agents/memory.md` и короткую ссылку
из подходящих инструкций для агентов. В предложении видны точные файлы и исходный
текст. Вопрос нужен только при неясном существенном выборе и остаётся в обычных
лимитах интервью.

Вы проверяете и одобряете конкретный план. Только после этого Tibicen применяет
его и сообщает результаты проверок. Возможный результат:

```text
AGENTS.md             # применимые правила агента и ссылка на память
.agents/memory.md     # принятые решения проекта и полезные причины
.tibicen/manifest.yml # запись настройки Tibicen, а не рабочая память
```

Например, память может сохранить: «Новые зависимости требуют одобрения — владелец
хочет оставить CLI небольшим». Она не должна выдумывать одобрение или выводить
постоянное правило из разового «ответь кратко». Файлы инструкций зависят от
выбранного агента; пример не требует, чтобы все агенты использовали `AGENTS.md`.

### Проект с существующими заметками

У вас уже есть инструкции и `docs/decisions.md` с полезными решениями. Попросите:

> Используй tibicen-adopt. Приведи настройку агентов в порядок. Сохрани наши решения
> и сделай так, чтобы агенты ими пользовались.

Агент читает разрешённые текущие настройки и заметки. Он предлагает подключить
существующий файл вместо создания другого хранилища. Полезные посторонние заметки
остаются без изменений. Если два хранилища противоречат друг другу, а действующее
решение неясно, агент показывает конфликт и спрашивает в обычных лимитах. При
отключённых вопросах неразрешённый выбор остаётся явным пробелом, а не определяется
молча по возрасту файла.

После одобрения последующие дополнения памяти — обычное рабочее содержимое.
Повторный adopt использует текущие заметки, а не восстанавливает исходный шаблон.

## Что правила предлагают делать рабочим агентам

| Когда                                                                 | Ожидаемое действие                                           |
| --------------------------------------------------------------------- | ------------------------------------------------------------ |
| Перед задачей, на которую влияет прежнее решение                      | Прочитать относящуюся к задаче память перед выбором подхода. |
| Долговременное решение явно принято                                   | Сохранить решение и полезную причину или источник.           |
| Факт о проекте проверен                                               | Сохранить его, если он поможет в дальнейшей работе.          |
| Предпочтение или объяснение только предполагается                     | Отделить его от подтверждённых знаний.                       |
| Пользователь заменяет решение или факт опровергнут                    | Исправить текущий смысл и сохранить посторонние заметки.     |
| Информация временная, чувствительная или является полной стенограммой | По умолчанию оставить её вне долговременной памяти.          |

Например, если позже вы скажете «Теперь небольшая библиотека дат допустима;
сохрани причину», рабочий агент должен исправить затронутое решение, а не оставить
два противоречащих правила действующими. Прежние границы одобрения и выполнения
сохраняются: заметка памяти не разрешает команду и не отменяет ваше указание.

Заметки — читаемый Markdown. Обязательной схемы записей, формата дат или отдельной
анкеты нет; всю историю не нужно копировать в каждый файл инструкций.

## Одно поддерживаемое расположение

Начальный охват поддерживает эти точные пути относительно корня проекта:

- `.agents/memory.md` — по умолчанию, если подходящего хранилища не найдено.
- `MEMORY.md`.
- `docs/memory.md`.
- `docs/decisions.md`.

Проверяемый план привязывает только один выбранный путь. Список не разрешает
переписывать все перечисленные файлы. Произвольные хранилища остаются нетронутыми
с явным ограничением или ручным подключением. Запреты путей, symlink и недоступные
файлы сохраняют обычные проверки безопасности. Отказ от памяти оставляет обычный
сценарий init/adopt доступным без добавления файла памяти.

## Обновление проекта с 1.0

Память подключается по выбору. Используйте совместимый новый runtime Tibicen и
проверьте предложенную миграцию памяти и точные изменения. Сценарии без памяти
сохраняют прежние форматы. Незавершённую старую сессию сначала завершают по её
существующему пути восстановления, затем предлагают память.

Записи с памятью используют схему proposal 2, manifest 3 и recovery 4. Версии
продукта и номера схем независимы. Runtime 1.0 отклоняет новые форматы до записи;
продолжайте проект с памятью совместимым runtime, а не понижайте формат его записи.

Начальные apply и resume прерванной сессии по-прежнему требуют одобренного
исходного содержимого. Если файл изменился, нужны свежий план и одобрение. После
завершённой настройки тело памяти принадлежит пользователю: добавленная заметка не
обязана совпадать с начальным хешем. Безопасное расположение, наличие файла и связь
с управляемыми инструкциями остаются независимо проверяемыми.

Обновление или удаление установленных скиллов Tibicen выполняется отдельно от
изменения заметок проекта. При рассмотрении восстановления или удаления сохраняйте
полезные поздние заметки. Следуйте [инструкциям установки и обновления](../README.md#update-or-remove-an-installation)
и примечаниям совместимости конкретного выпуска.

## Что доказывает проверка

Структурные проверки могут подтвердить безопасный файл и целую связь с
инструкциями. Они не доказывают, что агент прочитал, использовал или обновил память.
Наблюдения в свежих сессиях должны указывать проверенную поставку, версии агента и
инструментов, помощь и фактический исход. Отсутствие контролируемого выполнения
остаётся `unverified`; успех одного агента не доказывает поведение другого.

Релизный пакет раскроет эти наблюдения отдельно от структуры и человеческой
полезности, которая пока не измерена. Эта функция не добавляет аккаунт, сервер,
правки глобальной/приватной памяти агента, синхронизацию проектов или поля памяти
в сохранённых пресетах. Условия кандидата и публикации описывает
[подготовка выпуска](RELEASING.md).
