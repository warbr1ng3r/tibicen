Tibicen помогает вашему агенту настроить инструкции и инструменты проекта или привести их в порядок. Он изучает проект, показывает один подходящий план, применяет согласованные изменения и сообщает, что проверено. Tibicen работает внутри привычного агента; отдельный аккаунт и фоновый сервис не нужны.

## Начать

Выполните команду в терминале. Она установит оба полных скилла из точной опубликованной поставки **1.5.4**; нужны Node **22.20 или новее** и Git.

```sh
npx skills@1.7.4 add https://github.com/warbr1ng3r/tibicen/tree/381c5d53972b53d60e9a134ec7f620bb7c35e6be -g --agent universal --skill tibicen-init tibicen-adopt --copy
```

Затем откройте проект в агенте, который может читать файлы и запускать Node, и отправьте:

> Прочитай `~/.agents/skills/tibicen-init/SKILL.md` и следуй его инструкциям. Настрой проект для моего агента. Добавь только нужное и сначала покажи изменения.

Инструкции для агента уже есть? Укажите `~/.agents/skills/tibicen-adopt/SKILL.md` и попросите проверить и улучшить настройку. Замените `~` домашним каталогом, если хосту нужен абсолютный путь. Этот явный вход не зависит от автоматического обнаружения скилла.

Агент изучит настоящий проект, предложит точные изменения и дождётся вашего согласия. Если настройка уже достаточна, менять её не требуется. Дополнительные скиллы, память и MCP необязательны: они добавляются, только когда помогают проекту.

Требования, другие менеджеры пакетов, ручное размещение, обновление и удаление описаны в [руководстве по установке](docs/INSTALLATION.md). Не устанавливайте несобранную ветку исходников и не копируйте один `SKILL.md`.

## Работа с проектом

В проекте останутся согласованные инструкции и запись о настройке `.tibicen/manifest.yml`. При настройке защищены исходники приложения, существующие пакетные манифесты, CI и данные. Запись, установка и запуск команд приложения требуют согласия на точный план; Tibicen не создаёт коммиты.

Итоговый отчёт разделяет проверку структуры, результаты фактической работы и неподтверждённое поведение. В [коротком записанном примере](docs/examples/first-use.md) агент привёл в порядок инструкции искусственного проекта, оператор применил его точный план, а новый агент выполнил полезную задачу с существующей памятью.

## Возможности и ограничения проверок

Хост должен читать скилл целиком и выполнять его локальные операции. Модель и провайдер остаются настроены в этом хосте; отдельный API-ключ Tibicen не нужен. Явный доступ не подтверждает автоматическую загрузку и совместимость с любым хостом. На Windows запуск проектных команд пока недоступен; операции чтения поддерживаются.

Польза для людей и сравнительная экономия времени не измерены. Встроенной инициализации вашего агента или прямой просьбы проверить инструкции тоже может быть достаточно.

## Сборка и установка из исходников

Для разработки следуйте [руководству участника](CONTRIBUTING.md). `pnpm build` создаёт полные скиллы в `dist/`; [команды локальной установки](README_RELEASE_HISTORY.md#build-and-install-from-source) сохранены в прежнем README. Для обычной работы используйте закреплённую опубликованную команду выше.

## Обновление или удаление установки

Перед заменой или удалением сохраните локально изменённые папки скиллов: повторный `add --copy` заменяет выбранную папку. Следуйте [руководству по обновлению и удалению](docs/INSTALLATION.md#update-and-removal). Переустановка Tibicen не обновляет инфраструктуру проектов автоматически; отдельно попросите выполнить adopt.
