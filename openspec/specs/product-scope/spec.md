# product-scope Specification

## Purpose

Зафиксировать назначение Tibicen, два пользовательских сценария и границы MVP. Это требования к продуктовому контракту; готовность реализации подтверждается отдельно.

## Requirements

### Requirement: Two product scenarios
Продуктовый контракт SHALL описывать первоначальную настройку через tibicen-init и улучшение уже существующей инфраструктуры через tibicen-adopt.

#### Scenario: A developer chooses an entry point
- **WHEN** разработчик читает назначение двух скиллов
- **THEN** он различает пустую папку, приложение без инфраструктуры и проект с существующими агентскими настройками
- **AND** оба сценария предусматривают применение согласованных изменений, а не только рекомендации

### Requirement: User control and preservation
Продуктовый контракт SHALL требовать согласия на точный план до изменений, установки и исполнения стороннего кода; существующее приложение сохраняется, автоматические Git-коммиты запрещены.

#### Scenario: An existing application receives agent infrastructure
- **WHEN** описывается внедрение в существующий проект
- **THEN** исходники, существующие пакетные манифесты, CI и данные защищены от переделки
- **AND** согласие не подменяется автопилотом или данными предложения

### Requirement: Minimal infrastructure and explicit updates
Продуктовый контракт SHALL выбирать дополнительные скиллы и MCP по пользе для задачи, предусматривать обновление по запросу и не требовать постоянного процесса Tibicen в проекте.

#### Scenario: Instructions are sufficient
- **WHEN** проекту достаточно агентских инструкций
- **THEN** контракт допускает результат без дополнительных скиллов и MCP
- **AND** актуальность оценивается по применимым источникам и версиям, а не по числу компонентов

### Requirement: Evidence determines readiness
Продуктовый контракт SHALL отличать наличие файлов и локальные проверки от подтверждённого поведения агентов и пользы для пользователя.

#### Scenario: An implementation has not been tested with real agents
- **WHEN** существуют только документы или локальные проверки
- **THEN** это не объявляется доказательством загрузки инструкций, успешной рабочей задачи или готовности публичного выпуска
