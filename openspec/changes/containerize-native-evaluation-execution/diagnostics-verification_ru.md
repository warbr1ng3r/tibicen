# Диагностика первой ошибки контейнерного прогона

Офлайн-исправление от 28.10.2026. Оно устраняет потерю диагностики в испытательном harness; распространяемые скиллы Tibicen и опубликованная alpha не меняются.

## Наблюдавшийся дефект и изменение

[Остановленная нативная задача Ponytail](../../../docs/evals/results/2026-10-28-published-alpha-native/README.md) сохранила `tool-failure`, но не событие исполнителя, вызвавшее остановку. Исходная причина и набор записей внутри контейнера остаются неизвестными. Эти записи не переписывались, прогон не повторялся.

Детерминированный тест настоящей контейнерной сессии воспроизвёл потерю: разбитая между порциями JSON-RPC ошибка и последующее завершение процесса останавливали сессию, но первый код ошибки отсутствовал в результате. До исправления пять существующих тестов проходили, а новая проверка получала `undefined` вместо ожидаемых данных.

Результат теперь содержит `toolFailure`: null, `{kind: 'rpc-error', code: number|null}` или `{kind: 'process-exit', exitCode: number|null}`. Сохраняются только безопасные целые числа. Произвольные методы, сообщения, идентификаторы, команды, вывод и вложенные данные не копируются. Побеждает событие, начавшее остановку; игнорируемая ошибка -32004 и успешное завершение работают как прежде. При сбое файлы проекта по-прежнему не собираются, проверки остановки и удаления сохранены. Поле описывает наблюдавшееся событие, а не его первопричину.

Вызывающий код также возвращал `sourceUnchanged: false`, когда отмена мешала полной проверке профиля после прогона. Теперь отклонённая проверка даёт null, успешная — true; успешный прогон требует true. Null означает непроверенный результат, включая недоступную проверку или обнаруженное несовпадение; это не утверждение об изменении исходников. Другие потребители в репозитории не зависят от прежнего false. Исторические результаты сохранены.

## Проверки

Настоящий caller проверен в отдельной копии с инертными зависимостями. Случаи успеха, отмены и недоступной проверки сначала воспроизвели `false !== null`, затем прошли после исправления. Тест также проверяет передачу результата и отсутствие произвольного сообщения проверки. Это проверка управления настоящего caller без исполнения CLI или модели.

Целевые проверки Node 24.15.0 прошли: 30/30 для сессии, профиля, ограничений авторизации и результата caller. Отдельные проверки архива прошли 4/4. Независимое `ponytail-review` не нашло замечаний: **Ship**, для одного ограниченного разработческого прогона.

`pnpm test` прошёл на Node 24.15.0 и pnpm 11.21.0: lint, форматирование, типы, сборка сайта, строгая валидация активных и архивных OpenSpec, сборка поставки и **700/700 офлайн-тестов** (Node-тесты: 68,7 секунды). После сборки совпали все 168 закреплённых хэшей: 86 файлов поставки и их манифест сумм, исходный отчёт published-alpha и сохранённые файлы native-кейса. Браузерные проверки для этого изменения eval не повторялись.

## Ограничения

Новых model/API/native-сессий, чтения учётных данных, запусков Docker, изменений авторизации, коммитов или публикации не было. Реальные наблюдения жизненного цикла Docker остаются из предыдущей проверки. Новое поведение проверено офлайн с заглушками и настоящим caller с инертными зависимостями. Браузерные проверки не относятся к этому изменению eval. Будущий живой запуск требует отдельно проверенных новых freeze и лимита; прежний сбой не доказывает, что исправление сохранило бы его утраченную причину.
