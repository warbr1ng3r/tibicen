# Design

## Context

See [proposal](proposal.md). The original eight-attempt Codex packet and separate adopt recheck are immutable. Their unknown original failure is not recoverable. Existing public error projections deliberately exclude arbitrary text. The isolated recheck recorder proved a useful seam; the maintained implementation must bind that seam to source and destination identity.

## Decisions

- Add one optional private-diagnostic destination to the existing contained run input. Create a new owner-only directory and exclusive file outside target and disposable HOME; validate before execution. Include policy/destination and new helper source in the prospective freeze. Existing callers remain unchanged when omitted.
- Retain only terminal event type/hash and a bounded selection of message/code/type strings, never arbitrary provider objects. Redact exact access-only credential values and supported credential patterns before write; cap per-message, record and total output. Public projection remains unchanged. Recording failures cannot silently become success. Private messages remain untrusted and unsuitable for publication; arbitrary secret detection cannot be guaranteed.
- Clarify maintenance authority in the existing architecture guidance rather than adding a new template, validator or permanent runtime. Generated notes continue to use the one selected store and ordinary owner-authorized working agents.
- Reuse the native evaluator and approval controls. A pure generated-memory fixture/scorer helper is allowed where it prevents oracle leakage; no new runner framework. Fresh work receives approved project outputs without Tibicen or parent transcript. Choose a task-specific decision only from selected memory. Exclude previous implementations from the fresh-task source snapshot and declare that controlled reset. Keep the scorer outside all worker files.
- Prepare and mechanically verify a five-phase subscription-only protocol: proposal, conditional approved apply, fresh work, ordinary correction, fresh corrected work. Root alone executes any selected native packet after source/build/fixture/protocol review; 180 seconds per phase, 900 caller seconds total, concurrency one, zero automatic retries/new paid API calls. Missing receipts or usage stay unknown and prevent unreviewed continuation; observed usage is not a hard provider token quota.

## Reviewed execution adjustment, 15 November

The original packet stopped after native generation and an executor denial in
the apply phase; missing usage prevents further phases in that packet. Preserve
that result. A separately frozen, model-free real-executor control successfully
applied the exact generated plan. Independent review then admitted a distinct
three-task question: ordinary use, correction and fresh reuse of the actual
generated memory after controller application. This supplies no native-agent
apply evidence. The paired [protocol addendum](../../../docs/evals/GENERATED_MEMORY_OBSERVATION.md#separate-controller-applied-task-observation)
records the changed question and resource scope before its launch.

Keep the two earlier calls in the aggregate five-call/900-second allowance.
Unknown usage remains unknown: no aggregate token quota is claimed. The new
packet's reported-usage admission thresholds apply only to its three calls;
failure or missing usage stops it, with no replacement packet.

The first ordinary task legitimately updated observed implementation facts in
memory. The frozen preparation helper's stricter unchanged-memory assertion
was therefore unsuitable for correction input. Keep that helper unchanged in
the frozen record; separately bind and review a controller projection that
copies the actual accepted six-file working output without rewriting memory.
Record this preparation deviation and its hashes before correction admission.
The final fresh task still resets source/tests and retains only the actual
corrected memory and original generated entrypoint alongside starter files.

## Risks / Trade-offs

- Private provider text can contain unknown sensitive details → fixed-field extraction, known credential/pattern redaction, owner-only files, bounded storage and no publication; disclose the remaining arbitrary-secret limitation.
- A short guidance clarification cannot enforce model behavior → inspect generated proposals independently and report actual native content rather than interpreting text tests as compliance.
- Formatter output alone does not prove memory reading → isolate the distinguishing decision, retain direct tool reads where possible, report loading assistance and avoid human-benefit claims.
- A default/path change can invalidate old freezes → preserve old records and require a new prospective freeze for new calls.
- Other agents already have uncommitted work → explicit path ownership, root-only integration, no reset or commits.
