# Proposal

## Why

The 15 November observations exposed an inaccurate generated init-only maintenance rule, lost unknown terminal-error text, and a memory example whose answer was already visible in source. Follow-up work must correct the recommendation and improve retained evidence without introducing a permanent product dependency or overstating behavioral coverage.

## What Changes

- Clarify that owner-authorized working agents can maintain generated project instructions and memory without an installed Tibicen; init creates and adopt reviews updates.
- Add opt-in, bounded private terminal-error retention to the contained Codex evaluator before its unchanged public diagnostic projection, with credential redaction, restrictive file creation, source/destination freezes and offline regressions.
- Prepare a reproducible generated-memory observation fixture, isolated scoring controls and a finite subscription-only protocol. Policy generation, consent, native application and fresh working-task evidence stay distinct.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `agent-infrastructure-lifecycle`: generated guidance preserves independent post-handoff maintenance and owner authority.
- `evaluation-results`: private diagnostic retention and generated-policy observation controls preserve privacy, exact identities and evidence limits.

## Impact

Installed architecture guidance, paired memory/evaluation documentation, contained development evaluator and offline tests. No new dependencies, public diagnostic text, distributed evaluation tooling, automatic retries, paid API authorization, version bump, commit or publication. Existing uncommitted work and historical failed records remain intact.
