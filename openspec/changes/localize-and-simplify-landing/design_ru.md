# Design

## Context

См. [proposal](proposal.md) и аудит исходников/публичной страницы (локальная запись сопровождающего; не входит в публичный снимок). Сейчас index.astro содержит русский текст и структуру. Русские строки также есть в установке, пресете, иллюстрации, доступных подписях Features, app.ts и проверках preset.ts. Статические тесты читают одну страницу, браузерная навигация предполагает корень. Pages workflow уже передаёт Astro site/base.

Английская основная документация по инструкции владельца приоритетнее прежнего русскоязычного planning context. У артефактов русские копии; ссылки в обоих языках ведут в основные английские файлы. Валидатор OpenSpec допускает только spec.md внутри capability-каталогов, поэтому переводы двух спецификаций находятся рядом с design как landing-experience_ru.md и landing-interactions_ru.md.

## Goals / Non-Goals

**Goals:** одна общая вёрстка, полный перевод видимых/доступных/error-путей, статическая навигация, проверка root/project base.

**Non-Goals:** определение/авторедирект locale, запоминание языка, смена языка без перехода, зависимости переводов, новые агенты, продуктовый runtime, живые модельные прогоны и deployment. Переход языка открывает отдельную страницу и сбрасывает несохранённую форму; для необязательного конструктора это допустимо.

## Decisions

1. **Два маршрута и общий компонент.** Перенести страницу в Landing.astro с типизированным `en | ru`; index.astro и ru/index.astro — тонкие обёртки. Обычные ссылки строятся от BASE_URL; переключатель находится вне скрытой мобильной навигации. Клиентская подмена не даст английский без JS, дублирование страниц приведёт к расхождениям.
2. **Отделить текст страницы от клиентских сообщений.** Небольшой типизированный модуль EN/RU для готовой страницы и отдельные клиентские сообщения по html.lang. Передавать locale/подписи существующим компонентам. Перевести все ветви отказа пресета, сохранив ID полей. Не отправлять маркетинговый каталог клиенту, не вводить общий framework переводов.
3. **Только представление.** Сохранить installationCommand и schema-значения. Язык страницы не становится stack_hint.language; поле назвать Programming language. Выбор менеджера/агента остаётся там, где меняет команду; рядом реальные статусы. Без непроверенной цели Other.
4. **Переставить существующие блоки.** Hero → Get started (установка + init/adopt) → короткий процесс и иллюстративные до/после/отчёт → короткий FAQ → свёрнутый необязательный пресет → footer проекта/документов/релиза/лицензий. Убрать плавающие повторы и большую карточку manifest. Сохранить граф, reduced motion, одну помеченную иллюстрацию и локальные ресурсы.
5. **Честные свидетельства и ссылки.** Limited alpha, проверенная доставка macOS/Node24/Codex, экспериментальность остальных целей и Windows execution limits. Подробности вести в существующие английские README/release/results вместо истории разработки. Пример — иллюстрация, не доказательство общей приёмки. Сохранить фактическую публичную команду; старый основной ./dist-сценарий не возвращается.
6. **Соразмерные проверки.** Проверять обе готовые страницы и якоря страницы назначения, разрешая маршруты-каталоги в index.html относительно текущей страницы. Сохранить interaction/geometry-проверки; добавить целевые RU/error/download/copy, переключение без JS, все ветви валидации чистыми тестами и настоящий project-base build/preview browser smoke. Не умножать всю матрицу браузер/язык/31 ширина.

## Risks / Trade-offs

- Пропущенные скрытые переводы → все ветви ошибок, доступные подписи, noscript и принудительный отказ копирования.
- Неверные nested/base-ссылки → статические проверки обоих маршрутов и браузерные переключение/ресурсы/control под project base.
- Длинный русский текст → осмотр типовых RU phone/desktop, сохранение существующего responsive gate.
- Шум snapshots → менять только затронутые эталоны после осмотра; не удалять проверки поведения.
- Приватность истории → будущая публикация по существующему очищенному маршруту; локальная история не отправляется.

## Migration Plan

Реализовать и проверить локально, затем независимое ponytail-review с исправлениями. Публикация и новый коммит — отдельный разрешённый шаг. Будущий deployment сохраняет URL корня для английского и добавляет ru/; rollback возвращает прежний static artifact. Выпущенные skill tags/assets неизменны.
