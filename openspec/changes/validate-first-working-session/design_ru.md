# Design

Канонический документ: [design](design.md).

## Context

Релиз 1.4 имеет отдельные свидетельства публичной поставки и offline/platform проверок. Последние рекомендации были read-only с помощью родителя. Этот пакет наблюдает следующие стадии без переименования старых записей. Все 100 хэшей замороженной поставки совпали. Приватный полный roadmap сохранён; публичная история берётся из прежнего curated public tree.

## Goals / Non-Goals

**Goals:** пять обычных запросов, точные рекомендации, отдельно механическое применение и свежая задача, сохранность/счётчики усилий, минимальные подтверждённые исправления и актуальный roadmap.

**Non-Goals:** сравнение нативных сред/моделей, человеческая польза, личные настройки, платные API, новый runtime/backend/зависимости, универсальная совместимость и релиз.

## Decisions

1. Свежие внутренние субагенты явно читают полный скилл. ID среды — переданный контекст, не нативное наблюдение. Внешняя модель/CLI не запускаются. Авторство fixtures самим исполнителем раскрывается: это наблюдение с помощью, не слепой benchmark.
2. Пять сценариев: I1 начальные инструкции; A1 устаревшая команда с полезными правилами; M1 явное исправление памяти; C1 локальный MCP enabled/disabled; N1 достаточная настройка без изменений. Точные входы приватны; запросы синтезированы, не чужие стенограммы.
3. Авторы рекомендаций останавливаются до apply и не одобряют свои digest. Root отдельно проверяет точный план/собственный fixture. Контрактный тест может передать frozen API **имитированный approval token** с собственным HOME: это проверка механики, не согласие пользователя или обычный самостоятельный прогон. Отказы продукта не обходятся. Исходные планы, revisions и все начатые попытки сохраняются.
4. Профиль/доверие должны соответствовать fixture. Неподдержанный pure Node module остаётся unverified в продукте. Root отдельно может выполнить прочитанные builtin-only тесты как oracle разработки, не выдавая их за продуктовый/нативный успех. MCP-сервер и произвольные зависимости не запускаются.
5. Свежий рабочий агент получает только подготовленный проект, обычный запрос и явный путь инструкций. Запись — только в названные app/test файлы; oracle/прежние ответы не передаются. Root отдельно проверяет поведение и сохранность инфраструктуры. Память проходит позднее исправление/чтение с сохранением несвязанных заметок.
6. Максимум исходная и одна отдельно обозначенная исправительная попытка на case/phase. Ошибки не удаляются, причины повторов раскрываются. CLI-чтения/ошибки/повторы/вопросы и действия оператора — разные счётчики; экономия времени не заявляется. C1/N1 могут корректно закончиться без apply/рабочей задачи.
7. Дефект требует точного воспроизведения и существующего контракта, регрессии и минимальной правки. Без дефекта runtime не меняется. Новое поведение сначала оформляется требованиями/сценариями.
8. Основные документы EN, рядом RU. В публикуемом только сводка; сырые чтения/пути/стенограммы приватны. Roadmap содержит текущие факты и этапы, история явно датирована; при переносе меняются лишь адреса относительных ссылок.

## Reproduced preview correction

Замороженные A1/M1 заменяют одну строку, но весь файл отображается удалённым/добавленным. Линейно сократить общий префикс/суффикс, оставить три строки контекста и один общий hunk, сохранить окончания строк и полный текст. Без зависимости, вызова Git и нового diff-движка; apply использует точное содержимое/хэши, а не diff для отображения.

## Risks / Trade-offs

Малые fixtures с помощью не доказывают пользу людям и всеобщую загрузку. Механика и рабочая задача учитываются отдельно. Профильные ограничения остаются даже после рабочей задачи. Пропуск до старта не становится выполнением, ошибки сохраняются, человеческие/нативные оценки не выдумываются.
