# Design

## Context

См. [предложение](proposal.md). Существующий переносимый сценарий уже отделяет локальные операции от имени хоста/модели, а контекст задачи в report отличает переданные значения от нативных наблюдений.

## Decisions

Оставить один рецепт в `references/stage-handoff.md`, доступный обоим скиллам. Собирать копируемый запрос из рассмотренных рабочей папки, применимых существующих инструкций и необязательной выбранной памяти, сохраняя полезную задачу. Сохранять нативные/собственные точки входа, без определения приоритета по имени файла и добавления другого файла инструкций.

Объяснение наблюдений оставить вне запроса: структурный результат, доступное явное чтение, нативное обнаружение и использование в свежей задаче. Неизвестное остаётся неизвестным. Существующие правила ручных действий и незавершённого состояния сохраняются.

Обновить парное руководство переносимости, в том числе устаревшие сведения о релизе/контексте. Для формируемой рабочим агентом передачи не нужны поле runtime или постоянное состояние.

## Risks / Trade-offs

Тесты проверяют полноту общих ресурсов и связь контекста задачи; эквивалентность примеров EN/RU проверена вручную. Это не подтверждает поведение модели. Нативная загрузка и польза требуют отдельных наблюдений; этот пакет их не выполняет. При конфликте применимых инструкций может потребоваться уточнение; рецепт сохраняет неопределённость, а не выдумывает порядок.
