# Предложение

## Зачем

Обещание сравнения контролируемого профиля `python` (неизменная ошибка остаётся
`pre-existing-red`) выполняется для Python `unittest`, у которого нормализуется
полная строка `Ran N tests in Ts`. Pytest — самый распространённый Python-раннер —
печатает сводку как `========== N failed in Ts ==========`; эта временная запись не
распознаётся, поэтому один и тот же провальный прогон дважды даёт
`changed-failure` / `new-regression` только из-за дрейфа времени. Воспроизведение
на неизменённой публичной базе подтвердило ошибочную классификацию через реальную
точку записи (`outputHash` от `canonicalizeRunOutput`), при том что аналогичный
дрейф `unittest` сравнивается корректно.

## Что меняется

- Распознаётся полная временная запись сводки pytest — строка, состоящая только из
  `=+ <счётчики или «no tests ran»> in <длительность>s =+` — и нормализуются длительность, необязательные часы timedelta и переменная рамка. Построчная привязка сохраняется, как в правилах Node spec/TAP и Python unittest.
- Всё остальное остаётся строгим: значения утверждений, имена тестов, счётчики,
  неоформленные фразы вида `3 warnings in 0.42s` и неизвестные форматы остаются
  значимыми различиями (`changed-failure`).
- Точность документации вместе с фиксом: закрепление интерпретатора — только
  абсолютный путь; привязка скрипта покрывает единственный одобренный входной файл;
  каталоги `.venv`/`venv` исключены из baseline/final-копий и не воспроизводятся. Доступность пакетов зависит от закреплённого интерпретатора и согласованного окружения; исключение не изолирует импорты. `environmentReady` удостоверяет
  закреплённый интерпретатор плюс те пакеты, которые этот интерпретатор фактически
  видит (системные/ambient), но никогда не воспроизведённое окружение.

## Возможности

`verification-and-delivery`: неизменные ошибки, различающиеся только
распознаваемыми временными записями раннера — теперь включая сводки pytest —
сравниваются как `pre-existing-red`.

## Влияние

Общий `scripts/verify/index.ts` (одно правило канонизации), целевые регрессии в
`tests/verify/run-output-normalization.test.ts` (падают на неизменённой базе),
уточнение формулировок границ в `references/proposal-format.md` и
`docs/CURRENT_CAPABILITIES.md`, записи `Unreleased` в обоих языках changelog.
Оба распространяемых скилла получают ту же реализацию через существующую сборку.
Совпавшая строка сводки — соглашение о формате, а не доказательство честности
раннера; семантическое понимание произвольного вывода не заявляется.
