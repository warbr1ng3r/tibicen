# Proposal

## Why

The retained reliability reports describe self-consent under autonomy wording, project decisions placed in replaceable blocks and unclear memory recovery. The maintained evaluator also needs small inspectable records and bounded transport checks before another native packet.

## What Changes

- Separate interview autonomy, tool permission and approval of the exact compiled plan. State that digest equality identifies content, not a human; strengthen the existing external controller boundary in development evaluations.
- Keep project-owned decisions outside replaceable setup policy; connect one selected memory store from an applicable entrypoint or disclose explicit reading as a fallback.
- Return actionable missing-memory-connection recovery advice while preserving approved instruction removal and new-plan, fresh-consent, same-session repair.
- Fix confirmed supervisor output/failure handling defects and export compact hash-bound run summaries from existing retained evidence, without new model requests or inferred costs.
- Check init, adopt, no-op, memory preservation and interrupted repair offline, then review the combined source and exact built artifacts.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `agent-infrastructure-lifecycle`: distinguish the approval authorities and explain recovery before an ineffective unchanged-plan retry.
- `project-memory`: make durable ownership and explicit-read fallback part of setup guidance.
- `evaluation-results`: bind controller consent and compact retained summaries; fail closed on transport limit or observer errors.

## Impact

Installed references, lifecycle diagnosis/output, development-only evaluation controller/supervisor/collector, focused tests and paired documentation. No new dependencies, persistent product schema, write scope, native login, paid run, version bump, commit or publication is selected. Existing published 1.5.4 and historical outcomes remain unchanged.
