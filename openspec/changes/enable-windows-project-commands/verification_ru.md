Каноническая запись: [verification](verification.md).

## Начальная локальная точка интеграции — 18 ноября 2026

Реализация **Unreleased**, на базе опубликованной 1.6.0: Windows-исполнитель после прежних проверок согласия/доверия, закреплённый PowerShell/Win32-помощник, поиск нативных интерпретаторов и ограниченная batch-передача. Схемы состояния, POSIX-группы и опубликованные артефакты сохранены.

Нативный suite проверяет обе собранные поставки: реальные exit-коды, поддельную управляющую строку в stdout, Unicode/буквальные аргументы, настоящий batch-forwarder и отказы, точные пути без расширения, минимальное окружение/редакцию секретов, подменённый проектный PATH, раннюю/живую отмену, timeout и выход родителя с открытыми/закрытыми потоками потомков, отсутствие bootstrap/helper и публичный docs-profile CLI lifecycle. В диагностике — Node/OS и хэш манифеста. Синтетическое согласие действует только для временных фикстур, не доказывает человеческое одобрение или загрузку харнессом.

## Независимое ревью и исправления

Отдельный Ponytail-ревьюер изучил помощник, исполнитель, вызывающий код согласия/копий и аргументы. Два подтверждённых замечания исправлены и перепроверены:

- Суффикс `.com` обходил общую нормализацию запретов оболочек/обёрток/коммитов. Новая регрессия падала до исправления и прошла после; web-запрет Bash использует тот же normalizer, включая `.COM`/`.bat`.
- Отмена оставляла таймер timeout до закрытия процесса; около срока отменённая команда могла получить `timedOut: true`. Первое принятое завершение теперь очищает таймер; нативные abort-кейсы требуют `timedOut: false`. Это найденная в исходниках гонка, не воспроизведённый Windows-сбой по времени.

Root также убрал подмену явно согласованного пути без расширения: `./check` не выбирает соседний `check.exe`. Нативные тесты покрывают отсутствие/наличие точного файла с настоящим Node рядом. Ревьюер перепроверил правки и не нашёл других конкретных замечаний; его точечные проверки прошли **11/11**, нативное исполнение локально недоступно.

Нативный CI [44229803132](https://github.com/warbr1ng3r/tibicen/actions/runs/44229803132) **прошёл все шесть платформенных ячеек** на публичных исходниках `7221397bae0679bffbe333d81b338fc55b33c741`. Обе ячейки Windows Server 2022 завершили нативный процессный suite для обоих собранных скиллов и переносимый CLI lifecycle: [Node 22.20.0](https://github.com/warbr1ng3r/tibicen/actions/runs/44229803132/job/134551767405) и [Node 24.15.0](https://github.com/warbr1ng3r/tibicen/actions/runs/44229803132/job/134551767742). Четыре ячейки macOS/Linux прошли переносимые проверки. Это наблюдаемое Windows-исполнение для указанного runner и исходников, а не mock win32, все Windows-среды или автозагрузка харнессом.

Финальный локальный gate root прошёл **1 176 / 0 failed / 2 skipped**, всего 1 178, test-runner **78,41613 с**. Root и независимая сборка публичных исходников дали одинаковый LF-манифест поставки: `aa986f71cf6ea76608ea9b72ff0a31f5420efd0db3dc0009b574fd320472243a`. Логи CI записывают свой манифест; возвращённый Windows-хэш и точные нативные количества независимо не прочитаны, поэтому равенство хэшей Windows/root не заявляется. Прежние неудачные прогоны остаются неудачными. Текущие исходные изменения остаются **Unreleased**, версия пакета/ресурсов — 1.6.0; опубликованные артефакты 1.6.0 не менялись. Закрытие документации сохраняет эту исполняемую поставку.

Политика PowerShell/.NET может запрещать исполнение; Tibicen её не обходит. Job управляет обычными потомками, не файловыми/сетевыми правами и не намеренным выходом через WMI. Batch сознательно ограничен. Установка Python/Bash, равенство Windows ACL, автозагрузка свежим харнессом и человеческая польза не входят в эти проверки.

Финальная изолированная проверка поставки: совпали все **114/114** хэшей, оба self-test пройдены вне checkout с изолированным HOME и пустым PATH. Временная копия удалена.
