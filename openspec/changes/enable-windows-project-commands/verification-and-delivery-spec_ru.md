# Spec Delta

Перевод канонического [spec](specs/verification-and-delivery/spec.md).

## ADDED Requirements

### Requirement: Windows approved command lifecycle

На поддерживаемом Windows-хосте Tibicen SHALL исполнять поддерживаемые согласованные доверенные команды в контролируемой копии, сохранять фактический exit-код и ограниченный вывод с редакцией секретов, завершать обычных потомков при нормальном окончании, отмене и timeout. При отсутствии управления процессами SHALL сохраняться недоступность без успешного результата проекта.

#### Scenario: A native check completes

- **WHEN** неизменная согласованная команда запускает нативный executable в копии и выходит с 0 или 37
- **THEN** записывается соответствующий код проекта 0 или 37 независимо от кода помощника
- **AND** stdout проекта не может подменить управляющую запись помощника

#### Scenario: Parent exit or cancellation leaves descendants

- **WHEN** команда оставляет обычных потомков с открытыми или закрытыми потоками, а её родитель выходит, отменяется или достигает срока
- **THEN** потомки завершаются до сообщения об успешном окончании lifecycle
- **AND** timeout и отмена остаются различными недоступными исходами

#### Scenario: Process control cannot be established

- **WHEN** системный помощник отсутствует, присоединение к job не проходит либо отдельный результат отсутствует/повреждён
- **THEN** нулевой статус помощника не означает успех проекта
- **AND** выявляемая заранее недоступность управления процессами запрещает запуск до исполнения

#### Scenario: Consent or trust is absent

- **WHEN** нет согласия по точному плану, команда недоверенная или запрос заранее отменён
- **THEN** помощник и проектный код не запускаются
- **AND** прежние ошибки согласия и доверия сохраняются

### Requirement: Windows command representation preserves approval

Windows-исполнение SHALL сохранять поддерживаемые буквальные аргументы, использовать абсолютный разрешённый executable и отклонять NUL. Контролируемые интерпретаторы SHALL закрепляться нативными путями без запуска до согласия. Batch SHALL принимать только описанное ограниченное подмножество; неподдерживаемые формы SHALL отказывать до проектного запуска, без произвольных оболочек.

#### Scenario: Native arguments need quoting

- **WHEN** согласованные нативные аргументы содержат пробелы, Unicode, пустые строки, кавычки или конечные обратные косые черты
- **THEN** программа получает исходный массив аргументов
- **AND** посторонние секреты хоста отсутствуют, а явно переданные скрыты в сохранённом выводе

#### Scenario: An ordinary package-manager shim runs

- **WHEN** согласованный найденный `.cmd`/`.bat` использует безопасные буквальные аргументы, например `run` и `test`
- **THEN** закреплённый системный интерпретатор запускает этот файл внутри контролируемого job
- **AND** стандартный forwarding-shim получает принятые строки без изменений

#### Scenario: A batch argument cannot be represented safely

- **WHEN** batch-цель/аргумент содержит кавычки, подстановки или shell-символы, передаваемый аргумент заканчивается обратной косой чертой либо строка превышает описанный предел
- **THEN** команда недоступна с явной причиной до проектного эффекта
- **AND** исполнитель не переходит к `shell: true`, окружающим aliases или проектному системному помощнику

#### Scenario: A controlled interpreter is found on Windows

- **WHEN** у поддерживаемого интерпретатора есть `.exe` в абсолютной папке PATH
- **THEN** proposal закрепляет именно этот путь без запуска
- **AND** относительные папки PATH и отсутствующие интерпретаторы отклоняются

### Requirement: Windows support claims require native execution evidence

Поддержка команд Windows SHALL проверяться на настоящем Windows-runner с собранной standalone-поставкой. Mock платформы и self-test ресурсов SHALL NOT подменять нативный lifecycle, аргументы, отказы и сохранность копии проекта. Недоступность нативной проверки SHALL оставаться явной.

#### Scenario: Native CI has not run

- **WHEN** локальные POSIX-тесты проходят, но нативного Windows-результата кандидата нет
- **THEN** документация различает реализацию и проверенную поддержку Windows
- **AND** опубликованному выпуску не приписывается новая поддержка

#### Scenario: The packaged command lifecycle is exercised

- **WHEN** настоящие Windows-проверки запускают обе standalone-копии скиллов и контролируемые фикстуры
- **THEN** результат фиксирует исходники/поставку, Node/OS и фактические исходы команд
- **AND** прежние проверки POSIX и границ полномочий сохраняются
