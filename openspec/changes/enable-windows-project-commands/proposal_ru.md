# Proposal

## Why

Tibicen 1.6.0 умеет читать и применять инфраструктуру в Windows, но отказывает в запуске команд проекта: очистка процессов рассчитана на POSIX. Пользователь Windows не получает реальное сравнение тестов исходной и итоговой копий по согласованному плану.

## What Changes

- Фиксированный Windows launcher включает себя в безымянный, ненаследуемый Job Object с уничтожением при закрытии последнего handle до запуска кода проекта. Сохраняет настоящий exit code и останавливает обычных потомков при завершении, таймауте и отмене.
- Точное согласие, доверие, контролируемые копии, ограничение вывода, минимальное окружение и сокрытие секретов сохраняются. Недоступный launcher или неудачная очистка не превращаются в успешную проверку.
- Интерпретаторы закрепляются абсолютными `.exe`-путями. Добавляется native quoting и ограниченный маршрут `.cmd`/`.bat` для обычных команд пакетного менеджера; неподдержанные аргументы отклоняются до запуска.
- Упакованный launcher проверяется настоящим Windows runner, включая потомков, ошибки и отказ без согласия. POSIX-регрессии сохраняются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `verification-and-delivery`: жизненный цикл Windows-команд и достоверные результаты в рамках существующих контролируемых проверок.

## Impact

Исполнитель, поиск интерпретаторов, один самостоятельный PowerShell/Win32 helper, CLI/portable-тесты и платформенный workflow. Используются Windows PowerShell и .NET поддержанного хоста; новых пакетов, сервиса, постоянного кэша и повышенных прав нет. Job Object управляет обычными потомками, но не является sandbox ОС и не гарантирует удержание намеренно обойдённого запуска через WMI. Различия POSIX-прав и Windows ACL остаются явными. Схемы и опубликованная 1.6.0 не меняются.
