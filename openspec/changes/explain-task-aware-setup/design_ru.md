# Design

## Context

См. [предложение](proposal.md). Существующий отчёт — единственный вызывающий общую
диагностику компонент runtime. `scan.agents` содержит наблюдаемые признаки, а не
выбранный хост; пути инструкций в каталоге содержат glob-шаблоны, пояснения и
различные модели загрузки. Существующие инструкции стадий уже описывают
минимальную настройку и политику памяти.

## Goals / Non-Goals

**Цели:** добавить ограниченный контекст к существующему представлению и
подключить к нему оба входных сценария. Сохранить совместимость отчёта,
ограничения путей/согласия и обозначения свидетельств.

**Вне целей:** универсальное определение активных инструкций, парсеры нативных
конфигураций, новая система памяти, новые цели записи или новый backend живых
запусков.

## Decisions

1. Использовать `report --input FILE_OR_STDIN_DASH` с непосредственным объектом
   `{ agent, agentVersion?, cwd, targetPath? }`. Хост использует существующий
   ограниченный синтаксис ID. Версия — печатная строка ограниченной длины. Пути —
   канонические пути с `/` относительно проекта; cwd допускает `.`. Отклонять
   выход за пределы каталога, абсолютные пути, обратные слеши, управляющие символы,
   неизвестные поля и неверные типы до исследования состояния проекта. Контекст
   необязателен и передаётся вызывающей стороной.
2. Сохранить все существующие поля диагностики. Добавлять
   `instructions.taskScope` только при наличии контекста: основание контекста,
   выбранный профиль или статус неизвестного, отношения кандидатов к cwd и
   необязательному целевому пути, а также пределы оценки. Ядро отвечает за
   проверку/представление; root интегрирует вызывающую сторону CLI. Контекст не
   вызывает дополнительного чтения файловой системы или исполнения. Отношения
   путей лексические: они не разрешают символические ссылки и не отменяют
   исключения скана.
3. Распознанные обычные имена файлов инструкций позволяют показать отношения
   предков каталогов. Правила в нативных каталогах остаются условными/зависящими от
   хоста; один родительский каталог не позволяет отвергнуть их применимость.
   Все отношения остаются отдельными от применимости, приоритета, установленных
   версий, загрузки и использования в задаче. Не строить сопоставители по
   описательным строкам каталога.
4. Сохранить краткость инструкций: добавить общий вызов отчёта в scan/inventory
   и передавать контекст через agent architecture, verify и handoff.
   Использовать существующие правила единственного хранилища памяти и точного
   согласия без их дублирования.
5. Проверить чистую функцию представления, валидацию CLI и поведение без записи,
   затем провести ограниченные свежие агентские сессии с помощью исходных
   материалов на примерах без зависимостей: init, adopt и последующее
   чтение/использование/исправление памяти. Сохранить точные хэши кандидата,
   запросы, результаты, помощь и ошибки. Эти наблюдения не являются нативным
   автообнаружением хоста или репрезентативной матрицей моделей.

## Risks / Trade-offs

- Расположение могут принять за активное наследование → явные лексические
  обозначения и границы оценки, оговорки для нативных rules и регрессионные
  проверки отдельных поддеревьев.
- Переданный контекст могут принять за свидетельство установки → сохранять
  существующие `installedVersion` адаптера, загрузку/использование и проверки
  сохранённой сессии без изменения.
- Дополнительные параметры могут усложнить работу пользователя → необязательный
  внутренний ввод для агента; выводить его из сессии и спрашивать только о
  существенных неизвестных.
- Проверки снимков/строк не подтверждают рассуждение → отдельные наблюдения в
  свежих сессиях и независимое инженерное ревью.

## Migration Plan

Миграция сохранённой схемы и изменение версии не нужны. Существующие вызовы
отчёта сохраняются. Работа записывается в Unreleased; последующая подготовка
кандидата отвечает за минорный выпуск по SemVer. Удаление необязательного
ввода/представления и дополнений стадий восстанавливает прежнее поведение.
