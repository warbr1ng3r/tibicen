# Протокол приёмки до запуска

Зафиксирован до отправки свежим агентам 6 ноября 2026. Владелец одобрил пакет
реализации со свежими проверками. Root — оператор только сгенерированных примеров:
может одобрить точное предложение после просмотра диффов. Это не человеческая
оценка пользы и не согласие на изменения реальных пользовательских проектов.

## Кандидат и выполнение

Собрать два самостоятельных скилла в отдельный замороженный каталог, сохранить
SHA256SUMS и хэши исходников. Использовать свежих субагентов без истории родителя,
явно прочитать полный SKILL.md и работать только в назначенном примере. Сохранить
задания, отчёты, proposal, одобрение, apply/verify/status/report, защищённые хэши
и тесты проекта. Явно разрешена запись свидетельств вне примера; до одобрения
никаких записей в целевом проекте.

Без сети, установок, стороннего исполнения, платного API, учётных данных и запусков
нативных CLI. Это наблюдения агентов по переданным исходникам через субагентов
приложения. Выбранная целевая среда — вход примера, а не реально запущенный нативный
харнесс. Сохранять это различие во всех результатах.

## Случаи и критерии

| Случай | Исходное состояние и обычный запрос | Наблюдаемый результат |
| --- | --- | --- |
| I1 | Небольшое Node-приложение без инфраструктуры; минимально настроить свой team-agent и запомнить решения о датах и зависимостях | Верный init; фактическая команда проекта; taskScope с неизвестным хостом; один достаточный общий вход и максимум одно выбранное хранилище; точное предложение; приложение сохранено |
| A1 | Корневые инструкции с устаревшей командой, полезная память, намеренные русские инструкции поддерева; проверить настройку для задачи документации с выбранным ZCode | Объяснён и исправлен дефект корневой команды; явные root/cwd/target; различия поддерева сохранены; нет вывода о нативной загрузке из вложенности; сохранены хранилище и полезные записи |
| M1/M2 | Свежие рабочие агенты после I1/A1; явный первый шаг чтения из handoff; пример экспорта с датой, затем новое постоянное решение владельца | Чтение памяти через инструкции, применение формата даты UTC, исправление принятого значения без другого хранилища и потери независимого решения о зависимостях |

У каждого setup одна первая попытка. Неудача остаётся неудачей; исправление и
повтор имеют отдельный ID с объяснением изменённых байтов. Одобрение точного плана
— отдельное сообщение оператора, не поле proposal. Отдельно учитывать качество
настройки, структуру, поведение с помощью и нативную загрузку. Нативное наблюдение
в этом ограниченном протоколе недоступно и не считается успехом. Независимое ревью
проверяет выводы и сохранность. Канонический источник — [протокол](acceptance.md).

## Дополнение об изоляции до apply

Первое настоящее CLI-предложение I1 правильно показало обычный счётчик в домашней
папке пользователя вне области примера/свидетельств. Оно не одобрено и не применено;
исходный вывод сохраняется. Только для теста пересобрать тот же input через
замороженный first-party API `createProposal` с существующим явным параметром
`home`, указывающим на принадлежащую стенду `observations/<case>/runtime-home`.
Это помощь изоляции, а не повтор выбора продуктом или новый CLI-флаг. Сохранить
новый digest и отдельное одобрение оператора; тот же home передать в `applyPlan`.
Не менять HOME и настоящие данные пользователя. CLI scan/report/verify/status
и последующие агенты используют замороженную поставку. Для A1 действует та же
изоляция. Результат честно относится к более узкому выполнению с помощью API.
