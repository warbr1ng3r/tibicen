# Spec Delta

## ADDED Requirements

### Requirement: Init and adopt share a task-scoped explanation

Оба входных скилла SHALL использовать один доступный контекст хоста/версии,
корня проекта, рабочего каталога и предполагаемой задачи/пути, чтобы объяснять
сохранённые или предлагаемые инструкции. Объяснение SHALL давать одну
достаточную рекомендацию и конкретный шаг активации либо оставшуюся проверку.
Недостающий контекст SHALL оставаться явным без добавления обязательных вопросов
или вывода хоста по общим файлам.

#### Scenario: Initial setup starts from a simple request

- **WHEN** пользователь просит настроить агентов в проекте без агентской инфраструктуры
- **THEN** init получает команды проекта и доступный контекст задачи из разрешённого исследования
- **AND** объясняет минимальную настройку и первый шаг чтения/активации
- **AND** сохраняет файлы приложения и границу согласования точного плана

#### Scenario: An existing setup has intentional subtree differences

- **WHEN** adopt проверяет корневые и вложенные инструкции для конкретной задачи
- **THEN** объясняет относящиеся отношения каталогов и неизвестное, зависящее от хоста
- **AND** сохраняет намеренные различия, не считая разный текст конфликтом
- **AND** конкретный дефект получает адресное исправление либо результат без изменений

#### Scenario: An unknown host can read common instructions

- **WHEN** хост вне каталога поддерживает существующую работу с файлами и Node
- **THEN** рекомендация может использовать явный шаг чтения общего файла
- **AND** не выдумывает нативный приоритет, установленную версию или требование модели/провайдера

### Requirement: First-task handoff reuses the reviewed scope

Проверка и передача результата SHALL использовать рассмотренный контекст задачи
либо раскрывать его изменение. Существующие проверки памяти SHALL различать
структурную связь, свежее чтение, использование в задаче и принятое исправление с
сохранением несвязанных заметок. Недоступные наблюдения SHALL сохранять причины и
границы помощи.

#### Scenario: A later task depends on an accepted project decision

- **WHEN** свежий рабочий контекст следует согласованной настройке, а задаче нужно сохранённое решение
- **THEN** приёмка записывает, прочитано ли решение и повлияло ли оно на результат
- **AND** явно принятое исправление сохраняет несвязанные заметки
- **AND** наблюдение с помощью не устанавливает нативное автообнаружение или широкую совместимость
