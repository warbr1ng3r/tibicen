# Spec Delta

## ADDED Requirements

### Requirement: Read-only task context accompanies diagnosis

Отчёт SHALL принимать необязательные идентификатор harness, версию, рабочий
каталог относительно проекта и целевой путь от вызывающей стороны. Он SHALL
проверять весь контекст до исследования, сохранять существующие поля при
отсутствии ввода и отличать переданный контекст от наблюдаемой установки.
Контекст SHALL NOT разрешать новые чтения, записи, исполнение или обход файловой
системы.

#### Scenario: A nested task has instruction candidates in several subtrees

- **WHEN** контекст задаёт рабочий каталог и целевой путь внутри проекта
- **THEN** диагностика показывает отношения каталогов кандидатов к обоим путям
- **AND** условные или зависящие от хоста rules сохраняют явный предел оценки
- **AND** расположение не устанавливает активный приоритет или загрузку

#### Scenario: Unknown or absent host information

- **WHEN** передан допустимый хост вне каталога либо контекст не передан
- **THEN** неизвестный хост остаётся неизвестным, а отсутствие контекста сохраняет существующее поведение
- **AND** ни один случай не подставляет известный хост и не выдумывает установленную версию

#### Scenario: Invalid context fails without side effects

- **WHEN** контекст содержит неизвестные поля, неверные сведения идентификатора/версии или небезопасные пути
- **THEN** вызов отклоняет ввод до исследования проекта или сохранения отчёта
- **AND** state, файлы приложения и разрешения не меняются

### Requirement: Context explanation retains its evidence limits

Диагностика контекста задачи SHALL отдельно обозначать переданный контекст,
документированные сведения о хосте и лексические отношения путей. Она SHALL
оставлять ожидаемую применимость предметом оценки хоста/версии/конфигурации, а
текущие загрузку/использование — непроверенными без соответствующих наблюдений.
Исключённые пути и частичная инвентаризация SHALL сохранять свои пределы охвата.

#### Scenario: A documented workspace-only host sees a nested file

- **WHEN** кандидат расположен выше целевого пути, но нативный контракт хоста не установлен
- **THEN** диагностика не объявляет кандидата активным по отношениям предков каталогов
- **AND** вместо этого она указывает оставшуюся оценку хоста/сессии

#### Scenario: Rules use conditional matching

- **WHEN** нативный каталог rules содержит кандидата с условным или зависящим от хоста поведением
- **THEN** диагностика отмечает необходимость оценки поведения без трактовки как безусловного наследования поддеревом
- **AND** ни один кандидат не объявляется неотносящимся к задаче только по каталогу этого файла rules
