# Proposal

## Why

The returned 1.5.5 ZCode packet contains a failed ordinary task: the agent implemented an owner decision in only one call path and amended memory to describe that narrower boundary. Existing guidance separates decisions from facts, but its copyable maintenance policies do not explicitly say that verified implementation is not authority to revise an owner's decision.

## What Changes

- Clarify that owner-approved meaning and scope remain authoritative until the user changes them; record implementation mismatches separately.
- Carry the clarification into the copyable policy and both init/adopt examples, with a content regression and paired project guide.
- Assess the returned evidence without regrading the failed task or weakening the memory-only fixture's answer-leak guard. Document that combined instruction/memory observations require a separate prospective protocol.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `project-memory`: make the authority boundary in later memory maintenance explicit.

## Impact

Installed memory guidance, its instruction-content test, paired project documentation and the returned-observation assessment. No runtime/schema change, new store, dependency, model/API call, version bump or publication. Guidance completion is not a new behavioral pass.
