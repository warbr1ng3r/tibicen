# Spec Delta

## Purpose

Описать подключение проверяемых рабочих процессов и повторное применение настройки с явным происхождением материалов. Первый ограниченный адаптер OpenSpec включён в ближайший выпуск; остальные адаптеры, общая составная поставка, схема контекста и переносимый манифест остаются будущими расширениями.

## ADDED Requirements

### Requirement: Composite sources retain material provenance
Составная поставка SHALL различать обёртку и действительные источники каждого выбранного материала, проверять их доверие, версии и лицензии по общим правилам источников. Необходимые ссылки, шаблоны и вспомогательные файлы SHALL проверяться на полноту; преобразование сохраняет исходные материалы и результат. Неподдержанная поставка получает gap вместо подтверждения по одной обёртке.

#### Scenario: A wrapper remains unchanged while its original changes
- **WHEN** обёртка ссылается на изменившийся оригинал с другой лицензией
- **THEN** проверяются оба источника и лицензии; каждый установленный файл прослеживается до материала либо преобразования

#### Scenario: A required referenced resource is absent
- **WHEN** для выбранного процесса не хватает шаблона или связанного файла
- **THEN** неполнота видна как gap, компонент не объявляется полностью подключённым

### Requirement: Context maps describe configuration without inventing loading
Краткая схема SHALL связывать точку входа, правила, скиллы и справочные материалы по уже собранным сведениям, показывать способ подключения и поддержанное условие чтения. Неизвестная связь SHALL отмечаться на месте; порядок и постоянная загрузка не выводятся из одной ссылки. Фактическая загрузка подтверждается отдельными наблюдениями; сохранение схемы подчиняется правилам отчёта.

#### Scenario: A conditional skill contains a broken reference
- **WHEN** строится схема подключённого контекста
- **THEN** отсутствующая связь видна, условный материал не обозначается постоянно загружаемым
- **AND** схема не требует компилятора контекста или точного подсчёта токенов

### Requirement: Process frameworks use bounded verified adapters
Адаптер SHALL описывать проверенные версии, точные служебные пути, эффекты инициализатора, обновление и проверку подключения. Установка CLI имеет отдельные версию, место и согласие; не становится обязательной зависимостью Tibicen. Инициализатор допускается по контракту адаптера и общим границам исполнения; защищённое приложение и неконтролируемые эффекты оставляются ручным шагом. Существующий процесс может сохраняться.

#### Scenario: A process is initialized or adopted
- **WHEN** поддержанный фреймворк подключают с нуля либо к существующему процессу
- **THEN** стадии, артефакты, критерии перехода и команды доступны через выбранного агента в новой сессии
- **AND** наличие одного CLI не считается интеграцией; загрузка и типичная задача проверяются отдельно

#### Scenario: A framework directory contains protected application files
- **WHEN** адаптер перечисляет служебные пути внутри каталога фреймворка
- **THEN** это не разрешает менять соседние файлы или защищённое приложение; небезопасный инициализатор остаётся ручным шагом

### Requirement: The first process adapter supports an optional complete workflow
Первый выпуск SHALL поддерживать ограниченную интеграцию OpenSpec с нуля и в существующем проекте. Выбор процесса SHALL учитывать потребность и сохранять достаточную существующую настройку. Установка CLI SHALL согласовываться отдельно; CLI и генерируемые им скиллы SHALL не поставляться внутри Tibicen. Готовность SHALL требовать наблюдаемой загрузки и работы процесса в новой сессии на заявленных версиях.

#### Scenario: OpenSpec is initialized for a project that needs specifications
- **WHEN** пользователь согласовал точный план подключения поддержанной версии OpenSpec
- **THEN** служебная структура, инструкции, шаблоны и команды доступны выбранному агенту в новой сессии
- **AND** агент проходит согласованный цикл спецификация → план → реализация → проверка; одного успешного init или списка файлов недостаточно

#### Scenario: An existing OpenSpec process is adopted and updated
- **WHEN** проект уже содержит процесс, локальные изменения шаблона и пользовательские артефакты
- **THEN** план сохраняет полезные решения и показывает каждую предлагаемую замену; повтор не создаёт лишних изменений
- **AND** обновление проверяется отдельным планом, рабочей задачей и историей без потери исходных материалов

#### Scenario: A process version or initializer effect is unsupported
- **WHEN** версия не проверена либо инициализатор требует неизвестных эффектов, правки приложения, глобальных настроек или автоматического коммита
- **THEN** автоматическое применение не начинается; показан отказ или ограниченный ручной шаг без ложного подтверждения подключения

#### Scenario: A raw proposal removes the missing CLI action
- **WHEN** у процесса нет зарегистрированного CLI, а сырой согласованный план удаляет обязательный шаг установки, помечает его done или делает необязательным
- **THEN** общий валидатор отклоняет план до записи; новый digest не заменяет проверку обязательного подключения
- **AND** обычный файловый setup остаётся manual-action-required до регистрации проверенных ресурсов CLI

#### Scenario: A new CLI binding conflicts with preserved instructions
- **WHEN** установка или перенос CLI меняет команду вызова, а сохранённая локальная инструкция продолжает указывать прежнюю
- **THEN** новое предложение и применение сырого плана отклоняются до записи
- **AND** продолжение требует явного обновления команды в сохранённом тексте либо отдельно согласованной замены инструкции; полезные локальные правки не перезаписываются автоматически

#### Scenario: Existing rules already provide a sufficient process
- **WHEN** потребность проекта покрыта принятой настройкой без нового фреймворка
- **THEN** Tibicen объясняет сохранение процесса и не устанавливает OpenSpec ради наличия адаптера

### Requirement: Portable configuration is declarative and versioned
Переносимый манифест SHALL быть отдельным от паспорта и пресета, иметь версию схемы, имя/версию набора, применимость, источники, параметры адаптеров, агентов и стадии процесса. Свои материалы имеют происхождение. Применение SHALL сопоставлять набор с фактическим проектом, явно разрешать конфликты в предложении и сохранять в паспорте версию набора и отклонения. Пресет заполняет только незаданные предпочтения; согласие не переносится из манифеста.

#### Scenario: A configuration is reused across projects
- **WHEN** один набор применяют к двум совместимым проектам и одному несовместимому
- **THEN** совместимые сохраняют заданные источники, несовместимый получает объяснение; локальные отклонения показываются явно
- **AND** совпадение манифеста не доказывает воспроизводимость транзитивной среды

#### Scenario: Preset or user intent conflicts with the manifest
- **WHEN** предпочтения пресета, запрос пользователя либо принятые решения проекта расходятся с набором
- **THEN** рекомендуемая редакция обычного предложения разрешает конфликт явно; порядок загрузки файлов не выбирает победителя

### Requirement: Portable inputs fail visibly and export deliberately
Манифест SHALL не исполнять произвольную программу установки: действия создают известные адаптеры с обычными проверками доверия и согласия. Неизвестная схема, компонент или параметр и отсутствующий адаптер SHALL давать отказ либо видимый gap до применения; молчаливое частичное применение запрещено. Закреплённые источники меняются только отдельным предложением. Экспорт SHALL отделять материалы набора от состояния проекта и секретов по правилам пользовательских артефактов.

#### Scenario: An unsupported configuration is imported
- **WHEN** неизвестны схема, компонент, параметр либо требуемый адаптер отсутствует
- **THEN** причина отказа или gap показана до применения, произвольный код из манифеста не запускается

#### Scenario: A locally modified configuration is exported
- **WHEN** пользователь явно просит экспорт набора
- **THEN** экспорт сохраняет нужные источники и материалы без секретов и фактического состояния исходного проекта
- **AND** обновление закреплённых версий не происходит скрыто
