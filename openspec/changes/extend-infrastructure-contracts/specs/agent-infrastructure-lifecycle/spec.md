# Spec Delta

## ADDED Requirements

### Requirement: Versioned managed blocks preserve untouched bytes
Обработчик SHALL различать отсутствие маркеров, одну корректную пару и неоднозначные пары, распознавать версию формата и побайтно сохранять области, не меняемые планом. Без маркеров добавляются блок и явно показанный разделитель; корректный блок меняется или удаляется на прежнем месте; совпадающий текст не порождает повторной замены. Повреждение или неизвестная версия SHALL требовать явного разбора и точного диффа исправления.

#### Scenario: Markers are duplicated or malformed
- **WHEN** пары повторяются, вложены, переставлены или не замкнуты
- **THEN** автоматическая замена не выполняется, место неоднозначности показано
- **AND** совпадение хэша файла не делает повреждённый блок корректным

#### Scenario: A block is empty or moved within a file
- **WHEN** корректный блок пуст или перемещён вместе с маркерами
- **THEN** он обрабатывается на фактическом месте; нетронутые байты, включая CRLF, сохраняются

#### Scenario: Marker format needs conversion
- **WHEN** обнаружен известный старый формат либо неизвестная версия
- **THEN** старый формат распознаётся явно, неизвестный не переписывается по догадке; преобразование показывается отдельным точным диффом

#### Scenario: An approved managed block is removed
- **WHEN** согласованный план удаляет корректный блок
- **THEN** блок вместе с маркерами удаляется на прежнем месте, а остальные нетронутые области сохраняются побайтно

### Requirement: Updates reconcile ownership across three states
План обновления SHALL сопоставлять прежний состав из паспорта, фактические файлы и выбранную новую поставку. Для локальной правки явно выбирается merge/preserve/replace; исчезновение upstream само по себе не разрешает удаление. Паспорт SHALL различать исходную поставку и итоговый локальный файл, исключать удалённое из установленного состава и сохранять историю.

#### Scenario: Local changes and removed upstream resources coexist
- **WHEN** файл изменён локально, другой исчез из поставки, а рядом появился пользовательский файл
- **THEN** план явно решает судьбу первых двух, не присваивая соседний файл компоненту
- **AND** локальная версия сохраняет источник без ложного заявления о точном совпадении SHA

#### Scenario: A new upstream resource collides with a foreign path
- **WHEN** ресурс новой поставки занимает существующий чужой путь
- **THEN** фиксируется конфликт, файл автоматически не присваивается компоненту

#### Scenario: An older passport cannot represent the new guarantees
- **WHEN** схема паспорта несовместима с требуемой записью состава или происхождения
- **THEN** до записи проверяется совместимость, выполняется явный отказ либо согласуется точное преобразование
- **AND** прежняя запись не объявляется соответствующей новым гарантиям без проверки и история не теряется

### Requirement: Resume reconciles interrupted writes without inferring command execution
После прерывания state SHALL позволять сравнить исходное, согласованное итоговое и фактическое состояние, включая отсутствие файла. Исходное требует записи, итоговое не требует повторной записи, иное требует разбора. Совпадение файла SHALL не доказывать автора записи или исход команды; повтор команды с неизвестным исходом отдельно обосновывается в оставшемся плане с новым согласием.

#### Scenario: A file changed but its operation result was not recorded
- **WHEN** сбой произошёл после замены файла до записи результата
- **THEN** согласованный конечный файл распознаётся без повторной записи; неожиданный файл не затирается
- **AND** исходный baseline и история сессии сохраняются

#### Scenario: A crash occurs at a session boundary
- **WHEN** сбой введён до замены, при записи паспорта или перед удалением state
- **THEN** повторный разбор восстанавливает известные сведения о применении без выдумывания результата команд

#### Scenario: A resumed state has an unsupported schema
- **WHEN** новая версия не может достоверно прочитать формат сохранённой сессии
- **THEN** автоматическое продолжение не пишет файлы и показывает отказ либо отдельный план миграции с новым согласием
- **AND** исходная история не подменяется новой успешной сессией

#### Scenario: A command ended without a durable result
- **WHEN** процесс прерван после запуска команды до сохранения её исхода
- **THEN** существующий ожидаемый файл не подтверждает исполнение; неизвестный setup блокирует продолжение, проверка без повтора остаётся unverified
- **AND** повтор возможен по точной команде с отдельным обоснованием в новом плане и новым согласием

#### Scenario: A passport replacement was interrupted
- **WHEN** сохранено точное намерение записи паспорта и процесс прерван до либо после замены
- **THEN** прежний или согласованный паспорт распознаётся; паспорт вне обоих состояний не затирается
- **AND** история операций, происхождения и перехода схемы сохраняется при продолжении новым планом той же сессии

### Requirement: Multiple tools share traceable rule revisions
Настройка одного проекта для нескольких coding tools SHALL сохранять согласованную редакцию общих правил и стадий процесса через форматы их адаптеров. Необходимые копии SHALL иметь проверяемую связь для обнаружения устаревшей редакции при обновлении. Это требование не задаёт распределение задач или оркестрацию агентов.

#### Scenario: Shared rules are updated for two coding tools
- **WHEN** два выбранных инструмента настроены в одном проекте и общие правила меняются
- **THEN** применимая матрица форматов и проверки обнаруживает старую копию вместо незаметного расхождения

#### Scenario: A stale copy has a matching whole-file hash
- **WHEN** файл соответствует своему фактическому хэшу, но тело связанного блока содержит прежнюю редакцию
- **THEN** структурная проверка сообщает устаревшую копию по связи с общей редакцией
- **AND** различия окончаний строк и нетронутые пользовательские области не меняют редакцию общего текста

#### Scenario: An interrupted update continues with another plan
- **WHEN** часть связанных копий записана до прерывания и согласован новый оставшийся план
- **THEN** регистрация обеих копий и история редакций сохраняются, старая или отсутствующая копия не объявляется согласованной
- **AND** исправление выполняется только по показанному диффу и новому согласию

#### Scenario: A shared target is unsupported or silently omitted
- **WHEN** версия/точка входа отсутствует в проверенном контракте адаптера либо готовый план молча исключает зарегистрированную копию
- **THEN** применение отклоняется до записи вместо выдумывания совместимости или потери связи
