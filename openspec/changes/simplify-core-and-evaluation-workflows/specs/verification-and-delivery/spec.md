# Spec Delta

## ADDED Requirements

### Requirement: Structural verification reconciles recorded infrastructure

Структурная проверка SHALL сверять последний зарегистрированный состав инфраструктуры с фактическими файлами и текущими согласованными изменениями. Отсутствие файла в новом скане SHALL не скрывать его исчезновение. Проверка SHALL сообщать расхождения без записи или автоматического восстановления.

#### Scenario: A previously applied skill disappears

- **WHEN** после применения AGENTS.md и файла скилла файл скилла удалён вне Tibicen
- **THEN** отдельная проверка сообщает отсутствующий путь и не возвращает `passed`
- **AND** проверка не создаёт файл и не меняет паспорт

#### Scenario: A no-change improvement encounters missing owned resources

- **WHEN** повторный запуск улучшения без явно согласованного удаления обнаруживает исчезнувший зарегистрированный ресурс
- **THEN** итоговая проверка сообщает расхождение, а прежняя принадлежность остаётся доступна в составе или истории
- **AND** отсутствие не переобозначается как беспроблемное сохранение компонента

#### Scenario: A deliberate deletion supersedes an older addition

- **WHEN** текущий согласованный план удаляет ранее добавленный путь
- **THEN** проверяется отсутствие после удаления, а прежняя запись не требует восстановить файл
- **AND** несколько сессий учитываются по последней применимой операции каждого пути

#### Scenario: Local changes require review

- **WHEN** зарегистрированный ресурс отличается от последнего согласованного содержимого
- **THEN** проверка отражает расхождение, сохраняя локальные байты
- **AND** явно согласованное новое содержимое становится текущим ожиданием без ложной ошибки по старой версии

#### Scenario: A permission-only write has not happened yet

- **WHEN** для зарегистрированного файла согласовано только изменение режима доступа и сессия прервана до записи
- **THEN** равенство content hashes не означает применения нового режима; проверка и recovery сохраняют прежние ожидания
- **AND** после наблюдаемой записи новый hash/mode результат учитывается вместе; legacy без известного режима не получает выдуманного permission baseline

#### Scenario: Repeated approved operations keep chronological order

- **WHEN** одна resumed сессия применяет A → B → A → B и сохраняет историю, затем выполняется пустое улучшение
- **THEN** последнее вхождение повторной операции остаётся последним при объединении истории
- **AND** отдельная проверка ожидает фактическое согласованное B, включая компонентные изменения, общие правила и процесс

#### Scenario: The owner approves current local content

- **WHEN** владелец локально меняет зарегистрированный файл A на B, затем явно предлагает точное полное содержимое B и согласовывает digest
- **THEN** предложение сохраняет операцию принятия B, хотя предлагаемые bytes/mode совпадают с текущими; после применения B становится ожиданием
- **AND** обычный повтор уже согласованного неизменённого файла по-прежнему не создаёт лишней операции

#### Scenario: A project has no recorded baseline

- **WHEN** агентская инфраструктура существует, но Tibicen ещё не регистрировал её состав
- **THEN** доступная структурная проверка сохраняется в пределах наблюдаемых файлов
- **AND** неизвестный прежний состав не выдумывается и наличие файлов не доказывает загрузку агентом

#### Scenario: Managed resources retain their independent content contracts

- **WHEN** общие правила сохраняют зарегистрированную редакцию при допустимых правках владельца вне блока либо согласованный процесс сохраняет локальные инструкции
- **THEN** содержимое проверяется по контракту общих правил или процесса, а не по устаревшему хэшу всего файла
- **AND** пропавшие пути и точные байты текущих согласованных записей по-прежнему проверяются

#### Scenario: An older passport has only upstream hashes

- **WHEN** поддержанный паспорт schema 1 содержит upstream-хэш, но не фактический installed hash
- **THEN** проверка не выдаёт upstream-хэш за известный baseline локального содержимого
- **AND** явная согласованная миграция фиксирует фактическое состояние без выдуманного подтверждения происхождения

### Requirement: Development diagnostics are explicit and bounded

Локальный диагностический вход SHALL по умолчанию оставаться dry-run без исполнения модели. Он SHALL сохранять явные profile/provider/model/auth и лимиты поддержанного запроса либо фиксированный `blocked` с нулём модельных запросов. Отсутствующие условия и неподдержанный маршрут SHALL не вызывать другой профиль, модель или платный fallback. Этот вход SHALL оставаться инструментом разработки вне обоих устанавливаемых скиллов.

#### Scenario: Help or import needs no execution

- **WHEN** модуль импортируется либо команда вызывается без аргументов или со справкой
- **THEN** ни драйвер, ни процесс, ни модель не запускаются
- **AND** выходные файлы не создаются

#### Scenario: A dry-run or unsupported route is recorded

- **WHEN** выбран dry-run либо native-запрос не содержит поддержанного полного контракта и подходящего сохранённого preflight
- **THEN** новый диагностический артефакт сообщает `blocked` и `modelRequests: 0`
- **AND** даже полный dry-run не запускает модель; пути config/preflight, credentials и сырые ошибки в результат не копируются

#### Scenario: An offline diagnostic is reproducible

- **WHEN** явно выбран offline без native-конфигурации
- **THEN** встроенный fake driver проверяет ограниченный протокол без credentials и сетевого модельного запроса
- **AND** параметры и парный отчёт сохраняются как calibration, без заявления живой приёмки Tibicen

#### Scenario: Output reservation precedes execution

- **WHEN** выходной путь уже существует, является симлинком либо занят конкурентным вызовом
- **THEN** проигравший вызов отказывает до чтения config и исполнения драйвера
- **AND** прежние байты сохраняются; состояние команды и результаты эксперимента различаются

#### Scenario: Native execution retains the existing contract

- **WHEN** явно выбран native с поддержанными profile/provider/model/auth, сохранённым preflight и точным ограниченным бюджетом
- **THEN** вход делегирует существующему native-маршруту без расширения авторизации или лимитов
- **AND** неподдержанный API/модель не получают исполнения; фактический бюджет проверяется на fake CLI, а не живыми запросами

### Requirement: Selected judge evidence retains observable links

Выбранные основания судьи SHALL связывать отрывки с применимыми замороженными критериями и наблюдёнными событиями, раскрывать происхождение и явное усечение. Отбор SHALL не принимать полный private trace или oracle и SHALL сохранять прежнюю рубрику, формат verdict/cohort и совместимость пакетов без новых optional metadata.

#### Scenario: A source read is only partly observed

- **WHEN** команда чтения не совпадает с источником, завершилась ошибкой либо вывела только часть ожидаемого содержимого
- **THEN** наблюдённая команда может сохраниться как основание действия, но загрузка источника не выдумывается
- **AND** подтверждённое чтение связывает путь, hash содержимого, tool call и событие той же стадии

#### Scenario: Evidence exceeds its bounds

- **WHEN** текст отрывка или число выбранных оснований превышает действующий предел
- **THEN** отбор остаётся ограниченным и явно сообщает объём усечения
- **AND** очистка/проверка секретов выполняются до усечения, а отсутствие действия не превращается в положительный вывод

#### Scenario: New links coexist with historical packets

- **WHEN** судья или человек ссылается на новый отрывок другого критерия либо обрабатывается старый пакет без metadata
- **THEN** несовместимая новая ссылка отклоняется, а старый пакет проходит прежнюю валидацию
- **AND** сохранённые исторические результаты не переписываются и не получают новой приёмки автоматически
