# Design

> Public source snapshot: detailed local development records are omitted. Historical verification summaries below retain their original limits.

## Context

Основания и воспроизведение — в анализе. CLI и runtime строят разные проверяемые составы из текущего скана; записи исчезнувших файлов могут теряться также при пересчёте компонентов. Eval runner совмещает запуск процессов, сценарии и выбор оснований; сходные ограниченные запуски присутствуют в preflight и probe.

## Goals / Non-Goals

**Goals:** один владелец каждого инварианта, короткие публичные интерфейсы внутренних модулей и отдельные быстрые проверки при сохранении общего gate.

**Non-Goals:** универсальный orchestration framework, новая схема паспорта по умолчанию, произвольное исполнение конфигов, расширение поддержки агентов или снижение продуктовой приёмки.

## Decisions

- **Состав сверяется в одной процедуре.** Последняя операция по пути из зарегистрированного состояния, восстановленный baseline и текущие согласованные изменения задают ожидания; фактический скан добавляет неизвестные ранее пути. Исчезновение нельзя потерять до построения ожиданий. Альтернатива — сравнивать только installed[] текущего плана — уже теряет отсутствующие файлы. Простое объединение всей истории ошибочно требует вернуть согласованно удалённые файлы. Состояние pending/resume сохраняет действующие правила восстановления; ожидания не разрешают запись.
- **Фазы apply выделяются после исправления состава.** Выделить завершение/подготовку паспорта с прежними входами и результатами. Журнал команд и atomic write остаются в действующих границах. Альтернатива — переписать весь apply — резко увеличивает риск сохранности без доказанной пользы.
- **Один ограниченный запуск процессов внутри стенда.** Общая низкоуровневая процедура владеет таймаутом, прекращением дерева потомков и ограничением вывода. Передача env, авторизация, preflight policy и интерпретация событий остаются у профилей. Не объединять её с продуктовым исполнением команд: у них разные контракты доверия.
- **Основания отдельно от сценарного orchestration.** Выбор связывает наблюдённые чтения/реплики/команды с конкретным критерием, сохраняет происхождение и очистку. Усечение обозначается явно. Снять лимиты или передать весь private trace судье — не решение. Конкретные math/OpenSpec проверки выделяются как именованные функции, без plugin registry.
- **Команды по областям дополняют общий gate.** Core/evals/site получают прямые scripts поверх существующих инструментов; `pnpm test` по-прежнему проверяет всё. Измерять elapsed для сравнимой команды и среды, не обещать процент ускорения по числу строк.
- **Один воспроизводимый диагностический вход.** Без модели он валидирует параметры и выполняет offline/dry-run. Живой режим использует существующий явно выбранный профиль и требует отдельного разрешённого контракта; отсутствие маршрута и бюджета — `blocked`, без fallback. Исполняемый `.mjs` host driver остаётся доверенным кодом, а не конфигурацией от пользователя.
- **Данные матрицы разбиваются по существующим группам.** Сохраняются ID, число сценариев, SHA/содержимое фикстур, приватность ожиданий и общий freeze/loader. Разбиение не меняет frozen cohorts и не объявляет прежнюю серию приёмкой нового дерева.

## Risks / Trade-offs

Ревью накопленного diff уточняет три границы recorded scope: завершённость компонента сравнивает hash и известный mode, chronological history сохраняет последнее вхождение повторной операции, а явное полное одобрение текущих owner bytes не теряется как clean no-op при расхождении с recorded baseline. Используются существующие scope и journals без новой схемы; обычные clean no-op остаются пустыми.

- Исторический состав содержит повторные операции и локальные правки → регрессии для удаления/изменения/повторной сессии/resume; не восстанавливать автоматически.
- Выделение модуля может потерять обработку завершения потомков/секретов → сохранить существующие отрицательные тесты и проверить всех трёх потребителей supervisor.
- Два исполнителя правят native-runner одновременно → сначала supervisor, затем evidence; общий orchestrator имеет одного владельца в каждой волне.
- Новая команда выглядит подтверждением native-профиля → dry-run, preflight, старт и результат обозначаются отдельно.
- Число строк может уменьшиться без улучшения интерфейса → принимать по уменьшению дублируемых решений и связности, сохранению контрактов и проверкам, без целевой квоты строк.

## Migration Plan

Выполнять четыре пакета из roadmap, назначая непересекающиеся пути. Сначала correctness и отдельные checks, затем внутренние выделения, затем диагностический вход/полнота оснований, затем общая приёмка. Форматы сохраняются; необходимость миграции или второго агента OpenSpec становится отдельным решением, а не попутным рефакторингом. Откат — возврат конкретной правки без переписывания истории и без преобразования пользовательских данных.
