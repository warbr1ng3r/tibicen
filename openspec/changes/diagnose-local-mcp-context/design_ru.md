# Design

## Context

См. [proposal](proposal.md). Прежние `validateMcpConfig`/`planMcpChanges` уже
валидируют проектный JSON Claude/Cursor, имена ссылок окружения и точные границы
доверия. CLI пока не передаёт параметры целевого окружения. Codex остаётся ручным
TOML-помощником. Датированное исследование выявило несовпадения источника,
контекста и формата; свежая официальная документация Gemini/OpenCode подтверждает
различия структуры и нативные команды, способные запускать серверы.

## Goals / Non-Goals

**Цели:** одна ограниченная диагностика сервера, безопасное чтение файлов и
конкретная рекомендация init/adopt. Повторно использовать прежние ограничения
разбора, чтения и записи.

**Не входит:** универсальный поиск источников, новые автоматические механизмы
записи, запуск/handshake исполняемого файла, раскрытие shell-переменных,
подстановка секретов/файлов, глобальное чтение домашней папки, новый сервис
памяти/runtime или ещё один длительно работающий стенд оценки.

## Decisions

1. Добавить `mcp-diagnose --root ROOT --input FILE_OR_STDIN_DASH`. Прямой запрос
   метаданных: `{agent, agentVersion?, server, format?, sources:[{path}],
   effectiveSource?, launch?}`. Не более четырёх уникальных канонических путей
   относительно корня; текст/значения в запрос не принимаются. Для OpenCode
   обязателен `format: opencode-v2`; неизвестная версия не означает контракт V2.
   Другие известные профили выбирают документированное чтение; неизвестные
   инструменты сохраняют ручной исход.
2. Ядро экспортирует строгий валидатор запроса и чистую функцию
   `diagnoseMcp(request, configs: Map<string,string>)`. CLI валидирует запрос до
   исследования, читает разрешённые источники прежним `readProjectFile` с лимитом
   1 MiB и запрещёнными путями незавершённого плана, затем передаёт текст внутри
   кода. Недоступные записи карты остаются непроверенными; текст ошибок не
   возвращается. Для подготовки stdin сырые настройки не нужны в контексте агента.
3. Диагностировать одно выбранное имя во всех источниках. `effectiveSource` —
   переданный вызывающим выбор для этого сервера, а не наблюдаемое нативное
   полномочие. Сохранять статусы кандидатов, не угадывать порядок, не сливать записи
   и не утверждать, что входы проекта покрывают глобальные, управляемые или
   сессионные источники. Вывод содержит источник/путь/статус, имена окружения и
   фиксированные причины, без значений команды/аргументов/настроек.
4. Claude/Cursor повторно используют прежнюю валидацию; однозначный JSON-парсер
   получает минимальный экспорт для Gemini/OpenCode. Gemini использует
   `mcpServers`, строку команды, `args`/`env` и необязательный `cwd`; URL-поля
   приоритетнее и остаются неподдержанными. Внешнее включение неизвестно,
   переданные политики allowed/excluded сохраняются. OpenCode V2 использует
   `mcp.servers`, тип local, массив команды, `environment`, необязательный `cwd`
   и `disabled`. Неподдержанная/неоднозначная структура остаётся ручной и не
   переводится догадками. Значения файлов или окружения не разрешаются.
5. `launch` принимает только `targetContextKnown`, `availableEnvNames`,
   `executableAvailable`, `cwdAvailable`. Имена/булевы значения — переданные
   сведения; false/true не устанавливают целевой контекст, если
   `targetContextKnown` не равен true. Пропуски остаются непроверенными. Не делать
   выводы из `process.env`/PATH. Соединение/использование остаются непроверенными
   при любых этих наблюдениях.
6. Результат исправления называет прежний поддержанный механизм записи только
   для его точного проектного пути; остальные цели сохраняют ручное нативное
   действие. Устанавливаемые инструкции объясняют один результат и ту же
   повторную проверку с сохранением точного согласования. `gemini mcp list` и
   `opencode mcp list` потенциально исполняют код, а не читают до согласования.
   Поддерживать одну краткую секцию EN/RU и сводную проверку.

## Risks / Trade-offs

- Недоверенные настройки могут содержать секреты → ограниченное чтение и
  фильтрация только внутри Node, фиксированный словарь вывода, без сырых ошибок
  парсера или значений команды/аргументов/окружения.
- Переданные сведения источника/запуска могут ошибаться → основание остаётся
  переданным вызывающим, нативное соединение/использование и ненаблюдавшиеся
  области сохраняются непроверенными.
- Разрешённый файл недоступен или исключён → сохранять результат недоступного
  источника, а не отсутствующего сервера; не расширять доступ и не читать ссылки.
- Новое чтение может выглядеть как расширение записи → прежние пути и проверки
  доверия сохраняются, у других форматов явные ручные исходы.

## Migration Plan

Только дополнительная команда; сохранить прежние `mcp-verify`, схемы хранения и
отчёт с контекстом задачи. Работа остаётся Unreleased, корневая версия не меняется
до подготовки кандидата. Зависимости и выпуск для реализации не нужны.
