# Spec Delta

## ADDED Requirements

### Requirement: Init and adopt explain actionable MCP outcomes

Both entry flows SHALL connect a useful MCP request or symptom to the selected
server, effective-source evidence, current configuration and minimum necessary
repair or native follow-up. Existing supported writers and exact consent SHALL
remain authoritative. Native commands that can start servers SHALL retain their
execution/trust boundary; a diagnostic name SHALL NOT imply read-only execution.

#### Scenario: Supported record needs one correction

- **WHEN** a confirmed supported local source has a demonstrated configuration defect
- **THEN** the agent proposes the exact necessary upsert/remove through the existing writer
- **AND** unrelated records, settings and owner decisions remain unchanged
- **AND** the same scoped diagnosis is repeated after approved repair without claiming connection

#### Scenario: Native source or target process remains unknown

- **WHEN** useful diagnosis cannot establish source or launch context from available permitted evidence
- **THEN** the agent explains that precise limitation and one native next step
- **AND** it neither guesses a path nor weakens folder trust, secret filtering or disable choices
- **AND** it does not force a new questionnaire or host/model switch

#### Scenario: A valid setup needs no change

- **WHEN** no necessary correction is established in the inspected scope
- **THEN** the result can preserve the configuration with stated limits
- **AND** it creates no new session or component just to record activity
