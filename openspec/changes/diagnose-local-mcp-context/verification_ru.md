## Реализованное поведение

- `mcp-diagnose` принимает только выбранные хост/версию/сервер, до четырёх
  проектных путей и необязательные переданные сведения об источнике/запуске.
- Ограниченное чтение обычных файлов сохраняет исключения проекта. Текст остаётся
  внутри first-party Node; в результате нет конфига, значений команд, аргументов
  и env, сырых исключений и содержимого файлов подстановки.
- Четыре ограниченных reader: Claude/Cursor JSON, Gemini CLI JSON и явный OpenCode
  V2 JSON. Порядок источников не объединяет записи; выбранный источник и
  доступность запуска остаются переданными сведениями, не нативным доказательством.
- Обе ветки используют один маршрут от симптома к действию. Только установленный
  дефект синтаксиса ссылки в точном существующем writer-пути получает этот ремонт.
  Отсутствие env/executable/cwd ведёт к точной нативной проверке/проверке окружения.
  Прежние writers, отключения и доверие исполнению сохранены.

## Ограничения и документация

Это офлайн-проверки настройки/исправления. MCP handshake, обнаружение инструментов,
нативный клиент, модельная оценка и человеческая польза не наблюдались. Переданные
имена/булевы значения не доказывают установленную версию или целевой запуск.
Нативные list/status могут запускать серверы и сохраняют обычное доверие/согласие.
Платный API, учётные данные и сетевое выполнение не использовались.

Парные руководства содержат выполненные stdin-примеры и датированные первичные
источники; установленная инструкция независима от dev OpenSpec. Markdown исключён
из Prettier; ссылки, переводы и пробелы проверяются при закрытии. Поведение сайта
не менялось, свежая браузерная матрица вне пакета. Канонический [отчёт](verification.md).
