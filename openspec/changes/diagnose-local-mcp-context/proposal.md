# Proposal

## Why

Existing MCP checks validate selected local records but do not explain which
source defines the server or why apparently valid settings still yield no tools.
The owner approved a complete diagnosis/repair workflow after the 1.3 research
and task-aware setup packet, without routine approval pauses.

## What Changes

- Add a read-only single-server diagnosis with explicit sources, selected host/
  version, disabled/override state and target launch observations.
- Read permitted project settings through a bounded first-party boundary; return
  names/status only, never config text, command/argument or environment values.
- Support existing Claude/Cursor JSON plus bounded Gemini JSON and explicitly
  selected OpenCode V2 JSON readers. Preserve all existing mutation contracts.
- Connect init/adopt to one native-first explanation and exact supported repair
  or remaining native action, with no implicit MCP launch or forced questionnaire.
- Complete focused fixtures, standalone CLI acceptance and independent review in
  one consolidated verification record with adjacent Russian translations.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `verification-and-delivery`: bounded redacted MCP diagnosis with separate source,
  static configuration, target context and unavailable connection/use results.
- `agent-infrastructure-lifecycle`: actionable MCP diagnosis/repair in both entry
  flows, preserving native startup trust and existing approved write scopes.

## Impact

New shared MCP projection/validator, bounded project reader and CLI entry; focused
tests, installed references and paired guides. Existing mcp-verify, writers and
stored schemas remain compatible. No dependencies, new write adapters, secret
resolution, server health-check, automatic installation, paid APIs, credential
changes, package version change, commit or publication.
