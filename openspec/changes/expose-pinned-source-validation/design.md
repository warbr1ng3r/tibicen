# Design

## Context

Мотивация и наблюдение описаны в [proposal](proposal.md). `validateSources()` уже является общей проверкой для apply; CLI имеет штатный парсер файла/stdin и структурированные ошибки.

## Goals / Non-Goals

**Goals:** открыть существующую проверку как короткий read-only путь для явно выбранного источника.

**Non-Goals:** новый поиск, транспорт, формат Source, registry, устойчивый cache, изменение sourceGate или согласия.

## Decisions

- Добавить одну CLI-ветку поверх `inputData()`, `validateSources()` и `loadBlocklist()`. Вывод — прежний массив summary. Отдельный валидатор или DTO дублировал бы правила apply.
- В `stage-agent-arch.md` рядом с discover указать условную ветку известного repo/full SHA и полного выбранного состава. Источник без закреплённого SHA остаётся на пути discover; сбой сети сохраняется как gap.
- Проверить реальный CLI с синтетическим immutable mirror без сетевого fallback; stdin/file и снимки проекта/HOME доказывают отсутствие побочных записей. Прежние sourceGate-тесты сохраняют независимую проверку apply.
- Сборка обоих скиллов содержит новую команду как часть существующего CLI, без OpenSpec и dev/runtime-зависимостей.

## Risks / Trade-offs

- Проверка требует доступности разрешённого upstream → сохранять существующий явный отказ, без ослабления provenance.
- Один trace не доказывает ускорение → после механической проверки новая frozen SKILL-пара измеряет фактический путь; старые результаты не пересчитываются.
