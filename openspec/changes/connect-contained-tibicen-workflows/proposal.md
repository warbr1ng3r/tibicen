# Proposal

## Why

Контейнерный Codex Code Mode прошёл один реальный execution smoke, но существующий многофазный стенд ещё использует заблокированный общий native profile. Следующий рабочий рубеж — два ограниченных запроса Tibicen до собственного report, без второго стенда и расширения продуктовой матрицы.

## What Changes

- Подключить owned-container caller к существующей native session boundary для AGENTS-only init/adopt, сохранив proposal/review/consent/receipt/report.
- Явно выбирать setup-only Tibicen cases, фиксировать batch/child budgets и прекращать серию при первой ошибке.
- Переносить только bounded regular bytes/mode facts и точные trusted runtime assets; host auth HOME остаётся отдельным.
- Подтвердить actual CLI synthetic workflow и ошибки до отдельного fresh subscribed batch.

## Capabilities

### New Capabilities

- `contained-tibicen-workflows`: ограниченные setup-only сценарии Tibicen через существующий контейнерный native caller.

### Modified Capabilities

Нет. General native profiles и неподдержанные сценарии остаются blocked.

## Impact

Eval runner/selection, bounded archive facts, narrow caller/schema и tests. Product core/skills/dependencies не меняются. MCP, compat, installation of additional skills, target OpenSpec, application task, baseline comparison и paid API не входят в первый slice.
