# Proposal

## Why

Текущие руководства обещают общий приватный conduct-контакт, который не назначен, и не определяют адрес канала advisory/сумм. Исходные [релизные требования](../prepare-first-public-release/specs/release-process/spec.md), [задачи 3.1–3.2](../prepare-first-public-release/tasks.md) и [Vision §10.13](../../../docs/PRODUCT_VISION.md) требуют рабочих маршрутов участия/security и независимого канала; предложение явно определяет их операционную область без сокращения технического MVP.

## What Changes

- **Перспективное изменение политики:** заменить позднейшее невыполненное обещание общего приватного conduct-inbox публичными issues/PR для нечувствительных вопросов проекта, приватными обращениями в GitHub Support по нарушениям правил платформы GitHub и неизменным приватным vulnerability-маршрутом к подтверждённому security-сопровождающему. Сохранить запреты поведения, приватность и отвод; не назначать другого получателя.
- Определить независимый канал как отдельно версионируемый Pages-артефакт advisory/сумм, публикацию и HTTP origin, отличные от release attachments. Указать общий административный контроль GitHub и соответствующие ограничения.
- Добавить небольшой статический индекс с фактическими привязками опубликованной версии/source/distribution/manifest/archive и дополняемыми предупреждениями о замене. Начать с уже выпущенной ограниченной alpha после проверки её точных записей; будущего кандидата добавлять только при наличии фактов его публикации.
- Согласовать английские/русские политики и руководства, затем проверить локальные данные и, при отдельном разрешении публикации, реальные публичные маршруты/байты. Планирование, принятие политики, проверка рабочего канала и полная релизная приёмка остаются разными фактами.

## Capabilities

### New Capabilities

- maintenance-channels: конкретные получатели обращений/границы приватности и отдельно публикуемые неизменяемые записи advisory/сумм. Эта операционная capability реализует существующие обязательства release-process, не дублируя релизный checklist.

### Modified Capabilities

Нет. Capability release-process вводится активным релизным change и отсутствует в main specs. Её исходные требования рабочих контактов, приватного раскрытия уязвимостей и неизменяемых байтов сохраняются; новая delta добавляет ограниченное операционное определение вместо изменения отсутствующего main requirement.

## Impact

Последующая реализация затронет CODE_OF_CONDUCT, SECURITY, CONTRIBUTING, README, RELEASING, MAINTENANCE и актуальные статусные ссылки на обоих языках; существующий Astro public-каталог, ссылки сайта и узкие site/data-проверки; краткие перекрёстные ссылки активного релизного change. Новый сервис, dependency, провайдер/аккаунт, runtime payload, версия или автоматическая публикация не предлагаются. Подробная релизная работа остаётся в [prepare-first-public-release](../prepare-first-public-release/tasks.md); пересмотр ежемесячно/при изменении источников, полные технические свидетельства, неизменяемая доставка и явное разрешение публикации остаются обязательными.

Это неприменённый план. Текущее обещание приватного conduct-контакта и пробел канала открыты до принятия соответствующей политики и проверки рабочих маршрутов/публикации. Прежняя ограниченная alpha и все неудачные наблюдения сохраняют исходную область.
