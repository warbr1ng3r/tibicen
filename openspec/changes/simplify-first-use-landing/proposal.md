# Proposal

## Why

The published 1.4 landing asks visitors to choose a command runner and repeats the same first-use journey across several sections. The owner approved a single recommended installation, a compact first session, switchable examples and a secondary preset builder after the [dated review](../../../docs/research/2026-11-06-landing-installation-review/README.md).

## What Changes

- Show the existing exact npx command first; expose equivalent pnpm/Yarn and manual guidance only on request.
- Combine installation and first request into one concise path with both meaningful task choices.
- Present one compact illustrative interaction at a time, retaining initial state, proposed change, approval and honest result limits.
- Move local preset creation to dedicated EN/RU pages with language-preserving navigation.
- Preserve material prerequisites, Windows command limits, keyboard access, no-JavaScript access and local-only preset handling.

## Capabilities

### New Capabilities

None; extend existing landing boundaries.

### Modified Capabilities

- `landing-experience`: first-use hierarchy, secondary preferences and compact complete examples.
- `landing-interactions`: optional installer alternatives, native example selection and preset behavior on a secondary page.

## Impact

Only the Astro site, affected site checks and paired project documentation change. The installer version, 1.4 distribution SHA, universal target, both complete skills, runtime, schemas and package version remain unchanged. No new dependency, account, installer, native/model run or publication is included. The owner approved implementation, not a new commit/push request.
