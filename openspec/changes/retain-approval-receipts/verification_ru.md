## Проверки интеграции root — 20 ноября 2026

Независимое чтение и проверки без модели нашли четыре ошибки возвращённой
реализации: неверный входной канал мог сделать state нечитаемым; журналы
принимали противоречивые digest/ID сессии; паспорт обходил проверку журнала;
legacy-state мог наследовать согласия другой сессии. Регрессии до исправлений:
**14 тестов: 10 прошли, 4 упали, exit 1**. Отдельные регрессии поймали неверный
fallback в `status`/`report` и избыточное первое исправление, запрещавшее читать
историю после копирования проекта.

Общая проверка теперь действует перед записью, при чтении state и паспорта.
Отсутствующие legacy-поля и прежние абсолютные корни остаются допустимыми;
последняя активная запись связана с текущим планом/корнем. Ограниченный реальный
дочерний процесс завершает работу до первой записи паспорта и проверяет
legacy-восстановление. Последняя регрессия сначала получила `sessionId: null`
при stateless resume. Теперь библиотека и CLI называют выбранную сохранённую
сессию; новый apply без state не заимствует ID прежней сессии. Отказ сохраняет
байты state, паспорта и usage неизменными.
