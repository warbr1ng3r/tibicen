# Дизайн (_ru)

Краткий перевод ключевых решений; канонический текст — `design.md`.

## Контекст

`installedTibicenSkill(relative)` сопоставлял regex по пути файла и принимал
`['tibicen-init', 'tibicen-adopt'].includes(имя_каталога)` без проверки
содержимого. Единственный вызов — решение scan о `mode`: `improve`, если есть
файл инфраструктуры вне установленного скилла Tibicen. Оракул A5 требует не
считать имена происхождением.

## Решения

1. **Маркер идентичности**: `<каталог-скилла>/package.json`, распознанный как
   JSON, где `name` равен каноническому имени скилла
   (`tibicen-init`/`tibicen-adopt`), а `version` — непустая строка. Именно это
   `scripts/build.ts` записывает в каждую сборку поставки начиная с
   0.1.0-alpha.1 (проверено по истории git и по
   `frozen/candidate/dist/*/package.json`). Version требуется, но не
   закреплена, поэтому будущие версии работают офлайн.
2. **Где читается**: в существующем ограниченном проходе `readProjectFile` в
   `scanProject` — без дополнительного обхода и чтений. Повреждённый или
   несоответствующий маркер просто не учитывается (неизвестное остаётся
   неизвестным); gap не добавляется, ибо маркер-двойник — обычный сторонний
   контент, а не сбой scan.
3. **Сужение кандидатов**: маркер учитывается только для `package.json` внутри
   harness-каталога skills, чьё конечное имя каталога канонично и чей
   `<dir>/SKILL.md` — инфраструктурный путь harness; та же форма, что принимал
   прежний regex. Существующая защита документационных примеров
   `example.instructions.md`/`example.json` сохранена.
4. **Решение о mode**: `installedTibicenSkill(path, canonicalSkills)` теперь
   дополнительно требует полного пути каталога скилла относительно проекта в
   собранном каноническом наборе. Маркер вложенного или соседнего проекта не
   идентифицирует другой каталог с тем же окончанием пути. Остальное поведение
   scan не меняется.
5. **Фикстуры**: существующие фикстуры с голым `SKILL.md` под каноническим
   именем кодировали дефектное предположение; они приведены к подлинному
   составу поставки добавлением маркера. Фикстура
   `tibicen-adopt/package.json` сохраняет полезную нагрузку `scripts`
   (проверка MUST_NOT_RUN) и получает поля идентичности.

## Риски

- Каталог без маркера, который пользователь считает «своей установкой
  Tibicen», теперь классифицируется как чужая инфраструктура (подсказка
  improve). Это намеренная честность: без несомой идентичности происхождение
  неизвестно.
- Двойник, дословно копирующий `package.json`, проходит; зафиксировано как
  известное ограничение: двойник только по имени различается, но скопированные
  маркеры не аутентифицируются.
- Дополнительный разбор JSON для canonical-именованных `package.json` при
  scan ограничен существующим лимитом байтов на файл; незначительно.

## Миграция

Не требуется: чистое изменение классификации; форматов на диске нет.
