# Proposal (_ru)

## Почему

Воспроизведённый дефект A5-i3 от worker-2: `scan` решает «установлен
канонический скилл Tibicen» только по имени каталога скилла
(`scripts/scan/index.ts`, `installedTibicenSkill`). Неканонический двойник в
`proj/.agents/skills/tibicen-init/` (подражающее имя и frontmatter, другое
содержимое, без идентичности поставки) лексически считается установленным
каноническим скиллом, поэтому чужие файлы скилла не учитываются как чужая
инфраструктура, и scan возвращает `mode: "init"`, теряя документированную
подсказку improve/unknown-provenance. Это расходится с оракулом A5 замороженного
каталога: «Names are not treated as provenance». Квитанция воспроизведения:
`evidence/A5-i3/a2-20261119/cli/scan-controller.json`.

Каждая сборка поставки начиная с первого зафиксированного релиза
(0.1.0-alpha.1) записывает `<skill>/package.json` с `{ "name": "tibicen-init" |
"tibicen-adopt", "version": <string> }` (`scripts/build.ts`); тот же маркер есть
в обоих скиллах замороженного кандидата 1.7.1. Поставка уже несёт
идентичность содержимого, которой нет у двойника с одним именем.

## Что меняется

- Scan устанавливает факт установленного канонического скилла Tibicen по
  идентичности, которую несёт сама поставка: `package.json` внутри каталога
  скилла с `name`, равным каноническому имени скилла, и непустой строкой
  `version`. Одного имени каталога больше недостаточно.
- Каталог-двойник с именем `tibicen-init`/`tibicen-adopt` без этого маркера —
  чужая инфраструктура: его файлы учитываются как любой другой пользовательский
  или сторонний скилл, и документированная подсказка improve сохраняется.
- Подлинные канонические установки всех опубликованных версий сохраняют прежнее
  поведение (их состав всегда включает маркер).
- Существующие фикстуры scan, кодировавшие предположение «только имя» (голый
  `SKILL.md` под каноническим именем), приведены к подлинному составу поставки;
  контракты сохранённых сессий, паспортов и пресетов не меняются.

## Возможности

`agent-infrastructure-lifecycle`: канонические установленные скиллы
определяются по несомой идентичности, а не по именам каталогов.

## Влияние

Изменение исходника только в `scripts/scan/index.ts` (помощник распознавания и
чтение маркера в уже существующем ограниченном чтении файлов); обновление
фикстур `tests/scan/scan.test.ts` и новая регрессия. Форма результата scan не
меняется; меняется только классификация `mode` для каталогов-двойников без
маркера (init → improve лишь для них). Проекты с реальной установкой Tibicen, с
паспортом или без каталогов с именами Tibicen не затронуты. Двойник, полностью
копирующий маркер идентичности дословно, остаётся офлайн неотличим от
канонического содержимого; это исправление закрывает подмену только по имени, а
не побайтовую имперсонацию (для неё нужно закрепление хэшей известных версий —
отдельное решение). Наблюдение исполнителя A5-i3 против замороженного кандидата
1.7.1 этим исправлением Unreleased не переоценивается.
