# Spec Delta

## Purpose

Настроить память проекта по приоритетам пользователя, чтобы следующие агенты находили, сохраняли и исправляли полезные решения с сохранением существующих записей и явных границ записи.

## ADDED Requirements

### Requirement: Memory policy follows evidenced user priorities

Tibicen SHALL рекомендовать правила памяти по запросу человека и разрешённым сведениям проекта. Он SHALL различать явные долгосрочные решения, выведенные предпочтения и временные просьбы, показывать исправляемые допущения и сохранять действующие ограничения интервью.

#### Scenario: A user describes what matters without naming a memory tool

- **WHEN** пользователь просит помнить архитектурные решения и избегать ненужных зависимостей
- **THEN** рекомендация определяет, какие решения и причины сохранять и когда их читать
- **AND** человеку не нужно выбирать технологию хранения или проходить отдельную обязательную анкету

#### Scenario: A one-off response request is available

- **WHEN** единственное основание стиля — «ответь сейчас кратко»
- **THEN** оно не устанавливается как подтверждённое постоянное правило памяти
- **AND** выведенное предпочтение остаётся видимым и исправляемым

### Requirement: Project memory has one canonical location

Tibicen SHALL определить один поддержанный файл памяти, сохранить подходящую существующую память и предлагать новый файл по умолчанию только при необходимости. Путь, исходные изменения содержимого и ссылки из инструкций SHALL входить в просматриваемый план. Неподдержанные хранилища SHALL сохраняться с явным ограничением.

#### Scenario: Existing memory is sufficient

- **WHEN** в проекте уже есть полезная память по поддержанному пути
- **THEN** Tibicen подключает выбранных агентов к этому файлу без конкурирующей копии
- **AND** посторонние записи сохраняются побайтно

#### Scenario: No project memory exists

- **WHEN** пользователю нужна память, но подходящего хранилища нет
- **THEN** план предлагает один `.agents/memory.md` и короткие применимые ссылки в инструкциях
- **AND** до согласия ничего не создаётся

### Requirement: Memory rules define reading and maintenance triggers

Согласованные инструкции SHALL определять чтение перед подходящей задачей, сохраняемые подтверждённые сведения, моменты обновления и исправление отменённых решений. Они SHALL отделять устойчивые знания проекта от временного хода задач и ограничивать обычные обновления разрешённой пользователем областью.

#### Scenario: A later task depends on an earlier decision

- **WHEN** новая сессия получает задачу, затронутую сохранённым ограничением проекта
- **THEN** инструкции направляют её к соответствующей памяти до выбора решения
- **AND** посторонняя история не требуется в постоянно загружаемом тексте инструкций

#### Scenario: The user changes a project decision

- **WHEN** пользователь явно заменяет прежнее принятое решение
- **THEN** рабочий агент обновляет актуальный смысл и сохраняет доступную причину или источник
- **AND** противоречащий старый текст не остаётся другим равноправным текущим указанием

### Requirement: Memory records preserve provenance and uncertainty

Политика SHALL различать принятые решения, проверенные факты проекта и неразрешённые допущения. Она SHALL сохранять полезные причины или ссылки на основания без выдуманного подтверждения. Чувствительные сведения и полные переписки SHALL NOT копироваться в память проекта по умолчанию.

#### Scenario: A hypothesis has not been confirmed

- **WHEN** агент выводит предпочтение или возможное техническое объяснение
- **THEN** он не записывает это как установленный постоянный факт
- **AND** неразрешённая запись явно отмечается либо остаётся вне устойчивой памяти

### Requirement: Adopt preserves working memory and resolves actual conflicts

Adopt SHALL исследовать текущую разрешённую память, сохранять полезные записи и предлагать только обоснованные изменения. Изменение тела памяти после завершённой настройки SHALL быть обычным пользовательским состоянием, а не автоматическим признаком повреждения установки. Конфликты SHALL следовать явным решениям человека, а не возрасту файла или порядку загрузки.

#### Scenario: An agent added a legitimate decision after setup

- **WHEN** adopt запускается после изменения файла памяти
- **THEN** он использует текущее содержимое и сохраняет добавленное решение
- **AND** не восстанавливает шаблон настройки и не сообщает fixed-content mismatch только из-за дополнения

#### Scenario: Several candidate stores disagree

- **WHEN** два хранилища содержат существенные противоречия, а текущий источник неизвестен
- **THEN** Tibicen показывает конфликт и применяет действующие правила уточнения или gap при запрете вопросов
- **AND** не склеивает записи молча и не отбрасывает историю пользователя

### Requirement: Memory remains optional and local to the selected project

Tibicen SHALL сохранять достаточную настройку и отклонённую память без изменений. Настройка SHALL использовать обычный согласованный файловый процесс без постоянного Tibicen, внешнего аккаунта и автоматической правки глобальной памяти агента. Дальнейшее обслуживание выполняют рабочие агенты по настроенной политике.

#### Scenario: The user declines memory setup

- **WHEN** пользователь отказывается от необязательной рекомендации
- **THEN** файл памяти и специальная зависимость не добавляются
- **AND** обычный init или adopt может завершиться

#### Scenario: A connection cannot be established safely

- **WHEN** выбранное хранилище неподдержано, запрещено или недоступно
- **THEN** отчёт указывает отсутствующую связь или ручное действие
- **AND** наличие файла не выдаётся за работающий процесс памяти
