# Proposal

## Why

Реальный landing собирается с локальными зависимостями, но встроенный snapshot Tibicen исключает node_modules и не может выполнить согласованные проверки. Нужен явный согласованный снимок локальных зависимостей для сопоставимого baseline/final, без установки пакетов и чтения оригинала при исполнении.

## What Changes

- Опциональное checks.environment описывает выбранные локальные node_modules roots; proposal вычисляет hash содержимого и runtime identity, входящие в согласие.
- Зависимости один раз захватываются до baseline; каждая исполняемая копия получает собственные байты из этого захваченного окружения.
- Поддержаны внутренние pnpm links и ссылки на workspace внутри копии. Внешние/абсолютные ссылки, специальные файлы, чувствительные пути и превышенные лимиты отклоняются.
- Непереносимые .bin shims и manager/cache metadata исключены; первый поддержанный сценарий использует явные Node entrypoints. Обычная фильтрация секретов приложения не меняется. Выбранный package payload — отдельно согласованный исполняемый код, а не источник агентского контекста или копия личного окружения.
- Недоступное или изменившееся окружение оставляет проект unverified с конкретной причиной. Старые планы без окружения сохраняют поведение.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `verification-and-delivery`: воспроизводимое локальное окружение контролируемых проектных проверок.

## Impact

Core proposal/types/runtime, snapshot helpers, tests/verify и автономная поставка обоих скиллов. Новых пакетов, внешней сети, агента, OpenSpec dependency в дистрибутиве и автоматических коммитов в целевом проекте нет. Первый приёмочный пример — текущий landing с существующими зависимостями и 13 site tests.
