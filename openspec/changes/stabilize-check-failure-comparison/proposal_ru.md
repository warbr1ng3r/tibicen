# Предложение

Основная версия — [proposal.md](proposal.md).

## Зачем

Опубликованная 1.7.0 хэширует вывод проектной проверки после замены пути временного проекта. Тестовые раннеры Node и Python добавляют изменчивые длительности исполнения в остальной неизменный вывод провальных проверок. Поэтому одна и та же ошибка может получить статус `changed-failure` вместо `pre-existing-red`.

Возвращённый пакет сценариев воспроизвёл этот симптом. Его первый фикс заменял похожие на длительность фрагменты по всему выводу. Независимое интеграционное ревью обнаружило пропуск настоящей регрессии: значения утверждений `(1s)` и `(5s)`, и даже изменённые названия тестов с такими значениями, становились одинаковыми. Такая широкая нормализация не принята.

## Что изменится

- Нормализовать только распознаваемые полные записи времени: конечные суффиксы длительности в миллисекундах в строках статуса Node spec, сводки длительности Node spec/TAP, диагностическую длительность TAP непосредственно после результата теста и открытия диагностического блока, а также полную строку Python unittest `Ran N tests in Ts`.
- Сохранить значения утверждений, названия тестов, счётчики и обычные фразы лога, включая `took 1s`, `after 5s` и посторонние поля `duration_ms`. Неизвестные форматы сравниваются строго, как прежде.
- Для неизменившейся ошибки требуются одинаковые ненулевые коды завершения: закрыт существовавший пробел сравнения, найденный ревью.
- Сохранить единую точку записи результатов проверок, историю сравнения и существующие сохранённые хэши. Изменение схемы, CLI или миграция state не вводятся.

## Возможности

`verification-and-delivery`: устойчивое сравнение распознаваемых записей времени раннера без потери значимых различий провальных результатов.

## Влияние

Общий `scripts/verify/index.ts`, предметные тесты канонизации/сравнения и реальные запуски Node TAP/spec через существующий механизм проверок на снимках. Оба распространяемых скилла получают одну реализацию. Совпадение с форматом записи раннера — соглашение о представлении, а не доказательство правдивости проекта или раннера; семантическое понимание произвольного вывода команд не заявляется.
