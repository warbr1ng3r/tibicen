# Дизайн

Основная версия — [design.md](design.md).

`runProjectChecks` остаётся единственной точкой записи. Он нормализует путь временного проекта, приводит к каноническому виду распознаваемые записи времени раннера, затем хэширует полученный вывод. Существующие хэши сохраняются; сравниваемые исходный и итоговый прогоны используют один текущий путь записи.

Замены с привязкой к строкам покрывают конечные суффиксы длительности Node spec, сводки Node spec/TAP и сводки Python unittest. Длительность отдельного теста TAP распознаётся только непосредственно после результата `ok`/`not ok` и открытия его диагностического блока. Замены сохраняют CRLF, названия тестов, счётчики и остальной вывод. Произвольные числовые значения, фрагменты в скобках и фразы о затраченном времени остаются нетронутыми.

Возвращённый очиститель фрагментов по всему выводу отклонён: `AssertionError: expected (1s)` и `(5s)` превращались в одинаковую ошибку, а в названии теста и конечном временном суффиксе стирались обе длительности. Сравнение только кодов выхода и универсальный парсер логов тоже не нужны. Узкое распознавание записей сохраняет консервативное поведение для неподдержанных форматов вместо обещания охватить все тестовые раннеры.

При ревью также обнаружен существующий пробел сравнения: одинаковый вывод при смене кода выхода с 1 на 2 принимался за неизменную ошибку. Помимо совпадающего вывода требуется одинаковый ненулевой код выхода; отдельная регрессия, падающая до исправления, покрывает это независимо от нормализации.

Тесты покрывают детерминированное сравнение через точку записи при различиях только во времени, изменённые значения утверждений, похожие на длительность, изменённые названия тестов, диагностику TAP с CRLF, изменённые коды выхода и реальные провальные Node-проверки с обоими репортерами — TAP и spec. Ранее сохранённые хэши не переписываются и не объявляются рассчитанными с новой нормализацией.
