# Design

## Context

См. [proposal](proposal.md). Автодеплой Cloudflare уже проверен; GitHub Pages публикуется вручную. Оба раньше собирали весь Astro-сайт. В maintenance JSON указан прежний канал GitHub Pages.

## Goals / Non-Goals

Один актуальный лендинг и прежний машинный endpoint. Данные релизов не переносятся, Pages не отключается, исторические свидетельства и скиллы не меняются, зависимости не добавляются.

## Decisions

Четыре маленьких HTML содержат немедленный meta refresh, canonical и видимую ссылку. Скрипт с фиксированным назначением сохраняет query/fragment при JavaScript. Это HTML-переход, а не HTTP 301. Прежний workflow Pages копирует четыре файла и канонический JSON в свежий runner-temp каталог, сравнивая байты JSON перед upload. Публикация остаётся ручной для прежней границы обновления контрольных сумм.

Origin Astro и ожидание теста по умолчанию меняются на Cloudflare; явные флаги сохраняют другие origin/base. Обновляются homepage пакета, ссылки EN/RU README и действующие инструкции. Датированные свидетельства остаются историей.

## Risks / Trade-offs

- HTML-переходы возвращают HTTP 200 и зависят от клиента → немедленный meta refresh, canonical, видимая ссылка и настоящий браузер с JavaScript и без него.
- Удаление JSON нарушит опубликованные ссылки → URL, исходник и байты сохраняются и проверяются после публикации.
- Параллельная работа → отдельный worktree из опубликованного main и только явно согласованный коммит.

## Migration Plan

Полный offline gate и отдельные браузерные проверки. После разрешения на коммит отправить перенос (Cloudflare публикуется автоматически), затем запустить новый workflow Pages. Проверить четыре старых маршрута и прежний JSON. При сбое повторно выложить предыдущие проверенные исходники без переписывания истории.
