# Design

## Context

Ретроспективно описывается только `scripts/evals/results.ts` и его тесты. Общий runner, оценщики, preflight, парные сценарии и внешние агентские профили ещё не реализованы этим изменением.

## Goals / Non-Goals

**Goals:** строгие записи, непротиворечивый порядок стадий, прозрачные знаменатели, изоляция средств разработки от скиллов.

**Non-Goals:** запуск моделей, интерпретация доказательств, сравнение смешанных когорт, публикация измеренной пользы.

## Decisions

- Чистые функции `validateAttempt` и `summarizeAttempts` без IO. Вход считается наблюдением, а не доказательством загрузки инструкций.
- Схема 1 проверяет собственные обязательные поля и отвергает лишние, включая symbol. Не-pass исход имеет причину, skip — нулевую длительность. `started` фиксирует наблюдаемый старт сценария.
- Стадии не переписывают предыдущий результат: ошибка задачи не обнуляет успешную настройку. Ошибка запуска после наблюдаемого старта остаётся в знаменателе started.
- Возвращаются исходные счётчики и три дроби с явными числителями/знаменателями. При отсутствии знаменателя rate=null. Повторы сценария допустимы только с разными attempt id.
- Когорту выбирает будущий стенд; агрегатор не делает статистических или причинных выводов. Evals исключаются из сборки рядом с существующим исключением `build.ts`.

## Risks / Trade-offs

Схема не содержит полную среду/артефакты будущего испытания. Её расширение потребует отдельного контракта; свободные поля сейчас не допускаются. Успешные unit tests доказывают расчёт, а не качество Tibicen на настоящем агенте.
