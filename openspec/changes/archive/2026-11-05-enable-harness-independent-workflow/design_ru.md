# Design

## Context

Причины изменения описаны в [proposal](proposal.md). Три направления проверки
без изменений файлов установили, что обычные `createProposal`/`applyPlan` уже
работают без поля harness/model и могут обновлять общие инструкции AGENTS.
Фактические ограничения входа — команда установки на сайте с тремя целями,
проверка пресетов только по каталогу и инструкции, которые безусловно направляют
несколько инструментов через нативные общие копии с проверкой версии.
У закреплённого установщика есть отдельная явная цель `universal`; отсутствие
флага агента может выбрать всех обнаруженных/доступных агентов и не подходит
в качестве замены. Промежуточный кандидат 1.3 остаётся неизменяемым ранним снимком.

## Goals / Non-Goals

**Цели:** явный сквозной маршрут общих инструкций для хоста с доступом к файлам
проекта и необходимым операциям Node; описательные неизвестные предпочтения;
одно каноническое хранилище памяти; точное различение доступных и недоступных
проверок; небольшие существующие интерфейсы без новых полномочий на сохранение.

**Вне целей:** автоматическая произвольная запись нативных Markdown/config,
добавление всех адаптеров MCP/процессов/проб, собственная маршрутизация
провайдеров/моделей, настройка учётных данных, среда исполнения плагинов
или заявление о нативном автообнаружении/совместимости для каждого инструмента.

## Decisions

### Reuse the existing skill and project-instruction interface

Доставлять оба полных скилла в универсальную пользовательскую папку закреплённого
установщика и явно просить текущий хост прочитать выбранный SKILL.md. Где этого
достаточно, полученный согласованный AGENTS.md также читается явно. Настройка
модели или провайдера принадлежит хосту; Tibicen не требует ни ID модели,
ни клиента провайдера. Каталог остаётся дополнительной датированной справкой
по форматам. Нативные копии общих правил нужны только для отдельно обоснованного
поддерживаемого запроса; один общий файл не проходит через адаптер копирования
с проверкой версии.

Альтернатива — зарегистрировать больше брендов или расширить права нативной
записи. Это не снимет общее ограничение входа и потребует работы со схемами
и восстановлением для новых полномочий на сохранение. Такая нативная возможность
необязательна и не является условием маршрута с общим файлом. Существующая защита
путей и согласия в ядре сохраняется.

### Share a small hint validator rather than a new registry

Использовать существующий ограниченный синтаксис строчных `isHarnessId`
для известных и неизвестных ID. Вспомогательная функция, пригодная для браузера,
проверяет строковые массивы без пропусков с не более чем шестнадцатью различными
ID, не считая дубликаты дополнительными выборами. Она отвергает пропущенные
элементы массива и некорректные значения; нормализация не может превратить
произвольные инструкции в корректный ID. Ядро и браузер используют одну функцию.
Существующие известные дубликаты остаются читаемыми; браузерное скачивание может
сохранить существующее удаление дубликатов с сохранением порядка. Форма сохраняет
предложения каталога и добавляет небольшое поле своего ID с локализованными
доступными сообщениями об ошибках. ID — только данные; из них не следуют новые
URL или полномочия.

### Make installation and first use explicit

Команда по умолчанию сохраняет skills@1.7.4, полный SHA опубликованной поставки,
оба точных имени скиллов, глобальную область и --copy, с --agent universal.
Убрать обязательный выбор бренда; выбор менеджера пакетов и инструкции
без JavaScript сохраняются. Указать общее пользовательское расположение и точный
запрос на явное чтение. Полный ручной маршрут использует опубликованные
архив/контрольные суммы, обе целые папки скиллов и их ресурсы в выбранном месте.
Он не копирует только входной файл и не выдумывает нативный каталог хоста.
Не заменять опубликованные закреплённые версии неопубликованным кодом.
Существующие специализированные маршруты можно описать как необязательные.

### Express operations and evidence in existing guidance

Использовать существующие этапы scan/inventory/architecture/verify/handoff,
чтобы различать доступ к файлам проекта, поддерживаемый Node, согласованную
запись и явную активацию. Если операция недоступна, назвать её и полезный следующий
шаг. Необязательные пробы задач/квизов/загрузки сохраняют свои точные поддержанные
методы; их отсутствие не означает ни успешную проверку, ни полный отказ
в обычной настройке. Сохранить существующую семантику завершения и ручных
действий. Не добавлять формат хранения возможностей или список разрешённых
провайдеров/моделей. Поставляемые инструкции остаются самодостаточными.

## Parallel ownership

| Направление | Исключительные изменения |
| --- | --- |
| Подсказки ядра | scripts/agents/profiles.ts, scripts/core/contracts.ts, целевые тесты функции/пресетов, docs/HARNESS_CAPABILITIES.md и его копия _ru |
| Сайт/установка | исходники сайта, браузерные тесты/тесты сайта, новые docs/INSTALLATION.md и его копия _ru |
| Правила/документация проекта | существующие поставляемые справочники, README.md и его копия _ru, новые docs/HARNESS_PORTABILITY.md и его копия _ru |
| Корневая интеграция | OpenSpec/чеклисты, трекеры/план развития, журнал изменений и итоговая верификация |

Ни у одной пары файлов нет двух авторов. Направления ядра и сайта передают точные
факты направлению документации; читать ещё не готовую общую функцию разрешено,
но её контракт фиксируется до параллельных изменений кода. Новые руководства
остаются документацией проекта, а не зависимостями устанавливаемых скиллов.

## Risks / Trade-offs

- [Универсальная папка не означает универсальное нативное обнаружение] → явное
  чтение SKILL/AGENTS, полезный первый запрос, нативная загрузка остаётся
  непроверенной до наблюдения.
- [Неявное обнаружение установщика выбирает нежелательные цели] → явный флаг
  universal, проверки команды и одно внешнее наблюдение доставки
  с синтетическим HOME.
- [Неизвестные подсказки выглядят как предоставление поддержки] → формулировки
  только о предпочтениях, общая валидация, неизменные лимит источников, доступные
  для записи пути, адаптеры и методы проб.
- [У хоста нет операций с файлами/Node] → точная передача ручных шагов
  и недоступных операций без выдуманных результатов изучения/применения
  или принудительной смены провайдера/harness.
- [Формулировка обходит согласие или создаёт нативную конфигурацию] → проверка
  связанных правил и сохранности в общем жизненном цикле; сохранить тесты
  защиты нативных файлов.

## Migration Plan

Сохранить политику пакета/схем/зависимостей прежнего кандидата: планируемая минорная
версия 1.3.0, существующие сохраняемые схемы, опубликованные привязки поставки
1.2. Старые пресеты работают; старые валидаторы отвергают новые необязательные ID,
поэтому при откате нужно удалить только эти подсказки. После реализации получить
новые идентификаторы исходников/сборки. Повторно использовать существующие
свидетельства функциональности только при идентичных входах; выполнить затронутые
проверки и полный набор проверок, затем независимую проверку и ограниченные
наблюдения точной универсальной доставки/жизненного цикла без привязки к бренду.
Прежние H01/H02 остаются неиспользованными, без переоценки и запуска. Новые
коммиты/публикация требуют явного разрешения и конкретного пакета материалов.


Ручной вариант проверяется во внешней выбранной папке с пробелами: полный архив,
хэши архива/файлов, self-test обоих скиллов, точные пути явного чтения и сохранность
соседних файлов. Эта же распаковка используется для одного цикла init/adopt,
без дублирования прогона и без заявления о native/LLM поведении.

В границы ветки правил также входит только строка prerequisite входного
tibicen-init/SKILL.md: Git нужен Git-маршруту доставки, но не полному архиву.
Вход adopt уже корректен; остальное содержимое entry и права не меняются.
