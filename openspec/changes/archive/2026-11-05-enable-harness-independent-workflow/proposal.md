# Proposal

## Why

Tibicen's core can already configure common project instructions without an agent
ID, but installation and preset validation still present a fixed brand gate.
The owner requires a real usable route across harnesses and user-selected LLMs;
a larger descriptive catalog alone does not supply that route.

## What Changes

- Make explicit universal installation and skill-file loading the normal route
  for a host with project-file access and the required Node runtime, with a
  complete archive/manual-folder alternative. Preserve the exact published pin.
- Accept bounded, well-formed uncatalogued harness hints in core and browser
  presets; known profiles remain optional suggestions rather than permission.
- Guide init/adopt by available host operations. Reuse one approved project
  `AGENTS.md` and existing memory where sufficient; give an explicit activation
  prompt instead of assuming every harness discovers that file or the skill.
- Separate a user-selected model/provider from the caller harness and optional
  native probe methods. Missing file/Node/native operations receive a precise
  gap; they do not force a switch to Claude, Codex or Cursor.
- Preserve existing exact-plan consent, application protection, writable paths,
  persisted schemas, native adapters and credential/startup controls. Automated
  edits to additional native Markdown/config formats remain a separate feature.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `harness-capabilities`: portable explicit workflow, available-operation gaps,
  model/provider independence and bounded unknown preset identities.
- `landing-experience`: universal pinned installation, explicit first skill load
  and complete manual-folder recovery without a mandatory brand selector.
- `landing-interactions`: installation controls follow the universal route;
  optional uncatalogued preset hints retain accessible local validation.

## Impact

Core/browser preset validation, installation and first-use UI, existing installed
stage guidance, paired project guides and their focused tests change. The kernel
already supports generic AGENTS init/adopt and needs no new write authority or
persistent schema. New optional preset IDs remain unreadable by older validators;
remove only those optional hints when downgrading. No dependency, provider client,
agent runtime, paid API, native evaluation profile or published release changes.
The intermediate frozen candidate-01 stays retained; a later candidate must bind
the actual changed bytes and observations before any separate release decision.
