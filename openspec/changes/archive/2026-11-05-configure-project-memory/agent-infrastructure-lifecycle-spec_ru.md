# Spec Delta

## ADDED Requirements

### Requirement: Memory writes have an explicit bounded binding

Только один поддерживаемый путь внутри проекта, явно указанный в одобренном плане, SHALL получать записи настройки памяти. Начальные изменения SHALL проходить существующие проверки согласия, пути, симлинков, запрещённых файлов и исходного содержимого. Привязка SHALL NOT разрешать произвольные записи Markdown, приложения или глобальной памяти.

#### Scenario: A supported existing file is selected

- **WHEN** одобренный план привязывает `docs/memory.md` и точные изменения
- **THEN** записывать можно только этот файл и отдельно одобренные изменения инструкций
- **AND** другой Markdown-файл остаётся вне разрешения на память

#### Scenario: The selected file changes after approval

- **WHEN** содержимое памяти изменилось относительно одобренного исходного состояния до apply или возобновления прерванной сессии
- **THEN** устаревшая запись отклоняется до перезаписи
- **AND** требуются новый план и соответствующее одобрение

### Requirement: Mutable memory ownership is separate from stable setup

Сохранённая настройка SHALL отмечать канонический путь памяти как изменяемое содержимое пользователя. После завершения настройки проверки SHALL сохранять контроль инструкций, связи и безопасности пути, не требуя исходный хэш содержимого памяти. Прерванная запись SHALL сохранять точную защиту журнала и восстановления.

#### Scenario: Memory grows after a completed session

- **WHEN** рабочий агент добавил решение в рамках одобренных правил
- **THEN** последующая проверка принимает изменённое содержимое без сброса
- **AND** отсутствие файла, небезопасный путь или повреждённая управляемая инструкция по-прежнему выявляются отдельно

### Requirement: New memory records fail closed in older runtimes

Форматы proposal, manifest и recovery с памятью SHALL использовать новые явные схемы, которые читатель 1.0 отклоняет до записи. Новый runtime SHALL сохранять чтение и восстановление старых сценариев без памяти и показывать миграцию в одобряемом digest. Миграция SHALL сохранять полезное содержимое и историю сессий без молчаливой потери модели владения.

#### Scenario: An old runtime encounters a memory-enabled project

- **WHEN** runtime 1.0 читает новый manifest памяти или незавершённую запись её восстановления
- **THEN** он отклоняет неподдерживаемую схему до записи
- **AND** пользователь может продолжить совместимым runtime без потери содержимого

#### Scenario: An existing 1.0 project opts into memory

- **WHEN** новый runtime предлагает память для старого manifest
- **THEN** миграция и точные изменения файлов входят в одобряемый план
- **AND** отказ от памяти сохраняет обычный прежний сценарий
