# Proposal

## Why

Пользователи хотят, чтобы следующие агенты сохраняли важные для них решения и ограничения без повторения всей переписки. Tibicen 1.0.0 умеет настраивать общие инструкции, но не задаёт отдельный жизненный цикл памяти: обычные файлы памяти исключены из разрешённых целей записи, а проверка обычно считает зарегистрированное содержимое неизменным.

## What Changes

- Добавить необязательную настройку памяти проекта в `tibicen-init` и `tibicen-adopt`. Выводить краткую политику из реальных приоритетов пользователя, сохранять явные решения и спрашивать только о существенных неразрешённых выборах.
- Использовать один файл памяти и короткие правила чтения/обновления в инструкциях выбранных агентов. Сохранять подходящую существующую память; при необходимости создавать `.agents/memory.md`. Согласованные правки сохраняют посторонние записи и объясняют замены.
- Разделить стабильные правила настройки и изменяемое содержимое памяти, принадлежащее пользователю. Последующие дополнения — нормальный вход adopt; устаревшие согласованные записи, небезопасные пути и отсутствующие/сломанные связи по-прежнему останавливают работу безопасно.
- Добавить версионируемые opt-in записи памяти и явную миграцию. Сохранить сценарии 1.0 без памяти; старый runtime должен отказывать при незнакомых записях до изменения файлов.
- Проверить init, внедрение в существующий проект, исправления, повторные запуски и чтение/обновление в новой сессии. Структурные проверки, наблюдаемое поведение агента и неизвестную человеческую пользу показывать отдельно.
- Подготовить совместимую новую функцию к **1.1.0**. Описать SemVer после 1.0, держать выполненное в `Unreleased` до выпуска и сохранить опубликованные теги/assets 1.0.0. Планирование не меняет текущую версию пакета и ничего не публикует.

## Capabilities

### New Capabilities

- `project-memory`: приоритеты пользователя, ограниченный единый файл памяти, правила чтения/обновления/исправления, сохранность и отдельные структурные/поведенческие свидетельства.

### Modified Capabilities

- `agent-infrastructure-lifecycle`: явно указанный файл памяти получает узко ограниченные инфраструктурные операции и версионируемую изменяемую принадлежность без ослабления согласия или защиты приложения.
- `verification-and-delivery`: настройка памяти получает связанные с кандидатом свидетельства новой сессии; публичные версии отражают совместимость после 1.0 и обозначают неизменяемые байты поставки.

## Impact

Основные места изменений: `scripts/core/{types,contracts,paths,plan,apply,recovery,components,finalize,runtime}.ts`, `scripts/tibicen.ts`, `scripts/scan/index.ts`, `scripts/verify/{index,scope}.ts`, связанные first-party тесты и общие стадии references, копируемые в оба скилла. Изменения схем обосновываются новыми правилами принадлежности/прав, а не номером версии продукта. Точные решения и границы миграции — в [design](design.md).

Основные руководства остаются английскими с соседними переводами `_ru`. Поставка независима от development OpenSpec. Новые зависимости, сервер, фоновый наблюдатель, правка глобальной памяти агента, платный API и расширенное обещание поддержки агентов/ОС не вводятся. Строгая схема пресетов сохраняется: политика памяти относится к конкретному проекту.

Владелец запросил **утверждение плана до реализации**. Дашборд работ (`../../../../.scratch/project-memory/dashboard.md`; приватная запись разработки; не входит в публичную копию исходников) фиксирует зависимость от утверждения и параллельные области. Отдельное ревью лендинга готовит только рекомендации; реализация его предложений находится вне этого change. Коммит, push и публикация требуют последующего явного указания для конкретных результатов.
