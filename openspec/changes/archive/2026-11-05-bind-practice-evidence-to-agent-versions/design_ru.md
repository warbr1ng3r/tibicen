# Design

## Context

См. [proposal](proposal.md). `checkPractices` уже принимает `agentVersions` и
возвращает `agentVersion` для соответствующих источников. CLI передаёт только
agents. Поле proposal `practices` и история отчёта уже хранят JSON-свидетельства,
поэтому новая постоянная схема или движок рекомендаций не нужны.

## Goals / Non-Goals

**Goals:** связать CLI с проверенным вводом версий и понятно описать ограничения
источника, среды и применимости внутри существующего процесса агента.

**Non-Goals:** обнаруживать бинарники исполнением проектного PATH, устанавливать
инструменты, обращаться к модельным аккаунтам, автоматически классифицировать
весь интернет, добавлять сборщик или считать переданную версию доказательством
совместимости.

## Decisions

1. Переиспользовать `--input FILE|-` для необязательного JSON `{ "agentVersions":
   { "codex": "0.157.0" } }`; `--agents` обязателен и задаёт выбор. Нет ввода или
   карты — неизвестные версии. До HTTP отклонять лишние верхние ключи, карту
   не-объект/массив/null, неподдержанные/невыбранные ключи и значения не-строки,
   пустые, с управляющими символами или длиннее 100 символов. Не предполагать
   SemVer для всех поставщиков.
2. Проверять версии в существующей общей функции practices для CLI и прямого
   вызова; CLI проверяет оболочку и передаёт только поддержанную карту. Сохранить
   статусы, имена gaps, schema 1 и `requires-agent-assessment`. Новое поле вывода
   или автоматическая отметка совместимости не нужны.
3. Рабочий агент получает версии из доверенных метаданных хоста или уже
   разрешённого наблюдения, передаёт через stdin. Файл репозитория, пресет или
   старый паспорт не доказывают текущую установку. Без надёжного наблюдения
   запись пропускается с объяснением gap. Произвольный проектный код и временный
   входной файл ради выяснения версии не нужны.
4. Правило интерпретации живёт в `references/rules.md`; стадии направляют к нему
   без длинных дублей. Обновить пример ввода proposal-format и существующее
   руководство adopt, не создавать ещё одно. Существующие assumptions/practices
   сохраняют проверяемые основания и источники.

Отклонённые варианты: флаг для каждого агента дублирует карту; автозапуск
`--version` расширяет исполнение/доверие; оценка свежести или постоянное
хранилище рекомендаций не доказывают смысловую применимость.

## Risks / Trade-offs

- Переданная версия неверна → обозначать контекст от вызывающего, сохранять
  неопределённость и объяснять основание наблюдения.
- Документы описывают другой релиз → сохранять дату, оценивать применимость и
  оставлять неизвестное при отсутствии оснований.
- Общий CLI/тесты влияют на автономную поставку → офлайн-проверки stdin/файла и
  собранных init/adopt вне checkout.
- Объяснение агента задаётся инструкцией → статическое ревью не является живым
  результатом полезности или поведения; ограничение раскрывается.

## Migration Plan

Постоянной миграции нет. Прежний вызов только с agents работает. Работа остаётся
Unreleased при 1.1.0 до отдельной подготовки релиза. Откат ограниченных изменений
CLI/функции/references/документов убирает расширение, не меняя схем сохранённых
предложений и отчётов.
