# Proposal

## Why

Tibicen repeats three harness names across practice discovery, preset validation and inventory. This prevents users of other tools from receiving grounded guidance and confuses a recognized name with permission to install, write configuration or execute it.

## What Changes

- Add a small static, dated catalog for existing and additional harness identities, documented project instruction/skill locations, relevant official practice sources and explicit unknown/legacy states. Expose it through a read-only `harnesses` CLI command.
- Reuse the catalog in practice selection, preset hints and read-only instruction inventory/diagnosis. Preserve existing IDs, schema shapes and previous checked-adapter evidence.
- Allow bounded selections beyond the original three names while retaining at most six practice HTTP requests per invocation, two sources per harness, the existing HTTPS/text/redirect/size/time safeguards and explicit budget gaps.
- Keep observation, approved write paths, MCP/process adapters, installer choices and native evaluation identities separate. Catalog entries grant none of these capabilities.
- Explain limitations consistently in skill rules, English/Russian guides and the local-only preset form. Keep existing installer pins and supported choices unchanged.

## Capabilities

### New Capabilities

- `harness-capabilities`: dated harness descriptions, unknown outcomes, bounded observation and independent capability/evidence authorities.

### Modified Capabilities

- `agent-infrastructure-lifecycle`: practice selections and caller version context work for catalog and unknown harness identities within the unchanged network budget.

## Impact

One dependency-free profile module is shared by discovery, scan/diagnosis and preset callers. CLI help, preset form validation, focused tests and distributed skill references change. No new dependencies, arbitrary registries/domains/write targets, native model runs, project commands, credentials, background update, package-version bump or publication are required. Work remains under Unreleased; 1.2 assets and historical results stay unchanged.
