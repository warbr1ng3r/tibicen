# Design

## Context

См. [proposal](proposal.md). Read-only аудит исходников и две ветки исследования
официальных источников завершены 5 ноября 2026 года. В практиках, пресетах и
скане повторяются три названия; ID агентов уже хранятся строками. Классификация
скана шире права записи `core/paths.ts` и используется проверкой. Runtime-матрица,
установщики и профили живых испытаний имеют отдельные идентичности и свидетельства.

## Goals / Non-Goals

**Goals:** один небольшой модуль описательных идентичностей harness, ограниченный
выбор официальных практик, согласованные подсказки предпочтений и наблюдение
нативных инструкций. Сохранить схемы пресетов/скана/паспорта и совместимость
действующих операционных адаптеров.

**Non-Goals:** общие плагины, удалённое обновление каталога, выбор моделей/провайдеров,
новые пути записи, адаптеры MCP/процесса, цели установщика, живые модельные прогоны
или новые обещания совместимости. Версия пакета остаётся 1.2.0, изменения —
Unreleased; публикация позднее требует отдельного разрешения.

## Decisions

### Статический каталог содержит только описательные факты

Использовать `scripts/agents/profiles.ts`, пригодный для браузера и автономных
скиллов, без зависимостей Node/фреймворка. Экспортировать readonly каталог и поиск
собственной идентичности; хранить ID, название, documented/legacy, checkedAt,
область документации, описательные пути инструкций/скиллов проекта и максимум два
официальных URL практик. Фиксированные сопоставления кандидатов инструкций и
характерных маркеров инфраструктуры остаются внутри модуля. Экспортировать общие
чистые функции для наблюдения; CLI не сериализует объекты сопоставления.

Первые ID: `claude-code`, `codex`, `cursor`, `opencode`, `gemini-cli`,
`copilot-cli`, `aider`, `zcode`, `cline`, `devin-local`, `continue-ide`,
`roo-code`, `windsurf`. Факты/pins прежних трёх сохраняют исходный уровень
свидетельств. OpenCode — именно V2; ZCode — встроенный Agent, не любой ZCode CLI.
Roo — legacy из-за официального сообщения о закрытии. Windsurf — распознавание
прежней настройки; текущий Devin Local имеет отдельную идентичность. Файлы
соглашений Aider требуют явной настройки, без выдуманного автообнаружения.
Скиллы Continue и путь скиллов проекта ZCode неизвестны. Не дублировать большую
булеву матрицу: описательные метаданные не заменяют операционные контракты.

Использовать два приватных исследовательских журнала для краткого парного
руководства. Сохранить точные URL и оговорки; текущая изменяемая страница не
подтверждает загрузку конкретной версией. `harnesses` выводит записи без сети и
записи; необязательный `--agents` выбирает максимум шестнадцать корректных
строчных slug ID, убирает повторы по порядку и возвращает явные неизвестные
записи без подстановки профиля другого инструмента.

### Одна граница выбора и один бюджет чтения практик

Сохранить schema 1 и поля практик. Проверять весь выбор и необязательную карту
версий до чтения. ID: строчные буквенно-цифровые сегменты через дефис, длина
1–64; максимум шестнадцать исходных элементов выбора. Переданные версии выбранных
неизвестных ID допустимы как контекст, но дают только unsupported-agent gap.
Неверные/невыбранные версии отклоняются до сети.

Использовать источники каталога и явно проверенные официальные HTTPS hosts.
Добавить только hosts нужных профилей, без доменов из пользовательского ввода;
сохранить защиту приватной тестовой подстановки источников. Максимум два источника
на ID и шесть HTTP-попыток суммарно, в порядке выбранных ID/источников без
повторов. Неудачная попытка расходует бюджет. Каждый отложенный источник получает
unverified и gap `source-budget-exhausted`. Сохранить ограничения времени/тела/
содержимого, отсутствие редиректов/повторов/учётных данных и маркеры применимости.
Сохранить `OFFICIAL_SOURCES`, если он импортируется, вычисляя из каталога.

### Наблюдение не становится правом записи

Переиспользовать фиксированные сопоставления в скане и диагностике; корневые и
вложенные нативные кандидаты — наблюдения, а не доказательство области действия.
Общие AGENTS.md и .agents/skills не определяют один harness. Характерные конфиги/
rules могут определять ID кандидата, но версия/загрузка/использование неизвестны.
Сохранить прежние наблюдения и ограничения защищённых/секретных путей, ссылок,
числа файлов, глубины и размера.

Диагностика сохраняет проверенные `adapterContracts` из AGENT_MATRIX и может
добавить отдельные описательные профили наблюдаемых ID. Распознавание связи памяти
использует ту же функцию кандидатов, читает только разрешённые наблюдаемые/
ожидаемые файлы и существующие fallbacks и остаётся структурным. `core/paths.ts`,
согласие/хэши/состояние, состав компонентов, алгоритмы MCP/процессов, установщики и
профили eval не меняются. Новые нативные rules можно инвентаризировать, даже когда
автоматическая правка не поддержана; handoff объясняет пробел и сохраняет полезное.

### Подсказки пресета не выбирают установщик

Валидаторы ядра и браузера используют общие ID, сохраняя schema 1 и прежние
варианты. Форма показывает одинаковые названия, явно помечает legacy и объясняет,
что предпочтения не подтверждают установку/загрузку. Неизвестные ID по-прежнему
отклоняются в пресете; изучить их можно через harnesses/practices. Выбор установщика
и команды с полным SHA сохраняются. Сохранить пустой выбор, локализованные ошибки,
доступность клавиатуры/малого экрана и локальные скачивания.

## Risks / Trade-offs

- Документация меняется → сохранять дату, источник и версию/продукт; обновлять
  через ежемесячное ревью, без фоновой мутации.
- Новые названия выглядят обещанием общей поддержки → показывать ограничения в
  CLI, руководстве и форме; разделять адаптеры и установщики.
- Широкий скан влияет на структуру/сохранность → проверить кандидатов, общие
  неоднозначные файлы, исключения, ссылки памяти и отказ нативной записи.
- Общий браузерный модуль увеличивает payload → простые данные/чистые функции
  без Node/зависимостей; проверить production build и целевые браузерные сценарии.
- Меняются ошибки неизвестных выбранных версий и выбора >3 → явные delta
  требования, проверки zero-read/бюджета и прежних трёх ID.

## Migration Plan

Сначала каталог, затем независимые вызывающие модули в параллельных областях.
Интегрировать инструкции/руководства/UI, провести целевые проверки, независимый
Ponytail review, полный offline gate и проверки автономной поставки вне checkout.
Записать фактические результаты и неизвестные нативные свидетельства отдельно.
Откат — удаление новых вызовов/каталога при прежних схемах/правах записи; миграция
проекта или переписывание опубликованных тегов не требуются.

## Integration correction

Первый полный прогон выявил две ошибки: helper стенда требует точную поставку
из 46 файлов на скилл. Новый модуль каталога даёт 47 файлов. Точный офлайн-контроль
состава и его регрессионные проверки обновляются для нового кандидата с сохранением
обычных файлов, пофайловых хэшей, фиксации исходников/runtime и проверки перед
запуском. Native image, модель, авторизация, лимиты сессий, разрешения исполнения и
исторические свидетельства неизменны. Это необходимая интеграция поставки, не
новый native-прогон и не пересмотр старых результатов.
