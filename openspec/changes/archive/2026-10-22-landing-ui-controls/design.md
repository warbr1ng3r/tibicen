# Design

## Context

См. proposal.md. Статический Astro workspace использует локальные адаптации секций AstroWind, TypeScript и Tailwind 4. Пять нативных select обслуживаются FormData и обработчиком команд установки. Отправка формы отключена до установки обработчика локального скачивания.

## Goals / Non-Goals

Общий Select и единое оформление полей без смены структуры страницы. Контракт пресета, фоновый граф, палитра и исходные секции сохраняются. Новые продуктовые функции, React, CMS, глобальная тема Starwind и коммиты не входят в работу.

## Decisions

- AstroWind остаётся исходным кодом адаптированных секций, а не второй установленной UI-библиотекой.
- Локальный UI Select использует `@starwind-ui/astro/select` 1.3.0 и его runtime. Примитив отвечает за клавиатуру, фокус, выбор и размещение, локальный CSS — за вид. Полный styled registry добавил бы ненужные глобальные стили и зависимости.
- Мобильная проба WebKit выявила подавление click из-за отменённого pointerdown в runtime 1.3.0. Версионный pnpm-патч удаляет этот обработчик; штатный click, клавиатура и выбор остаются в runtime. При обновлении патч пересматривается по мобильному регрессионному сценарию.
- Проверка низких окон выявила обрезание сфокусированного пункта в Firefox: патч вызывает scrollIntoView после клавиатурного перехода, а flex-компоновка меню выделяет списку место с учётом рамки и отступов. На очень узких экранах пояснения иллюстрации переносятся под имена файлов через container query.
- Первый экземпляр проверяется в браузере перед заменой всех полей. Значения передаются скрытым полем примитива; установка слушает `starwind:value-change`. Пустые подсказки языка/типа сохраняют прежнюю семантику.
- Общая оболочка Field связывает label, hint и error. Проверка контракта остаётся в buildPreset; типизированная ошибка указывает поле. Кнопка скачивания включается только после установки локального обработчика; до этого form находится в disabled fieldset.
- Текстовый плюс заменяется SVG; нативные details, checkbox и radio сохраняют семантику, получая согласованные размеры.
- Браузерные тесты проверяют реальные меню, FormData, ошибки, сетку и локальное скачивание. Скриншоты фиксируются при уменьшенном движении; реальные Safari/Firefox не объявляются проверенными без прогона.

## Risks / Trade-offs

- Новый runtime → закреплённая версия, один пилотный Select, проверка меню на краях экрана и пустого значения.
- Портал меню отделяет его от формы → явная проверка FormData и локальные классы для оформления портала.
- Инициализация без JavaScript → disabled fieldset и кнопка в исходном HTML, включение только после обработчика; браузерная проверка отсутствия отправки.

## Migration Plan

Добавить примитив и пилот, заменить пять контролов, обновить обработчики и стили, выполнить сценарии и сохранить фактические результаты в change. Откат ограничен landing и новыми проверками, без изменения продуктовых данных.
