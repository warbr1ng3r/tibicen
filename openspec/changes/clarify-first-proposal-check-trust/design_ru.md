# Дизайн

Основная версия — [design.md](design.md).

Существующие гейты исполнения по доверию и готовности сохраняются. Уточняется порядок ввода без ослабления гейтов: показать точный запрашиваемый код/команды, включить предложенную область доверия, выбрать фактический поддерживаемый профиль проверок и задавать готовность только по наблюдавшимся фактам окружения. Затем получить отдельное внешнее согласие на этот неизменённый план.

В общем справочнике предложений сохраняются различия: `trusted: true` — предлагаемая область, `environmentReady: true` — проверенное вызывающей стороной заявление, доступ к инструменту — техническая возможность, а внешнее согласие, связанное с digest, разрешает применение. Ни одно из них не удостоверяет остальные. Собственная анкета или сгенерированный ответ не дают внешнего согласия.

Маршрут агента/хоста по-прежнему может нарушать инструкции. Сохраняются пять возвращённых нарушений согласия, последующие ограниченные функциональные наблюдения и отсутствие экспорта одобрений/запусков. Небольшое уточнение руководства не устанавливает техническое удостоверение человека, всеобщее соблюдение правил моделями или новый результат поведенческой приёмки. Новый сервис согласования или слой учётных данных не вводится.
