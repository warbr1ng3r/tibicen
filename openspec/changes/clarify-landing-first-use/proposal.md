# Proposal

## Why

The landing explains setup ingredients before showing a recognizable user request and result. The [six-site review](../../../docs/research/2026-11-04-landing-review/README.md) found repeated technical copy and an overly tall mobile hero. The owner explicitly requested a landing implementation agent on 4 November 2026.

## What Changes

- Implement the first recommended batch L1–L6: clear two-skill positioning, natural step-by-step init/adopt illustrations, a direct install/start path, concise visible limits with deeper detail, first-session troubleshooting and a shorter mobile hero.
- Retain the existing visual direction, English default/Russian parity, pinned published 1.0 installation, supported selectors, static delivery and accessibility.
- Label examples as illustrations; do not advertise the proposed memory feature, invented observations, extra agents or measured productivity.
- Keep L7–L10, framework changes and publication outside this batch.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `landing-experience`: concrete starting context/dialogue/results, a direct first-use route and accessible mobile presentation without hiding material limits.

## Impact

Landing components/styles and affected site tests only. No runtime, package version, installer pin, preset contract, dependency or published support expansion. Root maintains this separate change and tracker; a fourth implementation subagent starts when a concurrency slot is available. Independent review and browser checks follow. The owner's implementation instruction is recorded in the effort (`../../../.scratch/landing-clarity/map.md`; private development record; excluded from public source); no additional proposal approval is required for the selected first batch. Commit, push and publication are not authorized here.
