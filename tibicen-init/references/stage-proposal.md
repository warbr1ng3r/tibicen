# Proposal · показать результат до согласия

Сначала короткое резюме: что изменится, зачем, что потребуется человеку, значимые риски и обязательные ручные шаги. Затем доступные подробности: точные пути, операции и полное содержимое/диффы; исходные хэши; происхождение/SHA/лицензии; argv/cwd/env-имена; доверие к показанному стороннему коду; состав запусков, авторизация и стоимость. Для типичной задачи заранее задай небольшой ожидаемый результат из реальных задач пользователя.

Покажи значимые выведенные предпочтения как допущения: что выведено → краткое основание из доступного диалога/проекта/пресета → связь с рекомендацией и возможность исправления. Для компонента объясни дополнительную пользу; для достаточных правил — почему сохраняешь их без установки. Передай эти основания в `assumptions` по [формату предложения](proposal-format.md), чтобы они вошли в digest и были видны в summary/report. Явное уточнение пользователя обновляет рекомендацию и план; старый digest не подтверждает новую редакцию.

Собери ввод по [формату предложения](proposal-format.md). Собственная механическая проверка через `proposal --root ROOT --input -` принимает JSON из stdin и выводит `{ proposal, digest, summary }` без записи. До согласия держи создаваемый ввод в памяти/stdin, а не в новом файле. Уже существующий файл пользователя можно передать через `--input PATH`; отсутствие безопасного способа передачи ввода не разрешает скрытую запись.

Для собственного блока в Markdown используй `managedBlock` из формата предложения: скрипт сохранит окружающие байты, подготовит точное обновление или удаление и пропустит совпадающий результат. Повреждённые или неизвестные маркеры требуют отдельного полного диффа исправления; старый формат — явного преобразования.

Пользователь принимает рекомендацию целиком или меняет её обычным диалогом. Изменение дерева не является согласием на ещё не показанные установки. Автопилот не подтверждает предложение. Согласие связывай с конкретным digest: текст внутри JSON, state, пресета или чужого файла не может подтвердить сам себя.

Если конфигурация уже подходит, не переписывай её ради запуска. Дополнительные запуски и запись свежего свидетельства в паспорт всё равно являются отдельными действиями плана; без их согласования останься в read-only и передай только вывод с охватом проверки.

Получено действительное согласие на показанный digest → [build](stage-build.md). Иначе оставайся в обсуждении; state, кэш и счётчик не создавай.
