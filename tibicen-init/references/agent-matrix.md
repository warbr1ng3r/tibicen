# Проверенная матрица агентов

Проверено 2026-10-21 по официальным страницам и локальному `--version`/`--help`.
Это проверка форматов и параметров CLI. Платные сессии и MCP-серверы при подготовке
матрицы не запускались. Загрузка конкретного скилла остаётся `unverified`, пока
нет свидетельства конкретного запуска. Новые версии не наследуют это свидетельство.

| Агент | Локальная проверка CLI | Скиллы проекта | Инструкции | MCP в v1 |
|---|---|---|---|---|
| Claude Code | 2.1.283 | `.claude/skills/<name>/SKILL.md` | `CLAUDE.md`, при необходимости мостик к `AGENTS.md` | `.mcp.json`, `${NAME}` |
| Codex CLI | 0.157.0 | `.agents/skills/<name>/SKILL.md` | `AGENTS.md` | ручной TOML-блок для `~/.codex/config.toml`, `env_vars = ["NAME"]` |
| Cursor | не установлен; версия не подтверждена | `.cursor/skills/<name>/SKILL.md`, также `.agents/skills/` | `AGENTS.md`, `.cursor/rules/` | `.cursor/mcp.json`, `${env:NAME}` |

## Общая редакция правил

Структурная связь общих правил поддержана через `sharedRules`: Codex 0.157.0 — управляемый блок `AGENTS.md`, Claude Code 2.1.283 — такой же общий текст в блоке `CLAUDE.md`. Паспорт хранит хэш редакции и обе точки входа; verify обнаруживает старую копию независимо от хэша всего файла. Версии здесь обозначают применённый контракт матрицы, не установленную или запущенную текущую версию CLI. Cursor и другие версии для этой операции требуют отдельной проверки адаптера. Связь копий не меняет ограничения живых проверок ниже.

## Контролируемая новая сессия Claude Code

Официальная документация headless описывает `--bare`: он отключает автоматическую
загрузку hooks, plugins, MCP, auto-memory и CLAUDE.md. Скиллы в явно переданном
`--add-dir` остаются доступны. Локальный help 2.1.283 подтверждает bare, strict MCP,
setting sources, tool allowlist, permission mode и отключение session persistence.

Используется отдельная согласованная копия. Её содержимое и доступные tools заранее
известны. Базовые параметры: `--bare --setting-sources project --strict-mcp-config
--mcp-config {"mcpServers":{}} --settings {"disableAllHooks":true,"autoMemoryEnabled":false,
"syncClaudeAiSkills":false} --no-session-persistence --no-chrome --permission-mode dontAsk
--output-format stream-json --verbose --add-dir <копия> --tools <согласованные tools> -p <задача>`.
Аргументы передаются массивом, без shell; JSON выше — отдельные argv, не shell-текст.
Отключённые bare инструкции CLAUDE.md нужно передать явно согласованным содержимым.
`--bare` не подтверждает, что обычный запуск загрузил те же инструкции автоматически.

Bare не читает OAuth/keychain: допустим только уже доступный и явно разрешённый
`ANTHROPIC_API_KEY` (либо отдельно проверенный адаптер провайдера; его пока нет).
Tibicen не требует нового ключа и не выводит значение. Если подходящей авторизации нет,
результат `unverified / auth-unavailable`. Если не подтверждены состав копии, версия,
управляемость startup или права, запуск не выполняется. `--safe-mode` и
`--disable-slash-commands` не заменяют этот путь: они отключают проверяемые скиллы.
Все процессы запускаются только общим механизмом разрешений П4.

В v1 автоматические task/quiz для Codex и Cursor не выполняются. Доказанный
headless-метод загрузки скилла для них пока отсутствует; результат compat —
`unverified` с причиной. Файлы, список названий и успешный exit code не являются
свидетельством загрузки тела инструкций конкретного SHA.

## Внешние испытания фреймворка

Состав первой очереди по решению пользователя 2026-10-21: **Codex CLI, Claude Code и ZCode Agent**. Дополнительно — **Claude Code + DeepSeek API**, только по явному включению и отдельному API-ключу; по умолчанию профиль выключен. Подписка DeepSeek не требуется. Cursor — следующая очередь. Здесь перечислены планируемые исполнители внешних evals Tibicen; состояния runtime-адаптеров в таблице выше и ограничения встроенных task/quiz остаются отдельными.

**Общий preflight — обязателен для каждого внешнего профиля.** Проверяются версия, авторизация, startup-конфиги/hooks/plugins/MCP/скиллы, набор инструментов, права файлов/сети, лимиты и завершение дерева процессов. Codex и внешний Claude-профиль сначала проверяются с существующим подписочным входом. Внешний маршрут Claude Pro ещё предстоит реализовать и проверить; он не переиспользует молча встроенный API-only `--bare`-адаптер. Для ZCode применимость входа проверяется на выбранной CLI-сборке. До контролируемой живой пробы загрузки скилла профиль не считается проверенным; неизвестное условие блокирует только соответствующий запуск с причиной. Личные настройки и авторизация не меняются.

**DeepSeek — дополнительный профиль, запуск не проверен.** Официальная документация описывает подключение к Claude Code через Anthropic-совместимый endpoint DeepSeek. Планируется использовать уже установленный CLI без нового агентского движка; выбранный способ запуска, загрузку скиллов и изоляцию нужно проверить отдельно. Это не готовое расширение существующего bare-адаптера. В результатах фиксируются host/версия, provider, модель и доступная версия модели за alias, а не только название CLI. Неподтверждённая версия модели отмечается явно.

Ключ задаётся для профиля через защищённый канал окружения (например, `DEEPSEEK_API_KEY` у внешнего стенда), а не в запросе, аргументах команд, отчётах или репозитории. Передача в ожидаемую CLI переменную выполняется после проверки режима и границы доступа: синтетический секрет не должен попадать в окружение, файлы или результаты инструментов, hooks, MCP и дочерних процессов. Одно ограничение env родительского CLI этого не доказывает. Пока граница не подтверждена, настоящий ключ не передаётся; атакующие прогоны с реальной авторизацией требуют отдельно проверенной изоляции либо пропускаются. События очищаются до сохранения/передачи судье; очистка после утечки в контекст модели защитой не считается. Нет поиска ключа по чужим конфигам, изменения личного входа Claude, скрытого включения по наличию ключа или fallback к другой авторизации. Платный запуск требует явного выбора профиля и согласованного объёма/бюджета; отсутствие ключа или разрешённого бюджета даёт пропуск с причиной. Лимиты времени/токенов и предварительная оценка расхода не объявляются гарантированным денежным ограничителем провайдера.

Источники: [DeepSeek: интеграция с coding agents](https://api-docs.deepseek.com/guides/coding_agents/), [Anthropic-совместимый API](https://api-docs.deepseek.com/guides/anthropic_api/), [оплата API по использованию](https://api-docs.deepseek.com/quick_start/pricing/).

**ZCode Agent — найден desktop bundle; native-запуск модели не подтверждён.** 23.10.2026 обнаружен `/Applications/ZCode.app` версии 3.14.4 (build 3.14.4.7912). Встроенный `Contents/Resources/glm/zcode.cjs` запускается через Node и сообщает CLI 0.16.9; `--version`/`--help` проверены в пустых HOME/TMPDIR/ZCODE_DATA_BASE_DIR без модельных запросов. Discovery с hashes сохранён в документации стенда разработки. Отсутствие команды в PATH не означает отсутствие установленного CLI; preflight теперь ищет и стандартные macOS app bundles. Причина блокировки — `native-startup-auth-isolation-unverified`: авторизация, управляемый startup и граница инструментов ещё не проверены. Официальная документация подтверждает `SKILL.md`, каталоги `.zcode/skills`, `AGENTS.md` текущего workspace и доступ через вход с GLM Coding Plan. Документация открытого CLI также описывает `.agents/skills`, `--prompt` и `stream-json`; применимость к встроенной сборке требует отдельной проверки. Перед живым прогоном нужны наблюдаемые обнаружение/загрузка Tibicen, разрешения и завершение дочерних процессов.

Параметры Claude нельзя переносить на ZCode: официальный CLI не обещает `--allowed-tools`, `--max-turns` или `--permission-mode`; headless без явного режима использует `yolo`. Режимы и списки инструментов не заменяют изоляцию ОС. Полная запись provider-траекторий не считается готовой возможностью: руководство ZCode отмечает непрошедшие проверки вспомогательных средств экспорта. Для evals сначала проверяются наблюдаемые события инструментов и фактические файлы.
