# Verify · честные независимые результаты

При зарегистрированном [процессе OpenSpec](process-openspec.md) структурная проверка отдельно сверяет точные файлы и выбранные ресурсы внешнего CLI. Отсутствие/изменение обнаруживается независимо от текущего диффа. Loading, task и CLI execution остаются unverified до собственных наблюдаемых проверок; native CLI smoke-test не является живой агентской приёмкой.

`node SKILL_DIR/scripts/tibicen.ts verify --root ROOT` — структурная проверка по умолчанию. Исполнение проекта, новой сессии агента или MCP требует точного согласованного запуска и явного доверия. Проверяй возможности установленного скрипта и матрицы; наличие команды не означает, что она уже реализует любой профиль. Отсутствующий метод даёт `unverified` с причиной, а не самодельный небезопасный запуск.

Состав проверки объединяет паспорт, историю применённых операций и текущие согласованные результаты. Исчезнувший зарегистрированный файл даёт `missing-file`, локальное расхождение — `content-mismatch` или `permission-mismatch`; пустой improve не скрывает их и остаётся `incomplete`. Согласованное удаление проверяется как отсутствие. Проверка ничего не восстанавливает. Общие блоки и процессные ресурсы сверяются по своим редакциям/контрактам, сохраняя допустимые правки владельца. Без паспорта проверяются наблюдаемые файлы; у schema 1 неизвестный installed hash не подменяется upstream-хэшем, а новый baseline появляется только через согласованную миграцию.

- **Инфраструктура:** пути и точки входа, нужные инструкции/скиллы, согласованность, сохранность пользовательских решений и соответствие плану. Проверяется для любого языка проекта. Корректность управляемых Markdown-блоков проверяется независимо от хэша: повреждённая пара или неизвестная версия дают дефект с номером строки. Для зарегистрированных `sharedRules` проверяются все связанные копии по общей редакции: старая/отсутствующая копия — обязательный дефект даже вне текущего файлового диффа. Это не свидетельство загрузки инструкций в новой сессии.
- **Приложение:** в v1 только web-профиль; итоговый прогон — исходный снимок плюс все изменения. Для прочих стеков `unverified / unsupported-profile`. `pre-existing-red` допустим только при состоявшемся сопоставимом сравнении без новых ошибок. Известная регрессия сохраняется в истории; повтор не делает её старой. Коммиты не создаются.
- **Типичная задача:** отдельная контролируемая копия и новая сессия Claude Code с заранее согласованным результатом. Изменения этой задачи не переносятся в проект или снимок интеграции. Другие агенты — `unverified` с причиной в v1.
- **Квиз:** отдельные пять вопросов из паспорта и решений, порог ≥4/5. Не заменяет типичную задачу, загрузку каждого скилла или проектный прогон.
- **Compat:** каждая выбранная пара после установки/замены. Список метаданных даёт только `discovered-only`; `loading: verified` требует наблюдаемого свидетельства загрузки инструкций выбранного SHA. Прежнее свидетельство применимо только к тому же SHA, версии агента и существенному составу запуска.

Сравнение приложения требует полного согласованного набора команд с совпадающими id/digest в обоих прогонах; новый проект требует полного итогового набора. Совпадающий успешный префикс не подтверждает остальные команды. Отказ доверия, изменение источника команды, неизвестный исход или иной неполный прогон сохраняет `unverified` с причиной и известными регрессиями независимо от статуса передачи.

Для проверок с локальными Node-зависимостями до согласия выбери `checks.environment` по [формату предложения](proposal-format.md#исполняемые-проверки). Только согласованные байты попадают в независимые исполнения; неразрешимые ссылки, изменившиеся зависимости или runtime сохраняют `unverified` с причиной. После согласия окружение и команды не подменяются.
- **MCP:** проверка формата и env целевого контекста без значений и пробного запуска сервера. Возможны `configured-unverified`, `no-key`, `env-context-unverified`, `manual-action-required`, `disabled-by-user`; это не health-check.

Новая сессия не должна подхватывать hooks, plugins, MCP, settings или auto-memory сверх плана. Неконтролируемый startup — пропуск с `startup-uncontrolled`. Сам по себе `claude -p` или `--bare` не является доказательством контроля. Не добавляй обязательную авторизацию, не ослабляй права и не называй temp/worktree sandbox.

После ручной интеграции или прерывания нельзя подменять исходный baseline снимком изменённого проекта. При утрате сопоставимого сравнения — `baseline-unavailable`; успешность с первой попытки не заявляется. Неизвестный исход проверки после обрыва — `unverified / command-outcome-unknown`, а не успех по наличию ожидаемого файла. Повтор запуска требует отдельного обоснования в новом плане и согласия на его digest. Далее — [handoff](stage-handoff.md).
