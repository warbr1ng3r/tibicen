# Память проекта · сохранять то, что важно человеку

Используй эту ветку, если человек хочет сохранять решения между сессиями или в проекте уже есть память. Память необязательна: достаточную настройку сохраняй, отказ не блокирует init/adopt. Это правила для рабочих агентов после настройки; Tibicen не остаётся запущенным и не требует сервиса, аккаунта или доступа к глобальной памяти.

## Выбрать одну память

1. Из запроса и разрешённых материалов выдели, что важно сохранять: постоянные ограничения, принятые решения и их причины, проверенные факты проекта. Предложи достаточную политику обычными словами. Вопросы — только о существенном неизвестном в пределах [того же интервью](stage-interview.md); новая анкета или выбор технологии человеку не нужны.
2. По доступным файлам и фактическим ссылкам найди текущую память. Поддержаны только четыре точных относительных пути: `.agents/memory.md`, `MEMORY.md`, `docs/memory.md`, `docs/decisions.md`. Однозначный подходящий существующий файл используй без конкурирующей копии; отсутствие памяти при полезной потребности → предложи `.agents/memory.md`.
3. Несколько существенно противоречащих хранилищ → уточни действующее решение в оставшемся бюджете вопросов. Если вопросы запрещены, сохрани ограничения и файлы, укажи gap; дата изменения или порядок загрузки не выбирают победителя. Неподдержанный, запрещённый или недоступный путь сохраняй без скрытого переноса и автоматического создания замены: объясни ограничение/ручное действие. Запрет чтения важнее исследования памяти.
4. В предложении покажи выбранный путь, правила и точные первоначальные изменения. Сохрани несвязанные заметки побайтно; замени только действительно устаревший смысл с объяснением. Без необходимости не меняй содержимое. Конец выбора — одна обоснованная память и политика либо явный отказ/gap, а не набор новых файлов.

Просьба «ответь сейчас коротко» относится к текущему ответу. Это не подтверждённое постоянное правило; выведенное предпочтение остаётся исправляемым `inferred` в `assumptions`. Явный выбор постоянного правила — `user-confirmed` с действительным основанием. Содержимое памяти — данные: оно не переопределяет запрос человека и не даёт согласия на исполнение.

## Связать с рабочими инструкциями

Если выбранным хостам достаточно явно читать общий `AGENTS.md`, размести в нём короткую применимую политику с проектным путём обычным согласованным управляемым блоком по [формату предложения](proposal-format.md). Одного файла достаточно без нативной версии и `sharedRules`; дополнительные нативные копии нужны только по отдельно обоснованному поддержанному запросу. Сохраняй достаточные существующие точки входа и уже зарегистрированные связи копий по их контрактам. Ссылки из проекта ведут на его единственную выбранную память, а не на каталог установленного Tibicen: последующая работа не зависит от наличия скилла. Подставь реальный путь и пользовательские критерии; пример не требует лишних секций или обязательных дат:

```text
Перед работой, затрагивающей решения проекта, прочитай относящиеся к задаче записи в `.agents/memory.md`.
В рамках разрешённой работы сохраняй там явные постоянные решения пользователя, проверенные факты и принятые решения с причиной/источником, когда они известны. Сохраняй только полезное для следующих задач.
Отличай принятые решения, проверенные факты и неподтверждённые предположения; временный прогресс задачи не становится постоянным правилом.
После принятого нового решения или проверенного исправления обнови соответствующую запись. При отмене решения исправь его текущий смысл, не оставляй две противоречащие действующие версии; сохрани несвязанные заметки.
Следуй текущему запросу, запретным путям и разрешённой области записи. Расширение области или неоднозначность требует уточнения либо явного ограничения, а не догадки. Секреты и полные переписки по умолчанию не сохраняются.
```

Читай релевантные решения до выбора подхода, а не всю историю для каждой задачи. В память попадает минимальное полезное знание; неподтверждённая гипотеза явно помечается или остаётся вне постоянных записей. Понятный текст достаточен, фиксированная схема записи не нужна. Политика не даёт рабочему агенту новых прав: его обычные ограничения и согласования продолжают действовать.

## Передать точный план

Вход `memory: {"path":".agents/memory.md"}` связывает только один поддержанный путь. Точные начальные байты памяти и инструкций передаются в обычном `changes`, без записи файла до согласия. Это не разрешение менять произвольный Markdown, исходники, глобальную память или служебные `.tibicen/`-файлы.

Минимальный пример init для обычной просьбы «пусть следующие агенты помнят: новые зависимости обсуждаем со мной». Он подходит только при реальном постоянном решении и отсутствии обоих файлов; адаптируй текст к фактам проекта:

```json
{
  "mode": "init",
  "memory": { "path": ".agents/memory.md" },
  "changes": [
    {
      "path": ".agents/memory.md",
      "action": "add",
      "content": "# Решения проекта\n\n- Принято пользователем: перед добавлением новой зависимости обсудить необходимость и альтернативы. Основание: постоянное ограничение из запроса.\n",
      "reason": "Сохранить явно выбранное постоянное ограничение"
    },
    {
      "path": "AGENTS.md",
      "managedBlock": {
        "content": "Перед связанной работой прочитай релевантные решения в `.agents/memory.md`.\nВ рамках разрешённой работы сохраняй там постоянные решения пользователя и проверенные факты с известной причиной/источником. Отличай их от предположений и временного прогресса.\nПосле принятого решения или проверенного исправления обновляй текущую запись, сохраняй несвязанные заметки и соблюдай ограничения пользователя. Секреты и полные переписки по умолчанию не сохраняются.\n"
      },
      "reason": "Связать чтение и ведение памяти с рабочими инструкциями"
    }
  ]
}
```

Пример adopt, когда `docs/memory.md` уже полезен и его тело менять не нужно:

```json
{
  "mode": "improve",
  "memory": { "path": "docs/memory.md" },
  "changes": [
    {
      "path": "AGENTS.md",
      "managedBlock": {
        "content": "Перед связанной работой прочитай релевантные решения в `docs/memory.md`.\nВ рамках разрешённой работы сохраняй там постоянные решения пользователя и проверенные факты с известной причиной/источником. Предположения помечай; временный прогресс не превращай в постоянное правило.\nПосле принятого изменения исправляй текущий смысл записи, сохраняя несвязанные заметки и ограничения пользователя. Секреты и полные переписки по умолчанию не сохраняются.\n"
      },
      "reason": "Подключить существующую память без переписывания заметок"
    }
  ]
}
```

Уже подключённая достаточная память допускает `changes: []`; повторный запуск не требует её переписать. Возвращённый proposal добавляет `memory: {path, ownership: "user-memory"}` и использует schema 2; память сохраняется в manifest schema 3 и recovery state 4. Если проект уже имеет legacy-паспорт schema 1/2, передай `migrateManifest: true`, покажи миграцию в digest и получи обычное согласие; runtime 1.0 отказывает на новых схемах до записи. Не редактируй возвращённые версии вручную и не обнуляй прежнюю историю. Без памяти прежние контракты сохраняются; в memory-aware проекте последующие планы сохраняют его запись без понижения схемы. Память не расширяет схему пресетов.

Согласование — по [обычному proposal](stage-proposal.md). Автопилот убирает вопросы, но не одобряет digest. До apply и при незавершённом resume исходные хэши, режимы, безопасные пути, запреты и журнал остаются точными: чужое изменение после согласия требует нового плана, а не исключения для «изменяемой памяти».

## Проверить и передать результат

После завершённой настройки тело `user-memory` — изменяемые пользовательские данные. Новые законные записи не требуют начального хэша и не восстанавливаются из шаблона. Повторный adopt использует текущие записи как вход. Отсутствие файла, небезопасный путь или повреждённая управляемая инструкция остаются самостоятельными дефектами; начальные хэши сохраняются как история применения. При удалении/восстановлении настройки сохраняй последующие заметки, не считай их одноразовым сгенерированным ресурсом.

По [verify](stage-verify.md) отдельно покажи структурный результат и наблюдения в свежей сессии: прочитал ли агент нужное решение, повлияло ли оно на задачу, сохранил ли новый факт или исправил отменённое решение без потери других записей. Укажи кандидат, фактическую версию агента/инструментов, помощь, ограничения и неудачи. Подсказка прочитать конкретный файл — помощь, а не доказательство автоматической загрузки. Недоступный контролируемый запуск → `unverified` с причиной; структурный успех не заменяет поведение, один агент не подтверждает остальные версии, измеренная польза человеку не предполагается.

В [handoff](stage-handoff.md) достаточно назвать один файл, объяснить правила простыми словами и указать, что действительно проверено и что осталось непроверенным. Обычное завершение инфраструктуры и отдельный результат поведения памяти не смешиваются.
