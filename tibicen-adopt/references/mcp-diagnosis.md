# MCP · от запроса к точному действию

Используй этот маршрут в init при полезной задаче для MCP и в adopt при жалобе вроде «инструменты не появились» или «после перезапуска не видит ключ». Из запроса и [контекста задачи](stage-scan.md#контекст-задачи) возьми фактический harness, известную версию и имя сервера. Любой допустимый ID может выбрать известный формат или общий маршрут наблюдений; профиль каталога и смена модели/провайдера не нужны. Неизвестное оставь ограничением; отдельная анкета не нужна.

## Исследовать без запуска

Сначала используй доступные сведения выбранного хоста о конфигурации и состоянии. Учитывай только фактически наблюдавшийся источник; порядок файлов и единственный найденный конфиг не устанавливают нативный приоритет. Глобальные, управляемые и сессионные источники могут оставаться за пределами проверки. Нативные `gemini mcp list`, `opencode mcp list` и похожие команды могут подключать или запускать серверы: диагностическое название не делает их разрешённым чтением. Новый запуск требует точной команды, явного доверия и согласия по обычным правилам проверки.

Для разрешённых проектных файлов используй собственную read-only границу вместо вывода конфигов в контекст агента. При известных запретах добавляй `--forbidden-paths` по [общей области чтения](proposal-format.md#область-чтения-проекта), сохраняя список и для повторной диагностики/проектного `mcp-verify`:

```text
node SKILL_DIR/scripts/tibicen.ts mcp-diagnose --root ROOT --input -
```

Через stdin передай метаданные с фактическими значениями, например:

```json
{
  "agent": "cursor",
  "server": "docs",
  "sources": [{ "path": ".cursor/mcp.json" }]
}
```

`sources` содержит до четырёх уникальных путей обычных файлов внутри `ROOT`, с `/`, без абсолютных путей, `..` и symlink. Скрипт читает до 1 MiB на файл, сохраняет запретные области и возвращает статусы без сырого конфига, команд, аргументов и значений env. Передавай пути, а не текст настроек; недоступный файл не означает отсутствие сервера. Секреты и файлы их подстановки не читай и не выводи.

При наличии добавь `agentVersion`; переданная версия остаётся контекстом, а не проверкой установленной сборки. Явный `format` не зависит от `agent`: он выбирает только контракт чтения, не переименовывает среду и не доказывает нативную совместимость. Без формата сохраняются прежние значения по умолчанию только для Claude Code, Cursor и Gemini CLI.

### Выбрать формат или передать наблюдение

Для другого языка, собственного экспорта или неизвестного диалекта выбери `format: "stdio-observation"`. Каждый источник содержит `observation: {sourceHash, state, envNames}`: все поля обязательны; `sourceHash` — 64 строчных hex-символа SHA-256 исследованного текста UTF-8; `state` — `stdio`, `disabled` или `unknown`; `envNames` — до 256 допустимых имён необходимых переменных, пустой массив для состояний, отличных от stdio. Получай факты разрешённым исследованием, без выполнения кода. Во вводе только состояния, хэши и имена: команды, аргументы, значения и сырой конфиг не передавай.

Совпавший хэш связывает переданные сведения с текстом источника, а не доказывает их правильность или безопасность файла. Источник stdio получает `reported-stdio`, не `valid-stdio`; его явный выбор как `effectiveSource` даёт `configuration.basis: "caller-observation"`. Недоступный или изменившийся источник оставляет наблюдение непроверенным. Явные факты целевого запуска помогают выявить недостающую предпосылку; исправление остаётся ручным/нативным. Без более конкретной проблемы запуска причина — `observed-configuration-not-parsed`; механизм записи не добавляется. Состояние отключения из наблюдения сохраняй с его основанием.

Если фактический источник соответствует известному контракту, выбери один из readers:

| `format` | Область чтения |
| --- | --- |
| `claude-code-json` | `mcpServers`, ссылки env Claude |
| `cursor-json` | `mcpServers`, ссылки `${env:NAME}` Cursor |
| `gemini-cli-json` | `mcpServers`; URL имеет приоритет над командой |
| `opencode-v2` | `mcp.servers`, массив команды, `environment`, `{env:NAME}`, `disabled` |
| `zcode-native-json` | `mcp.servers`, `enable: false` |
| `zcode-shared-json` | `mcpServers`, `enable: false` |
| `kimi-code-json` | Текущий `.kimi-code/mcp.json`, `mcpServers`, `enabled: false`, локальный stdio |
| `mistral-vibe-toml` | Подмножество TOML `[[mcp_servers]]`, stdio, `disabled: true` |

Новым readers нужен явный формат. ZCode/Kimi/Vibe не заимствуют подстановку env другой среды: непустое буквальное env остаётся ручным ограничением. Нелокальный `environment_id` Kimi не получает сведения о локальном запуске. Vibe принимает однострочные строки, булевы значения, ограниченные числа, массивы, inline tables и обычные/array tables; повторы, quoted headers, dotted assignments, многострочные строки и иной неподдержанный синтаксис оставляют источник ручным шагом. Shell-команда не разбирается. `disabled` Vibe скрывает инструменты и не доказывает отсутствия нативного запуска.

Контракты проверены по официальным источникам 6 ноября 2026 года, не по живым установленным версиям. [ZCode](https://zcode.z.ai/en/docs/mcp-services): нативная непустая карта подавляет весь `.agents/mcp.json` той же области, личные одноимённые настройки приоритетнее проектных. [Kimi Code](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/mcp): текущая `.kimi-code`, проект перекрывает личный источник, требуется доверие проекту. [Vibe](https://docs.mistral.ai/vibe/code/cli/configuration): доверие папке и более приоритетные слои остаются вне локального файла. Reader не вычисляет эти нативные слои. DeepSeek Harness с Cordis YAML и приложение GigaChat с Python остаются на поддержанных фактах/наблюдениях: код, YAML-теги `!!js` и фрагменты оболочки не исполняются.

`formatEvidence` отделяет `caller-supplied`, `harness-default` и `unverified`; успешно разобранный источник имеет основание `parsed-format`. `nativeActivation` всегда остаётся `unverified`. Формат, источник, состояние записи и действующая нативная настройка — разные свидетельства.

`effectiveSource` — один из переданных путей, явно выбранный вызывающим для этого сервера по доступным сведениям. Это переданное основание, не независимое доказательство нативного выбора. Сохраняй статусы всех источников; при неизвестном выборе не объединяй одноимённые записи и не назначай приоритет по порядку.

`launch` необязателен: `{targetContextKnown, availableEnvNames, executableAvailable, cwdAvailable}`. Передавай имена доступных env и булевы результаты только из сведений о целевом запуске. Неизвестные поля пропускай; без `targetContextKnown: true` они не устанавливают доступность. Окружение/PATH процесса Tibicen и успешная команда в другом терминале не подтверждают окружение GUI или другого процесса. Даже подтверждённые имя переменной, executable и cwd не доказывают подключение и использование инструментов.

## Одна рекомендация и повторная проверка

Объясни простыми словами: какой сервер и источник рассмотрены, какое препятствие установлено, что осталось неизвестным и какое одно действие нужно дальше.

- Для доказанного дефекта в подтверждённом поддержанном проектном источнике предложи точечный `mcp` upsert/remove по [формату предложения](proposal-format.md#mcp). Автоматическая запись остаётся только при совпавших хосте, формате и точном пути Claude `.mcp.json` или Cursor `.cursor/mcp.json`; выбор их reader другой средой не даёт механизм записи. Сохрани чужие записи, настройки и решения. Добавление или изменение сервера требует явного доверия показанному коду, включая возможный автозапуск хостом, и согласия на точный план.
- Codex получает согласуемый ручной TOML-блок по прежнему контракту. Gemini, OpenCode и другие форматы не получают новых прав записи от наличия reader. При неизвестном эффективном источнике, целевом окружении или неподдержанном формате назови конкретный нативный следующий шаг и его оставшуюся границу. Сохрани выбор отключения, доверие папке и фильтрацию секретов; ключ человек задаёт вне репозитория и чата.
- Если необходимая правка не установлена, сохрани настройку с перечисленными пределами проверки. Не создавай компонент, сессию или запись только ради отчёта.

После одобренного ремонта повтори тот же `mcp-diagnose` с теми же сервером и областью; изменение источников или контекста назови явно. Старый `mcp-verify` остаётся отдельной структурной проверкой и сам не устанавливает целевое окружение. Разделяй выбор источника, конфигурацию, доступность целевого запуска и подключение/использование: последние остаются `unverified`, пока нет собственной разрешённой наблюдаемой проверки. Передай результат и одно оставшееся действие через [handoff](stage-handoff.md).
