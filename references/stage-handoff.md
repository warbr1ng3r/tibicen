# Handoff · понятный следующий шаг

Начни с результата простым языком: что готово и что ещё нужно человеку. Для улучшения укажи добавлено/изменено/удалено и обязательные ручные шаги с понятными действиями. Дай первый полезный запрос агенту. Таблицы технических свидетельств не должны быть обязательными для понимания результата.

Передача — `complete`, только если инфраструктура подключена, обязательные ручные действия выполнены и нет известных обязательных дефектов подключения. Только внешние шаги человека → `manual-action-required`. Внутренний сбой или неисправленный обязательный дефект → `incomplete`, причина, фактически применённое и способ продолжить. Непроверенное приложение или поведение само по себе не определяет передачу.

Отдельно покажи инфраструктуру, проектный прогон, типичную задачу, квиз, MCP и compat с причинами пропусков. Не выдавай файлы на диске за загрузку инструкций, зелёный квиз за реальную пользу или прочитанный старый источник за свежую проверку. Если изменений не нужно, сообщи охват исследования.

До удаления state скрипт атомарно сохраняет краткую историю исходной сессии, попытки, известные регрессии и обязательные ручные действия. Обрыв/`incomplete` сохраняет state. Resume не является новым использованием или вторым успехом.

Пресет предложи сохранить, но записывай только по явному запросу: `preset-save --input INPUT --requested`. Сохраняются типизированные предпочтения без секретов и произвольных инструкций; установки и прежнее согласие не переносятся. Файл отчёта тоже создаётся только по явному запросу. После работы в проекте остаются инфраструктура и паспорт; постоянного процесса нет.
