# Current tools and a restrained technology-refresh mechanism

Labels: wayfinder:map
Status: resolved
Assignee: none

## Destination

Research public user complaints and primary tool contracts to decide what Tibicen
still needs after its diagnosis work. The owner named SDD, mem0, Ponytail and an
uncertain Netflix-related “head…” tool, and asked whether proposing current
technologies through a self-update mechanism is a good idea. Deliver a critical
EN/RU study, not an implementation, installation, product promise or release.

## Decisions so far

- Research only. Use firsthand issues/discussions and official docs/source;
  distinguish reported experience, vendor claims and independent evidence.
- Three background agents own separate lanes; root owns synthesis, existing-code
  comparison, refresh-policy design, tracker and final validation.
- Unknown tool identity stays uncertain until sourced. Do not turn trendiness,
  release recency, popularity or an ex-employer into a recommendation criterion.
- Keep program updates, evidence refresh, recommendation-policy changes and
  target-project edits separate. No native/model evaluations, paid API,
  installations, commits, auth changes or publication are included.

- [Synthesis](issues/00-synthesis.md): evidence freshness/version binding is a
  smaller next opportunity than a trend catalog; implementation remains unselected.
- [SDD/skills](issues/01-sdd-skills.md): retain useful existing process, scale
  ceremony, distinguish plain instructions from full plugins.
- [Memory](issues/02-memory.md): project decisions do not require a new service;
  application memory needs separate data/correction/erasure checks.
- [Context](issues/03-context.md): likely Headroom, not a Netflix product;
  correctness/cache/cost/recovery must justify compression. Independent review
  corrected the expiry interpretation; no tool efficacy inferred.
