# Broader harness coverage

Labels: wayfinder:map
Status: resolved
Assignee: none

## Destination

The owner asked why Tibicen concentrates on Codex, Claude Code and Cursor despite
many other agents and harnesses. Support should follow observed capabilities and
project needs. Keep installation, instruction loading, memory, MCP and task
execution evidence separate; a model/provider is not a harness.

The owner authorized autonomous continuation after the completed 1.2 release.
Implementation, integration and independent reviews are complete locally. No adapter, network permission,
write target or support claim is expanded by this map alone.
Substantial implementation requires a coherent OpenSpec proposal before code.

- Specifications were synced and the completed [change](../../openspec/changes/archive/2026-11-05-catalog-harness-capabilities/proposal.md) archived on 5 November 2026 after all eight tasks and independent reviews passed. Release actions remain separate.

The package is local Unreleased; no native compatibility or public release is inferred.

- [Catalog/discovery complete](issues/02-catalog-and-discovery.md):13 descriptive profiles, read-only CLI and bounded six-attempt practices pass focused checks.
- [Rules/docs/UI complete](issues/04-rules-docs-ui.md):shared hints, paired guide and translations; 18 preset, 43 site and 9 browser checks passed.

- [Observation complete](issues/03-observation.md): native candidates and structural memory pointers pass focused checks; checked adapters, native evidence and automatic write authority remain unchanged.

- [Design complete](issues/01-design.md): static descriptive catalog, explicit unknown/legacy results, six-request global practice budget and unchanged write/adapter/installer/eval authorities. Three implementation lanes used disjoint source contracts.

- Inspection confirmed product hardcoding, including practices, presets/UI,
  scanner and adapter data; the limitation is not only the test sample.
- Prepare a small static profile catalog and an explicit unknown-capability
  outcome. Preserve the existing network budget and approved-path policy.
- Observed paths, authorized writable paths, installer choices and native test
  profiles are different responsibilities. Adding a name grants none of them.
- Research and validate further profiles against primary sources when selected;
  do not imply universal AGENTS.md discovery or a new model/API provider.
